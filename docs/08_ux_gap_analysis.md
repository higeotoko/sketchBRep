## 4. 重点 3 テーマの技術的課題と方針

### 4.1 線・円弧からの自動面生成（F-01〜F-10）

**現在の構造**
- 一筆で閉じた線 → `PolygonProfile`（従来）
- 別々の線・開いた円弧・曲線が端点でつながって閉じる → `LoopProfile{各曲線のレシピのスナップショット}`。円弧は正確な円弧のまま（F-02 ✓）、膨らみも `in<i>.bulge` で再編集可能（F-10 ✓）
- 接続許容差は **1e-3 mm**（幾何許容差。画面の吸着しきい値とは別）。超える隙間は閉じない（F-03 ✓）
- 閉路検出は**同じ親（グループ）の中だけ**（F-09 ✓）
- 非平面の閉路は `BRepBuilderAPI_MakeFace(onlyPlane)` で失敗 → 面を作らない（F-06 ✓）

**ギャップと方針**
1. **F-08（最優先）**: 線を確定するコマンドと面化のコマンドが別の Undo になっている。→ ツール側で `beginGroup("線")` で 1 つにまとめる。Undo 1 回で「線を引く前」に戻る
2. **F-04/F-06 の理由表示**: 閉路は見つかったのに面にできない場合（非平面・自己交差）、今は黙って線のまま残る。→ `faceFromLoop` が「閉路なし」と「閉路はあるが不正」を区別し、ツールが日本語で理由と次の手（非平面ならロフト等）を表示する。線は保全
3. **F-05 穴**: 外周の面の内側に閉輪郭を描くと、今は外周の上に重なる別の面になる（押し込めば穴になるので機能的には代替あり）。正式な「内周を持つ面」は共有エッジ・入れ子判定の設計が必要 → Gate 1 の後半
4. **P-10**: API の `create_line` は自動面化しない → GUI と揃えるため `auto_face`（既定 true）を追加

### 4.2 既存面の分割（§3.3）

**現在**: ソリッドの平面を端から端まで横断する線（折れ線可）→ `SplitOp{FaceRef, 点列}` をソリッドのレシピに追加。`BRepFeat_SplitShape` で正規トポロジーとして分割し、検証済み（境界は表示線ではない ✓）。上流の寸法変更にも追従。

**ギャップと方針**
1. **単独の面オブジェクト（矩形などのプロファイル）の分割が未**。→ 分割後の各部分を `FacePart{元の面レシピのスナップショット, 分割線, 部分内の代表点}` としてレシピ化し、元の寸法を保ったまま 2 つの面オブジェクトに分ける（1 Undo）。各部分はそのまま Push/Pull 可能（F-07）
2. **分割線が短く途中で止まる／辺と重なる**: 現在は拒否（面に変化なし・線として残す）。ケース別テストを追加（§3.3 の要求）
3. **既知の制限**: 後続の Push/Pull で同一平面の面が統合（`UnifySameDomain`）され、分割線が消えることがある。→ 統合を「その操作で生まれた面」に限定する案を Gate 3 で検討（リスク: 統合しないと面が細切れになる）
4. **曲面上の分割は別フェーズ**（p-curve が必要。平面処理で擬似的に切らない）

## 5. 優先順位（依存順）

**Gate 1（今回から着手）: 描画 → 面 → 立体**
1. F-08: 作図＋自動面化を 1 Undo に（線・円弧ツール）
2. F-04/F-06: 面にできない閉路の理由表示（非平面・自己交差）、線の保全
3. 予告表示: 線ツールで「閉じる／分割する」をホバー時に表示（P-03/P-05）
4. 単独の面オブジェクトの線分割（`FacePart`、パラメトリック、1 Undo）
5. API の `create_line` に自動面化（P-10）
6. AC-03〜09 を AC 番号つきのテストとして整備

**Gate 2: 入力体験の統一** — 推論のヒステリシス、未閉合端点の可視化（AC-05）、AC-11/14/15/16/22 のテスト、囲み選択
**Gate 3: BRep ならではの直接編集** — 内周（穴）を持つ面、分割線が統合で消える問題、曲面上の分割、長時間演算の中断
**Gate 4: AI 共同操作** — 提案プレビュー（下記 §6）

Phase 3 の残り（3DM 入出力）は Gate と独立なので、Gate 1 の後に並行して進める。

## 6. AI 提案プレビューの境界（§9.2 の設計評価）

現行構造で実現可能: `Document` は値としてコピーでき、`Modeler` は `Document` を持つので、**一時 `Modeler` に現ドキュメントを複製 → 同じ `CommandApi` で batch を適用 → 差分（追加・削除・変更オブジェクト）を計算 → 表示**ができる。適用時は「提案作成時の履歴リビジョン（`CommandStack` の revision）」と比較し、変わっていれば再検証。正規ドキュメントへの適用は既存の原子的 batch をそのまま使う。新しい編集経路は不要。

## 7. 判断が必要な論点（§13 への現時点の回答）

1. **作図要素の所有者**: 分割線はソリッドのレシピ（`SplitOp`）または分割後の面のレシピ（`FacePart`）に吸収され、独立したオブジェクトとして残らない
2. **スケッチと BRep の境界**: 閉じた瞬間に面化し、作図と面化を 1 Undo にまとめる
3. **分割後の ID**: 面は ID を持たず、`FaceRef`（平面）/`SurfaceRef`（曲面）で幾何参照。曖昧・消失時は拒否（AC-13）
4. **重複輪郭・穴**: Gate 3。それまでは重なる閉輪郭は別の面として扱う
5. **閉輪郭とソリッド切削のタイミング**: 面上の閉輪郭は「面上の別の面」として作るだけ。Push/Pull した時点で初めてホストへ合成・切削（意図が確定してから。予期しない切り分けをしない）
6. **プレビューと確定の差**: 曲面 Push/Pull のプレビューは確定と同じ演算。重い場合は「簡略プレビュー」と表示する方針
7. **修飾キー**: Ctrl = コピー（移動・回転）／面・線の切替（円弧）。どちらも押すたびに切り替わるトグルで、ステータスに現在の状態を表示
8. **AI との競合**: AI コマンドは作図途中の操作を取り消してから実行（現行）。プレビュー導入時は「提案の適用」だけがドキュメントを変える
9. **巨大モデル**: 近似してよいのは表示メッシュとプレビューだけ。正規 BRep・スナップ・保存は近似しない
10. **建築部材**: 部材の意味はタグ／名前／将来の属性として付与し、幾何操作を強制しない
