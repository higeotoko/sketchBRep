# 円弧の交点を含む面生成・テクスチャの修正（2026-10-25）

## 円弧と直線を消しゴムで整理した後、閉じても面ができない

ユーザーの操作順：

1. 2 辺の直線を描く。
2. その間に円弧ツール（A）で円弧を描く。
3. 重なった線を消す。
4. 残った線をつないで閉じる。

この順序を GUI テストで再現すると、閉じても 4 本の線図のまま残った。
同じ平面の正しく閉じた輪郭を面にできるのが仕様。円弧を含むこと自体は制限ではない。

### 原因

- 円弧と直線は、円弧の端点だけでなく途中でも交わる。
- マウスから取った端点と膨らみでは、ほぼ接する円弧が直線と近い 2 点で交わる場合もある。
- 消しゴムは正しい交点まで直線を残す。
- しかし面生成は、線図オブジェクトの端点同士だけをたどっていた。
- 円弧の途中につながる場合に、幾何的に閉じた輪郭を見落としていた。
- 再現例では円弧の始点 X は約 `3995.542880`、消した後の直線の端点 X は約 `3996.847100`。後者は円弧との別の交点であり、端点を近づける修正は不適切。

### 修正

- 通常の端点探索で見つからないとき、曲線の途中への接続も調べる。
- 接続点で正確な曲線の区間を分け、閉じた経路を面にする。
- 面に使わなかった区間は、線・円弧として残す。削除しない。
- 曲線を折れ線に近似しない。許容誤差も広げない。
- 区間は `CurveIntervalOp` として元のレシピに追加する。元の作成情報を保持する。
- 辺の数と端点を検証し、元形状の編集で参照が変わったときは拒否する。
- 保存では修飾 `curveinterval` を使う。この修飾を含むデータは対応する新しいアプリで開く。
- 交点候補は空間索引で絞る。通常の端点探索・直線の領域探索は維持する。
- 面化と最後の線の作成は Undo 1 回。失敗時は変更を残さない。

これは消した線の端点などが曲線の途中につながる場合への対応。
未分割の任意の曲線同士の全交点から、すべての面を作る一般的な曲線領域演算ではない。
A の通常の「弓形の面」モードと Ctrl で切り替える線モードは従来どおり。

## N ツールで曲線を最後に描いた場合

調査中に見つかった別の不具合。
N の曲線ツールの確定だけが、輪郭の面生成を呼んでいなかった。
線・円弧と共通の `createCurveAndFace` を使うようにした。
曲線が先でも最後でも、同じ平面で閉じた輪郭を面にできる。
単独の閉曲線を作る操作や、DXF 取り込み時に自動で面を張らない方針は従来どおり。

## 編集するとテクスチャが単色になる

懸念事項として登録し、小さな修正で直せる表示不具合を再現した。

- 再現条件：テクスチャを割り当てた箱の寸法を変更する。
- マテリアルの参照と画像データは残っていた。
- 表示用形状を作り直す際、三角形メッシュができる前に画像の重ね描きを作っていた。
- 描画内容が空でもキャッシュが更新されるため、単色のまま残っていた。
- 表示用メッシュが生成される `Display / Redisplay` の後でテクスチャを更新するよう修正した。
- マテリアル全体の大規模な改修はしていない。
- 正規 B-rep に表示用メッシュを付けない原則は維持する。

## 確認内容と残る懸念

- 操作順を再現した GUI テストで、修正前の失敗と修正後の面生成を確認。
- 元の線の総延長が、面の輪郭と残る線の総延長に一致することを確認。
- 元の作成情報、保存再読込、Undo/Redo、押し出しを確認。
- 隙間がある輪郭・同じ平面にない輪郭は拒否し、モデルを変更しない。
- 辺の数が同じでも参照先の端点が変わった場合は拒否する。
- テクスチャは寸法変更・Undo・Redo の後も画像の表示が残ることを確認。
- Windows の実 GPU と報告された元図面での実機確認は未実施。
- 別の操作での素材割り当て消失、UV 編集、曲面への貼り方、描画性能は、今回の表示順序の問題と分けて懸念として残す。
