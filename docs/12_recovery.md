# 12. 自動保存・復旧・世代バックアップ

実際の設計データを預けられるよう、「保存し忘れ」「異常終了」「上書きの失敗・後悔」の 3 つから守る。

| 仕組み | 内容 |
|---|---|
| 原子的保存（既存） | 一時ファイルに書いて読み戻しを確認してから置き換え。途中で失敗しても元のファイルは壊れない |
| 自動保存（復旧用） | 未保存の変更があるとき、既定 5 分ごとに**復旧用の別ファイル**へ保存（元のファイルは書き換えない）。変更がなければ書かない。保存済みの状態に戻れば消す |
| 異常終了からの復旧 | 次の起動で「前回、正しく終了しなかった作業があります」と表示。復旧すると**元のファイルへの未保存の変更**として開く（保存先は元のファイル、無題なら新規） |
| 世代バックアップ | 保存で上書きする前に、前の版を `ファイル名.sbr.bak1`（最新）〜 `.bakN` として同じフォルダに残す（既定 3 世代） |

設定：ファイル > 自動保存とバックアップの設定（自動保存の間隔 0 = しない、残す世代数 0 = 残さない）。

## 仕組みの詳細

- 復旧ファイルの場所：アプリのデータフォルダ（Windows は `%LOCALAPPDATA%/SketchBRep/recovery`）。セッションごとに `<id>.sbr`（モデル）、`<id>.json`（元のファイルのパス・時刻）、`<id>.lock`
- **ロック**：起動中のセッションはロックを持つ。ロックが外れている（プロセスが終わっている）ものだけを復旧候補にするので、2 つ目のウィンドウ・同時起動で他人の作業を奪わない
- 正常終了（閉じる・新規・保存）では復旧ファイルを消す。異常終了だけが残す
- 復旧したセッションがそのモデルを引き継いで自動保存を続け、古い復旧ファイルは消す
- 複数ある場合は新しいものから確認（「あとで」なら次回の起動でもう一度）
- 自動保存は現状 GUI スレッドで書く（4,000 配置で約 0.2 s）。大きなモデルではワーカーで書く形へ（レビュー F の計算基盤と一緒に）

## 画像を含むモデル（テクスチャ・下絵の段で）

画像は内容のハッシュで参照して `.sbr` に埋め込む予定（docs/11）。復旧ファイル・バックアップも同じ `.sbr` なので、画像ごと復旧・移動できる。外部の元画像のパスは再読込用の手がかりとしてだけ持つ。

## 検証（`autosaveRecoveryAndBackups`）

保存済みなら復旧ファイルなし → 未保存の変更を自動保存 → 起動中は他から見えない → 異常終了を模擬 → 次のセッションで候補に出る（元のパスつき） → 復旧すると未保存の変更として開き、候補から消える → 保存で元ファイルに書き、前の版が `.bak1` → 世代数の上限 → 正常終了で何も残らない。
