## P0：今回すべて実装

| # | 内容 | 対応 | テスト |
|---|---|---|---|
| P0-01 | 消しゴムでなぞったとき、再探索が選んだ対象以外に広がらないようにする | なぞって消すとき、各印は**その印を付けたオブジェクトの系譜**（そのオブジェクト自身と、それまでの消去でそこから作られたオブジェクト）の中だけで線を探し直す。以前は同じ階層の他のオブジェクトまで探していた。同じ場所に線が 2 本重なって区別できないときは、どちらも消さずに件数をステータスに出す。線同士が端で接しているだけなら重なりとはみなさない | `gui_phase1: eraserDragFollowsWhatTheLineBecame`（1 本目を消すと ID が変わるが、2 本目はその後継から見つかる。関係ない線には触れない） |
| P0-02 | preview と原子的バッチから外部 I/O を外す | `preview` と `batch`（atomic）は、`external_io` の手順を 1 つでも含むと実行前に拒否する。preview の一時 API ではファイル系コマンドも無効にしてある（二重の防御） | `CommandApi.PreviewAndAtomicBatchNeverTouchFiles` |
| P0-03 | 3DM の部分読込を知らせ、「成功」の意味をはっきりさせる | `read3dm` が読込レポートを作る：オブジェクト数、読めた数、変換に失敗した数、一部が欠けた数（落ちた面・トリムの数）、未対応の種類ごとの数（mesh/subd/point/curve/annotation/block…）、単位。何かが欠けるファイルは既定で拒否する（何も読まない）。GUI は内訳を見せて「読めた分だけ読み込みますか？」と聞き、API は `allow_partial` と `report` を持つ | `Rhino3dmReport.*`（openNURBS で、正常 2・欠落 1・失敗 1・メッシュ・点・曲線の混在フィクスチャを作る） |
| P0-04 | 長い演算中のモデル書き込みを直列化する | 進捗ダイアログはイベントを回す（再描画と「中止」のため）。そのイベント配送の間を `GuiProgress::busy()` として印を付ける。その間、AI ブリッジは要求をソケットに溜めて順番を保ち、演算が終わってから実行する。直接の書き込み呼び出しは `busy` で拒否、自動保存は演算後に回す | `gui_phase1: aiWaitsForLongOperation` |

P0-04 について。レビューが提案しているのは「ModelSession にキューと確定済みスナップショットを置く」形。今回はその前段として、**再入が起こりうる唯一の入口（進捗中のイベント配送）を塞ぐ最小のゲート**を入れた。読み取りは、演算中もコミット前のモデル（変更前の確定状態）を返す。ジョブ化（P1-01）で演算を別スレッドへ移すときに、このゲートをセッションのキューに置き換える。
