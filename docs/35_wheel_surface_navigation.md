# 壁を越えて室内に入るホイール操作

## 使い方

1. 「表示 → 透視投影」をONにします。F8でも透視／平行投影を切り替えられます。
2. 入りたい位置の壁にカーソルを置き、ホイールで近づきます。
3. 壁の近くでは移動が細かくなります。そのまま続けると壁を越えて内部へ進めます。
4. 逆向きのホイールで戻れます。視線と画角は勝手に反転・変更しません。

平行投影は寸法確認や図面表示に使う従来の倍率変更のままです。室内へ視点を進める場合は透視投影を使ってください。速さやホイールの向きは従来の「表示 → ホイールズームの設定...」で調整できます。

## 原因と変更範囲

旧実装は面の10mm手前でカメラを止めていました。これはアプリで定めていたズームの停止条件で、壁ツールによる衝突判定ではありません。

今回、モデルの面に向かう透視投影のホイール操作だけを変更しました。

- 遠くでは従来と同じ距離に応じたズーム。
- 近接域では小さい移動を保ち、0に減速して止まり続けることを防止。
- 面を越えても元の接近方向を保ち、背後になったアンカーへ引き返さない。
- 通過後は移動速度の上限を設け、室内で際限なく加速しない。
- 同じ操作中は、入力を細かく分割しても結果が一致。逆操作でも戻れる連続した計算。

カメラの後ろの面・点を拾ってしまう既存の判定も修正しました。面の交差判定を前方の半直線に限定し、室内で背後の外壁へアンカーやスナップが飛ぶことを防ぎます。

歩行・重力・衝突判定を持つ新モードは追加していません。壁やソリッドの形状も変更しません。既存の選択・作図・保存・MCPの操作APIは維持しています。

## 実用面の確認

- 壁ツールと同じAPIで200mm厚・高さ3000mmの四周の外壁を作成し、外側から内側へ進めることを確認。
- 室内の物体が前方の面として取得できることを確認。
- 壁に近い位置で一度止めてから再開しても、細かい前進を維持。
- 通過時も視線方向とカメラと注視点の距離を維持し、同じ操作中の逆スクロールで元の位置へ戻ることを確認。
- まとめた入力、半ノッチ単位、非常に細かい分割での一致を確認。
- 遠くからの通常ズーム、平行投影、空白上の操作、作図途中のホイール操作も確認。

近接域10mmと通過後の速度上限に使う500mmの奥行き尺度はSketchBRep側の調整値です。SketchUpの数値を再現したものではありません。移動は入力に直接追従し、追加の慣性アニメーションや毎イベントの全モデル走査は行いません。

## 参考にした資料と確認範囲

確認日：2026年10月28日。

- [SketchUp公式 Camera API](https://github.com/SketchUp/ruby-api-docs/blob/gh-pages/Sketchup/Camera.html)：透視投影・平行投影、eye/target、画角の区別。
- [SketchUp公式ツール一覧](https://github.com/SketchUp/ruby-api-docs/blob/gh-pages/Sketchup.html)：ズームと歩行は別の操作。
- [Blender公式のZoom実装](https://github.com/blender/blender/blob/main/source/blender/editors/space_view3d/view3d_navigate_view_zoom.cc)：カーソル基準ズーム、段階入力、距離制限という設計上の区別。
- [Blender公式のDolly実装](https://github.com/blender/blender/blob/main/source/blender/editors/space_view3d/view3d_navigate_view_dolly.cc)：視線上のベクトルに沿って視点を並進する考え方。

参考にしたのはこれらの操作上の考え方です。計算はSketchBRep向けに実装しました。SketchUp・Blenderのヘルプサイト本文は本環境から403で参照できず、取得できた公式公開API文書・ソースを確認しました。SketchUpのホイールの内部減速式や通過閾値は公開仕様として確認できていません。「近づくと細かくなり、続けると中へ進める」というユーザーの実測説明を受け入れ条件にしています。

## 検証結果

ローカル（Qt 6.8.2 / OCCT 7.8.1）でCore351件成功、任意ベンチマーク4件スキップ。通常ズーム・空白・作図継続・壁通過のGUIテストは6件成功（初期化・終了を含む）。モデルの履歴を増やさず、壁の両面を越えて室内の物体を前方で拾えること、60ノッチの往復、まとめた入力と半ノッチ入力、近接時の一時停止・再開を確認しています。

GUI全体は148成功・7スキップ・従来からのローカル環境固有の失敗3件（topEdgesCopiedDownDivideTheSides、moveToolLiftsRidgeIntoGable、autosaveWritesInTheBackground）。最終確認はLinux/Windows CIでも行います。
