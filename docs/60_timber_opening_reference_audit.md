# 開口・架構の基準線修正と耐力壁連携の検証

2026-11-05 JST。基準コードは `073ce73`。ブランチは `claude/sketchbrep-modeler-spec-4wnp0b` のまま。

## 問題と変更後の動作

壁厚120mmの壁の面に窓を配置すると、開口の座標は壁芯から60mm離れた壁面上にある。
架構生成がこの座標を壁の基準線として使っていたため、まぐさ・窓台も60mmずれ、
壁芯に立つ間柱を窓の上下に分ける処理が働かなかった。

`ConstructionFrame.cpp`で、壁ツール由来の元矩形とSubtractの配置をたどり、
中央・左・右の指定基準線へ開口を投影するよう修正した。壁の表裏、平面移動・回転に対応。
任意B-repや追加編集で基準線が確定できないときは、外接箱から推測せず未評価の警告を出す。

また、生成する柱・通し柱・筋かいの設計芯が開口内を通る場合に警告を出し、
`opening_conflict=design_axis`、`opening_host`、`opening_index`を属性へ記録する。
柱の撤去や筋かいの除外は自動では行わない。支持条件の判断が別途必要になる。
手動削除を保持して再生成する場合は、生成しない柱を競合として警告しない。
保持した手編集部材は別途未評価とする。

提案プレビューが生成結果のwarningsを受け渡していなかったため、`MainWindow.cpp`で
応答と詳細表示へ伝達し、`TimberFrameDialog.cpp`で警告件数を表示するようにした。
プレビュー中の文書非変更、却下、適用・Undoの既存契約は維持する。

## 再現条件と結果

壁はY=0、厚さ120、下端600、高さ2400mm。窓は中心X=1820、幅1800、高さ1000、
壁下端から腰高700mm（世界Zの下端1300、上端2300）。8×6マス・910mmの架構を生成する。

|項目|修正前|修正後|
|---|---:|---:|
|まぐさ・窓台の中心Y|60mm|0mm|
|窓内を横切る間柱|2本|0本|
|生成部品・表示物|712|714|

2本の間柱を各々上下に分けるため、全体の部品数は2増える。
指定した筋かいと中央柱の設計芯競合は警告する。柱の断面端だけが開口へ掛かるケースや、
全ての実ソリッド干渉を検査する機能ではない。属性は生成時点の診断で、常時監視ではない。

## 耐力壁計算との連携で残る問題

生成筋かいの区間に対応する手入力壁を登録し、実部材の筋かいを削除する検証を行った。
入力上の存在壁量1.82mと比較のpassは変わらなかった。これは算術誤りではなく、
現在の計算がモデルとは独立した設計指定を評価するためである（docs/58の既存仕様）。
架構グループの対象違い・削除を拒否する仕組みは既にあるが、個々の壁区間と実部材は連動していない。

次の優先事項は、壁・階・開口・左右柱・上下横架材を持つ区間データへ、耐力壁仕様と
計算内訳を関連付けること。壁・開口・柱・高さ・仕様の変更後は該当区間を再確認待ちにし、
従来の手入力比較も別モードとして保持する。計算式の置換、四分割法・N値の追加は今回していない。

墨CAD 0.7.1のMCPから、現在の壁の開口を除いた耐力壁候補6区間を読取確認した。
壁ID＋t0/t1＋筋かい/面材仕様という関連付けは参考になるが、墨CADの初期値・法令判断や
自動修正を無条件に採用しない。墨CADの作業モデルは変更していない。

- 新しい基準線回帰試験が修正前に失敗することを確認。
- 表裏×基準線の6条件、平面移動・回転、競合警告、保存再読込、削除保持を追加確認。
- 最終の関連48件（Frames、FrameChecks、WallQuantity、TimberWorkflow）は全て成功。
- 広範囲の非GUI選択は516項目中508成功・7スキップ・ローカル通信1項目が制限環境で失敗。
  同じ通信試験をローカル通信可能な条件で再実行し、内部6件成功（初期化・終了込み8件）、終了コード0。
  全項目を同条件で一度に通したという意味ではない。
