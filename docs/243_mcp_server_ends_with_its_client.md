# 243. sbr_mcp がクライアントと一緒に終わる（2026-11-22）

## 困っていたこと（オーナー、2026-11-22）

sbr_mcp.exe が、クライアント（Claude など）が終わった後もプロセスとして残り、`C:\Apps\SketchBrep` を消す・入れ替えることができなかった。`taskkill /F /T /IM sbr_mcp.exe` で親子 2 つのプロセス（sbr_mcp と、その子のコンソールの係 conhost）を終わらせると、すぐ消せた。これがずっと続いていた。

## わけ

sbr_mcp は、入力（標準入力のパイプ）の終わりが来たら終わる作り。Windows では、パイプの書く側の口が別のプロセスに引き継がれて開いたままになることがあり（クライアントの間に挟まるプロセスなど）、その時はクライアントが終わっても入力の終わりが来ず、sbr_mcp は次の入力を待ち続けて、exe と DLL を掴んだままになる。

## 直したこと

- sbr_mcp は起動した時に、自分を起動したプロセス（親）を覚え、親が終わったら、入力の終わりが来ていなくても自分も終わる（Windows：親のプロセスの終わりを待つ。Linux・Mac：2 秒ごとに親が変わったか見る）。
- 入力の終わりで終わるのは今までどおり。

## 確認

**再現と修正の確認**（`tools/check_mcp_exit.py`。クライアントが sbr_mcp を起動し、パイプの書く側の口を別のプロセスに渡したまま終わる形）

| exe | 結果 |
|---|---|
| 直す前（de01f12 の ZIP の sbr_mcp） | 8 秒たっても残る（再現） |
| 直した後 | 1.7 秒で終わる |

- 直した sbr_mcp に `tests/data/mcp_session.jsonl` を流すと、直す前と同じ答え（initialize・tools/list・create_box 成功、わざと間違えた extrude が失敗）。

**Windows 実機確認（人の操作）**：入れ替えた後、Claude を終わらせて、タスクマネージャーに sbr_mcp.exe が残らないことを見る。※今の `C:\Apps\SketchBrep` の古い版には入っていないので、次の入れ替えの時だけは今までどおり taskkill が要る。

## まだ

- `sbr.py install`（B 案の入れ替え）で、`C:\Apps\SketchBrep` の exe から動いている物を止めてから入れ替える（docs/246 の予定）。
