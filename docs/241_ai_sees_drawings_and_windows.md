# 241. AI が図面一式と窓を絵で見る（MCP、2026-11-22）

オーナーの意図（2026-11-22）：「オーナー確認項目をできる限り絞り自動化したい」「MCP に追加することによってコンピューター use を使わずに解決出来ることがあるなら追加」。

docs/105 の人の確認のうち、AI が MCP で起動中のアプリを動かして見られる物を増やす。今までは、図面一式の PDF はファイルメニューからしか出せず、窓（ダイアログ）の見た目は画面を撮る（computer use）しかなかった。

## 足したコマンド（起動中のアプリだけ。「外部 AI からの操作を許可」が ON の時）

| コマンド | すること |
|---|---|
| `render_drawing_set` | 図面一式を、ファイルメニューの「図面一式を書き出す」と同じ作り（表題欄の設定・付近見取図の地図タイル）で、PDF 1 つとシートごとの PNG にする。置き場所はアプリ自身の一時フォルダ（`%TEMP%\sketchbrep-drawing-set`、毎回空にする）で、AI は場所を選べない。シートごとに番号・図面名・用紙・注（はみ出し等）を返す。`sheet`（"A-15" か 1 からの番号）で、そのシートの絵も AI に返す |
| `capture_window` | `window` に main（メイン画面。パネルも入る）か、窓の名前（project_outline・energy_route・vicinity_map・equipment・insulation・schedules・rooms・levels・site_road・site_ground・opening_performance）。窓は開いて、絵に撮って、キャンセルで閉じる（モデルは変わらない）。開かない時（何も選んでいない等）は、ステータスバーの文を返す |

- どちらも読むだけの扱い（Effect: read）。ファイルを保存・開く・好きな場所へ書くコマンド（save・open・export_*）は、今までどおりアプリ経由の AI には出さない。
- 付近見取図があると、`render_drawing_set` は国土地理院のタイルを取る（キャッシュに無ければ）。ファイルメニューと同じ。

| オーナーにしか決められない | 「分かりやすいか・困らないか」、本当の敷地の位置、申請先のやり方に合うか |

## 確認

**GUI テスト済み**
- `GuiPhase1::aiPicturesOfDrawingsAndWindows`：給湯設備を入れて `render_drawing_set {sheet: 1}` → PDF とシート全部の PNG がある、1 枚目の絵が返る、「機器表」のシートがある。無いシート "Z-99" は失敗。`capture_window equipment` → 題「設備の機器」の絵、窓は閉じている、機器は 1 つのまま。main も撮れる。何も選ばずに insulation → 「no window opened」で失敗。知らない名前も失敗。取り消しの数は変わらない。
- `McpServer.AppCommandSpecsAreValidSchemas`：アプリのコマンドが 11 個、どれも型が object。
- Windows ローカル：コア全件成功（8 件スキップ）。AI・図面・機器・付近見取図・断熱まわりの GUI 26 件成功。落ちた `paintedFaceFollowsItsMaterial` は表示倍率 175% でローカルだけ落ちる既知の 8 件（docs/192）。

**Windows 実機確認（人の操作）**：アプリを入れ替えたら、AI に `render_drawing_set` と `capture_window` を使わせて確かめる（AI がやる）。
