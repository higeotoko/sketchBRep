# 木造の一連操作検証と床開口（2026-11-04）

鉄骨への展開を保留し、木造の生成・修正・再生成・拾い出し・図面を一件の例で通した。
実案件の図面を使った検証ではなく、検証用に作った2階建てプランである。

## 検証例

- 910mmモジュール、1階8×6マス（7280×5460mm）、2階6×4マス（5460×3640mm）。
- 2階に2×2マス（1820×1820mm）の階段・吹抜け用床開口。一部下屋あり。
- 1階の壁に窓開口。開口幅を1200から1800mmへ変更し、まぐさを再生成する。
- 内部の柱を追加後、2階の1本を削除。編集を保持して作り直し、削除を復活させない。
- 保存・再読込後の数量と材積が一致し、4種類の伏図を生成できることを確認する。

この例の梁せい・柱・金物は既存の計画用初期値。構造設計例ではない。
柱を抜いた後に構造的に成立することも判定しない。形状の診断に合格があっても、未評価の事項は残る。

## 直したこと

### 階段・吹抜けの床開口

ツール → 木造架構を作成・作り直し... に床開口の表を追加した。
階と、X/Yの先頭・末尾の通り芯番号（先頭0）で矩形を指定する。
欄が画面に入り切らない場合は設定部分をスクロールする。

```json
{"command":"generate_frame","args":{"inputs":{"x_bays":8,"y_bays":6,"second_floor":{"x":[0,6],"y":[0,4]},"floor_openings":[{"storey":2,"x":[2,4],"y":[1,3]}]}}}
```

従来と同じプレビュー→適用。1回のUndoで戻る。
`floor_openings:[]` で床開口を外せる。最大100区間、階の範囲外・重なる区間は変更前に拒否する。
隣り合う別々の開口は、間の境界梁を残す。一つの大きな開口にしたい場合は一つの矩形で指定する。

開口内の合板・根太・床梁・大引を除き、横切る材は開口の手前と向こうに分ける。
火打は途中だけを残さず、開口に掛かるものを除く。1階の床束も開口内なら除く。
分けた材は通常の共有部材で、寸法変更・レベル追従・拾い出しができる。
付随する古い継手候補・端部金物を消し、分けた材に必要な概略表示を作り直す。
開口の縁に既存の梁があれば重ねず、足りない範囲だけ受け梁を追加する。

柱は自動削除しない。手で編集した部材を保持した場合、その部材が開口内に残ることがある。
その上へ同じ元材の分割梁を重ねず、警告を返す。開口範囲は通り芯間の計画範囲で、
梁の幅や仕上げを引いた有効寸法ではない。
階段・手すり、受け梁の断面、接合、柱への荷重伝達、床構面は未照査。
床面積・荷重など壁量計算の手入力値を自動で書き換えることもしない。

### 2階床の梁の二重生成

外周の胴差と、同じ位置の床梁が重なっていたため、内部の床梁だけを追加するようにした。
これ以降に生成・作り直した架構では、外周2本分の床梁とその概略金物が減り、拾い出しにも反映される。
保存済みモデルを開くだけでは形・数量を変更しない。

### 画面と作り直しの条件

- 2階の範囲指定を外したら、古い指定を消して全範囲に戻す。
- 角度で生成済みの屋根も、勾配欄を変えたら新しい勾配を使う。
  欄を変えなければ元の角度の精度を保つ。
- 床開口を再表示・変更・削除できる。
- 開口がある壁の参照、筋かい、追加柱など、画面に専用欄のない既存条件は内部で引き継ぐ。
  それらの条件が失われる問題ではなかった。

## 確認範囲

`TimberWorkflow.*` は床開口、根太の分割、既存境界梁の重複防止、不正入力の変更なし、
編集梁を保持する場合の重ね生成防止、一件を通した修正・保存・図面を確認する。
`timberStairwellRegenerationMatchesDialogAndExports` は実際の画面で範囲指定解除・屋根勾配変更・
床開口の変更を行い、生成条件・部材数・Undo・伏図PDFを確認する。

計算テスト、GUI自動確認、人によるWindows実機確認は分けて報告する。
人によるWindows操作、Jw_cadでの読込み、実寸印刷、構造的な妥当性の確認は未実施。
インストーラー2ステップは引き続き `if: false`、`.iss` は保持する。

次に詰める候補は、耐力壁の指定と実際の壁・筋かいの連携、その後に四分割法。
今回、四分割法・N値・金物の製品選定を追加したわけではない。

## 実行結果

- 計算テスト済み：Windows通常構成（MSVC19.44／OCCT8.0.1／Qt6.12、3DM対応ON）。
  全513件中506件成功・7件スキップ・失敗0、84.20秒。新規の一連操作6件を含む。
  1階の開口受け材を既存の大引に合わせた最終調整後、関連29件も再確認して失敗0。
- GUI自動確認済み：床開口の変更・範囲解除・勾配変更・UndoとPDF、既存の木造生成、拾い出し、壁量の4項目成功
  （開始・終了を含め6件、失敗0、7.13秒）。
  画面と伏図も画像で確認した。人によるWindows操作は未確認。
- CLIの修正後サンプルは木材388対象、既知の材積・実形状体積とも約9.517000m³、寸法未評価0。
  保存・再読込で数量・材積が一致。4種類の伏図をDXF/JWW計8ファイルと、それぞれに対応するCSVへ出力。
- 診断は合格983、不適合500、未評価4、対象外19。
  不適合の内訳は材の交差380組とその集計1件、定尺超過53、支え未検出37、間柱の支え未検出29。
  交差は母屋と垂木132組など小屋組が多い。概略材を接合加工なしで置く現状の納まりが残り、
  この操作テストが通ったことを、建物の成立確認には置き換えない。
- 同梱の `timber-workflow-example.sbr` が一連操作の検証例。
  `timber-workflow-gui-plan.pdf`／画像は、画面で2階範囲を全体に戻し、開口を3×2マスへ広げた別の検証例。
