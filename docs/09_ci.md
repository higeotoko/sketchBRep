# 09. CI（GitHub Actions）と実行時間の節約

`.github/workflows/ci.yml` には 2 つのジョブがある。

| ジョブ | 内容 | 目安時間 |
|---|---|---|
| `linux` | Ubuntu 24.04。ビルド（ccache）と全テスト（Xvfb 上の GUI E2E を含む） | 依存関係の取得時間と ccache の状況で変動 |
| `windows` | MSVC + conda-forge の OCCT/Qt。ビルド、コアテスト、ポータブル zip（`SketchBRep-windows-x64`）作成、zip 内 DLL の依存確認、zip から CLI/MCP のスモークテスト | 直近ではおおむね 20〜30 分。非 GUI テストは 4 並列 |

## 実行するタイミング

| 操作 | Linux | Windows の検証・ポータブル ZIP |
|---|---|---|
| 作業ブランチへコードを push・PR を更新 | 実行 | スキップ |
| `ci-*` タグを push | 実行 | 実行 |
| PR に `windows` ラベルを付ける | スキップ | 実行 |
| Actions から手動実行 | 実行 | `Also build the Windows package` を有効にすると実行 |

文書だけのブランチ push・PR 更新では起動しない。タグの push はタグ先のコミットのワークフローを使う。新しいブランチ push は同じブランチの古い実行を止める。タグの実行はタグ単位なので、作業ブランチへの次の push と並行できる。

### 節目で Windows 版を作る

作業ブランチに push 済みの対象コミットに、用途が分かる名前のタグを付けて、そのタグを push する。

```sh
git tag ci-preview-20261119 <対象コミット>
git push origin refs/tags/ci-preview-20261119
```

Actions でタグの Linux・Windows の結果と `SketchBRep-windows-x64` アーティファクトを確認する。タグの push で GitHub Release は発行されない。

PR ラベルは `windows` を付けた時点の実行に使う。Actions の手動実行には、デフォルトブランチ側に `workflow_dispatch` を設定したワークフローが必要。現在の運用ではタグを使う。

### インストーラー（現在は CI で停止）

以下は 2026-11-03 時点の配布仕様。現在の Windows CI の成果物はポータブル ZIP。
- Windows ジョブで、zip と同じフォルダから Inno Setup 6 のインストーラー（`SketchBRep-<版>-setup-x64.exe`）も作る。設定は `packaging/installer/SketchBRep.iss`、版は `CMakeLists.txt` の `project(... VERSION ...)`。成果物名は `SketchBRep-windows-x64-setup`。
- 中身：利用者ごとのインストール（管理者権限なし。管理者は全員向けも選べる）、スタートメニュー、デスクトップのアイコン（選んだ時）、`.sbr` の関連付け、アンインストール（モデル・設定・自動保存・落ちた時の記録は残す）。
- CI では、静かにインストール → ファイルと関連付けを確認 → 入れた先のプログラムを動かす → アンインストールして消えたことを確認する。
- 利用規約（EULA）は、空欄が埋まってからインストール画面に出す（今は同梱だけ）。コード署名はまだ（「PC が保護されました」が出る）。
