# 09. CI（GitHub Actions）と実行時間の節約

`.github/workflows/ci.yml` には 2 つのジョブがある。

| ジョブ | 内容 | 目安時間 |
|---|---|---|
| `linux` | Ubuntu 24.04。ビルド（ccache）と全テスト（Xvfb 上の GUI E2E を含む） | 初回 6〜7 分、2 回目以降は ccache で短縮 |
| `windows` | MSVC + conda-forge の OCCT/Qt。ビルド、コアテスト、ポータブル zip（`SketchBRep-windows-x64`）作成、zip 内 DLL の依存確認、zip から CLI/MCP のスモークテスト | 7〜10 分（非公開リポジトリでは Linux の 2 倍の分数として計上） |

## 節約のしくみ

| しくみ | 動作 |
|---|---|
| ドキュメントだけの変更は実行しない | `docs/**` と `*.md` だけの push / PR では CI を起動しない |
| 古い実行の自動キャンセル | 同じブランチ / PR に新しい push があると、実行中の古い CI を止める |
| ccache | Linux のコンパイル結果をキャッシュし、2 回目以降のビルドを短縮 |
| **節約モード**（任意） | リポジトリ変数 `SBR_CI_ECONOMY` を `true` にすると、Windows ジョブは次のときだけ動く: Actions 画面の「Run workflow」で手動実行（「Also build the Windows package」に✓）、または PR にラベル `windows` を付けたとき。Linux は毎回動く |

### 節約モードの切り替え

GitHub のリポジトリ画面 → Settings → Secrets and variables → Actions → **Variables** → New repository variable
- 名前: `SBR_CI_ECONOMY`、値: `true` … 節約モード ON
- 変数を削除するか `false` … 通常モード（push ごとに Linux と Windows の両方）

公開リポジトリでは標準ランナーの実行時間が無料なので通常モードでよい。非公開に戻すときは節約モードを推奨。

### Windows 版 zip が欲しいとき（節約モード中）
- PR にラベル `windows` を付ける（付けた時点で Windows ジョブだけが走り、その後の push でも毎回走る）
- または Actions → CI → Run workflow（ブランチを選んで実行）
