# 構造の診断を画面に重ねる（2026-11-05）

オーナーと決めた「診断はモデルを変えずに画面で見せる（壁量の横棒、四分割の帯、柱の N 値の札、支えの無い所の印、直す候補の半透明表示）」
（docs/70 §5）の第一段。**今ある計算の結果だけ**をまとめて、パネルと 3D の重ね描きで見せる。
まだ計算していない四分割法・N 値などは「未評価」と表示し、合格のように見せない。

## 画面

「建築 > 木造 > 構造の診断（画面に重ねる）...」または「ツール」から開く。

| 部分 | 内容 |
|---|---|
| 壁量の横棒 | 「木造の壁量...」の入力から、階・方向ごとに「存在壁量／必要壁量（％）」を横棒で表示。緑＝足りている（壁量の比較のみ）、赤＝不足、橙＝未評価（理由はツールチップ） |
| 但し書き | 壁量の基準の版・施行日・表の確認日（docs/52 §7.3）。確認から 1 年を過ぎたら強めの注意を足す |
| 3D の重ね描き | 指定した耐力壁を、その階の判定の色の線で表示（nFL のレベルの高さ。無ければ Z=0 と明記）。印の対象は枠線で囲む |
| 印の一覧 | 架構チェックの不適合・未評価と、基礎までの支持先で支えが見つからない部材（支えなし・隙間・食い込み・一部だけ・候補が複数・未評価）。ダブルクリックで対象を選択して寄せる |
| 未評価 | 四分割法、N 値（柱頭・柱脚の接合）、柱の小径・直下率、横架材の断面、地盤・基礎の構造計算 |

- 重ね描きは専用の層で、選択・吸着の対象にならず、モデル・Undo・保存に入らない。
- モデルを編集すると、重ね描きと一覧はすぐ消えて「モデルから更新」を促す（古い印を変わったモデルの上に残さない）。
- 「画面に重ねて表示」を外すと、一覧だけ残して重ね描きを消す。パネルを閉じても消える。
- 「架構チェックの印」「基礎までの支持先の印」をそれぞれ外せる（画面の枠だけ。一覧は全件）。
  二階建て 4×4 間のサンプルでは架構チェックの不適合が 152 件（うち COM-01 が 111 件）、支持先の要確認が 22 件と多く、
  画面が埋まるため（`ccfe446` の検証で確認し、次のコミットで追加）。架構チェックの判定そのものは今回変えていない。

## API / MCP

```json
{"command":"check_structure","args":{}}
{"command":"check_structure","args":{"frame_rules":["LAT-"]}}
```

読み取り専用（effect: read）。`wall_quantity`（rows・notice・as_of・stale_table・unassessed）、`walls`（階・方向・
壁の状態・その階の判定・世界座標の始点終点・レベルから高さを取れたか）、`markers`（元の確認・状態・ルール・対象 ID・内容）、
`counts`、`unassessed`、`verified:false` を返す。中身は `check_wall_quantity`・`check_frame`・`check_foundation_supports` の結果そのもの。

## 実装で見つけたこと

- 一時的な JSON のメンバーを範囲 for で回すと、一時データが先に消えてループが空になる（C++ の落とし穴）。
  実装中に気づいて、解析結果を変数に入れてから回すようにした。同じ書き方が他に無いことも確認した。
- 木造レシピのレベル名は「<架構名> 1FL」の形。壁の階 "1" は、名前の最後の語が "1FL" のレベルの高さに描く。

## まだ作っていないこと（次の段）

- 四分割法（側端部分の壁量充足率・壁率比）と N 値（柱頭・柱脚の金物）の計算そのもの。計算ができたら帯・札として重ねる。
- 柱の小径・直下率、横架材の断面の目安。
- 直す候補の半透明表示（不足する方向に足せる壁の位置の提案）。自動で足すのではなく、人が選んで確定する流れにする。

## CI で見つかった異常終了と修正（`def2621`）

`ccfe446` の CI で、Linux の GUI テストが新しいテストの後片付けで異常終了（SegFault）した（Windows は成功）。
ウィンドウを閉じる時、3D 画面が先に壊れた後で、パネルが重ね描きを消そうとして壊れた画面に触れていた。
画面への描画は、壊れたら自動で空になるポインタ（QPointer）を通すようにした。
同じコミットで「架構チェックの印」「基礎までの支持先の印」の切り替えも足した。
