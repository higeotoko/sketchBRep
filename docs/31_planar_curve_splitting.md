# 平面を曲線で分割する修正（2026-10-26 JST）

ユーザー報告：平らな面に曲線を描いても面が分割されない。画像の面は平面であると確認済み。
前回保留した「曲面を線で分割する」改修とは別の問題として対応した。

## 原因と対応

- 既存の面分割経路は `worldPolyline` による直線・折れ線だけを対象にしていた。円弧・スプラインは表示されても分割対象にならなかった。
- 円弧と曲線ツールから、正確な曲線を平面の境界として刻む処理を追加。曲線を折れ線に近似しない。
- 円弧ツールは通常モード／Ctrlの「円弧のみ」モードとも、既存の平面を横切る場合はその面を分割する。面を分割できない場所では、通常モードは従来どおり円弧＋弦の面を作る。
- 曲線ツールは始点の面から作図平面を保持する。従来は点ごとに水平面を指定していたため、傾斜面での作図に対応できなかった。
- 傾斜面の境界へスナップした点で、画面の整数ピクセルへの丸めにより面へのヒットが外れ、水平作図平面へ戻るケースも修正。近隣1ピクセルの見えている面のうち、スナップした点を含む平面から作図平面を取得する。
- 上面／下面の点や辺が画面上で重なると、輪郭ではどちらも可視と判定され、登録順や投影誤差で下面の点が選ばれた。同じ画面位置・優先度なら視点に近い点／辺を選ぶよう修正した。これを直さないとスプラインの端が下面、途中の点が上面になることがあった。

## 対象と制限

- 円弧・曲線ツールの単一の辺からなる曲線と、単独の平面／立体の平らな面が対象。傾斜していても平面なら扱う。
- 曲線が面の境界から境界まで横切る場合に分割する。面からはみ出した部分は正確な曲線として残す。
- 面の途中で止まる開いた曲線、面から浮いた曲線、面を突き抜ける曲線では分割しない。投影や延長は行わない。
- 非表示・ロック対象、別の編集グループは分割しない。多数の線をまとめたDXFレイヤCompoundを単一の作図線として処理しない。
- 曲面への投影・分割は今回の対象外。[前回の調査](29_curved_face_split_assessment.md)どおり保留。（2026-10-29：円柱・円錐への分割は [39](39_curved_face_split.md) で対応。投影は引き続き行わない。）
- 円弧の分割後に膨らみだけを数値再入力して編集する操作は対象外。形状を変える場合はUndoして描き直す。
- 単一立体で分割処理の繰り返しが256回に達する曲線は中止し、呼び出し側のUndoグループを取り消す。

## 形状・履歴・素材

平面の単独オブジェクトは別々の面に分け、元のレシピと正確な分割曲線のスナップショットから再生成する。
立体では分割曲線を `SplitOp` に保持し、閉じた立体を維持する。形状を破壊する三角形分割は行わない。
作図＋分割は1回のUndoで取り消せる。SBR保存・再読み込みにも対応する。

`FacePart.source` の2番目の要素が存在する場合は正確な分割曲線を表す。既存の直線分割データは従来どおり1要素で読み込む。
`SplitOp` にオプションの `curve` を追加し、従来の `points` だけのデータも読める。
新機能で保存したデータは更新版のEXEで開くこと。旧版による新しい曲線分割レシピの読み込みは保証しない。

単独面に塗られた素材の指定は分割後の各面へ引き継ぐ。素材ライブラリや画像データは変更しない。
これは今回の分割による素材の取り落としを防ぐ処理であり、過去に報告された全操作でのテクスチャ問題を解決したとするものではない。

## 検証

- コア：正確な円弧境界、面積・立体の体積維持、傾斜面、配置済みグループ、素材とテクスチャ参照、Undo/Redo、SBR保存・再読み込み、分割後の押し出し／プッシュプル。
- 分割しないケース：面の途中で止まる、面から浮く、別平面にある曲線、異なる編集グループ。
- はみ出す円弧は面を分け、外の2区間を円弧のまま残す。
- 24本の円弧から25面を作成し、総面積・保存再読込・1回のUndo/Redoを確認。Linux／OCCT7.8.1で分割処理は約0.28〜0.45秒。これは小規模な平行配置の値であり、多数の交差や大規模モデル全体の性能保証ではない。
- スナップ：上から見て同じ画面位置になる上面／下面の端点・中点・辺について、上面を選ぶことを確認。
- GUI：円弧通常／円弧のみ／曲線の各ツールから、単独平面・傾斜平面・立体の見えている上面を分割する9パターンの操作を確認。

ローカル全体確認：コア348件合格・任意ベンチ4件スキップ。GUI本体144件合格・既存3件失敗・7件スキップ（曲面のコピー分割、棟の移動、書き込み先制限によるバックグラウンド自動保存）。新しい失敗なし。BREP/IGES GUI6件、STL GUI5件、DXF取り込みGUI17件も合格。GUI本体は仮想画面接続の失敗後に別ディスプレイで再実行した。
