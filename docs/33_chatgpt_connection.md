# ChatGPTのチャット画面からSketchBRepを操作する（2026-10-26 JST）

Claude専用ではない既存のMCP連携に、ChatGPT向けの **Streamable HTTP接続口** を追加した。
起動中のSketchBRepのモデルをChatGPTのツールから読み取り・編集する。OpenAI APIキーを入力する方式やアプリ内チャットではない。

## 必要なもの

- 更新版のSketchBRepを起動できるPC。
- カスタムMCPアプリ／開発者モードを使えるChatGPTのアカウントと設定。プランや組織の管理設定により利用できない場合がある。名称や提供範囲はChatGPT側の更新に依存する。
- PC上の接続口へ届く公開HTTPSトンネル。以下ではngrokを例にする。ngrokはZIPに含めず、利用者がインストール・アカウント設定を済ませる。

参考： [OpenAI公式 Apps SDK examples の接続手順](https://github.com/openai/openai-apps-sdk-examples)。開発者モードとHTTPSトンネルを使う接続例が記載されている。

## 接続手順

1. ZIPを展開し `SketchBRep.exe` を起動する。操作したいモデルを開く。
2. **AI連携 > ChatGPT 接続...** を開き、**接続を開始**を押す。「外部AIからの操作を許可」もONになる。
3. ngrokをインストールし、同サービスの案内に従ってログイン／authtokenの設定を済ませる。
4. ダイアログの **コマンドをコピー** を押し、このPCのPowerShell等で実行する。例：
   ```text
   ngrok http http://127.0.0.1:51234
   ```
   ポートは毎回アプリが割り当てるため、実際の画面のコマンドを使う。
5. ngrokが表示する `https://...ngrok-free.app` などの公開URLを、ダイアログの **トンネルの公開HTTPS URL** に貼り付ける。ここにはホストまでを入力する（`/mcp/...` はまだ付けない）。
6. **接続URLをコピー** を押す。生成されたURLには `/mcp/` 以下の秘密の文字列が付く。
7. ChatGPTの設定で開発者モードを有効にし、アプリ／コネクターの作成画面からカスタムMCPアプリを登録する。
   - 名前：`SketchBRep`（任意）
   - MCPサーバーURL：上でコピーした **接続URL全体**
   - 認証方式：**認証なし（No authentication）**
8. ChatGPTの会話でSketchBRepアプリを選び、まず次のように頼む：
   ```text
   モデルは変更せず、現在のオブジェクトと選択状態を確認して。
   ```
   次に小さいモデルで、例えば次を試す：
   ```text
   原点に幅1000、奥行1000、高さ2000 mmの箱を1個作って。
   ```
9. 操作はアプリの画面へ反映される。必要なら **Ctrl+Z** で取り消す。

接続画面の受信リクエスト数が増えれば、アプリの接続口までMCP通信が届いている。
ダイアログを閉じても接続は継続する。アプリとHTTPSトンネルの両方を起動したままにする。

## 接続の停止と権限

- **接続を停止**、または **外部AIからの操作を許可をOFF** にするとHTTP接続口を閉じる。
- 停止・アプリ終了で秘密のURLは失効する。再開時は新しいURLをChatGPTに登録し直す。登録画面で編集できなければ、カスタムアプリを作成し直す。
- 「認証なし」はChatGPT側にOAuthを設定しないという意味。サーバーは **256ビットの秘密を含むURLそのものを操作権限** として扱う。URLは共有・公開しない。
- これは利用者自身の開発者モード向け接続。OAuth認証や複数利用者向けの権限管理、公開アプリとしての配布機能は実装していない。
- ChatGPTからモデルの状態や、要求したビュー画像を取得できる。ファイルの保存・開く・取り込み・書き出しは、従来のアプリ内AIブリッジと同じく禁止。保存は利用者が行う。
- 待機中・未受信の操作は停止で実行されなくなる。**すでに始まった形状計算は切断だけでは中断・巻き戻しされない**。タイムアウトした場合は、同じ編集を繰り返す前にモデルを確認する。
- ローカルstdio MCP（Claude Desktop / Claude Code / Codex等）は従来の `sbr_mcp` を使える。

## つながらない場合

- ChatGPTにカスタムMCPの作成画面がない：アカウントの機能提供範囲・開発者モード・組織の管理設定を確認する。SketchBRepだけでChatGPT側の機能は有効化できない。
- `localhost` のURLを登録した：ChatGPTからPC内のlocalhostへは届かない。生成した **公開HTTPS接続URL** を使う。
- トンネルを再起動した：公開ホストやポートが変わっていれば、アプリの表示どおりにトンネルを起動し、接続URLを登録し直す。
- 404：URLの末尾が欠けた、古い秘密URLを使った、トンネルが別のサービスを指している可能性がある。
- 403：公開ホストの入力や、Host / Originの一致を確認する。
- ブラウザーでURLを開くと405：正常。ここはMCPのPOST用で、Webページではない。
- 登録できても編集されない：会話でSketchBRepアプリを選ぶ。ChatGPT側がツール利用の確認を求めた場合は内容を確認する。最初は読み取りを頼み、次に小さいモデルで試す。

## 実装と検証範囲（引き継ぎ用）

- `McpHttpServer` は既存の `api::McpServer` をHTTPへ接続する。ループバックIPv4のみで待ち受ける。外部公開・トンネル実行は自動化しない。
- MCPはセッションなしのJSON応答。POSTを使用し、任意のSSE GETは405とする。HTTP/1.1のContent-Length・chunked・100-continueを処理する。
- 秘密パスの照合、HostとOriginの検証、CORS未許可、重複ヘッダーや余分な要求の拒否、リクエストサイズと接続数の上限を持つ。
- ヘッダー32 KiB、デコードした本文2 MiB（生の要求全体は2 MiB＋32 KiB）、応答64 MiB、接続16、受信10秒／待機120秒／応答送信10秒。完了済みの演算をこれらのタイマーで取り消すものではない。
- `AiBridge::execute` を経由し、GUIと同じ検証・失敗時の取り消し・Undoを使う。重い操作中は待機し、HTTP要求も直列実行する。
- MCPのツール注釈にreadOnlyHint・destructiveHint・openWorldHintを明示。読み取りと表示操作以外は破壊的変更の可能性ありと保守的に扱う。
- ビュー画像はMCPのimageコンテンツで返す。Windowsの日本語を含む一時画像パスも読めるようにした。
- 実モデルへのHTTP操作、Undo、ファイル操作拒否、画像バイト列、秘密URL／Host／Origin、形式不正／過大要求、chunkedと100-continue、停止・再開と秘密の更新をネットワークテストで確認する。
- GUIで接続開始・公開URL入力・接続URLのコピー・グローバルOFFによる切断を確認し、従来のローカル接続と操作中の要求待ちも再確認する。
- **ChatGPTの実アカウントと利用者のPCへのHTTPSトンネルを通した実接続は、このクラウドでは未実施。** ローカルHTTP／MCPの検証と、ChatGPT実画面からの接続成功は区別する。


### ローカルの実施結果

- HTTP通信テスト8件（初期化・終了を含む）合格。接続設定と既存AI連携の対象GUI7件も合格。
- コア348件合格、任意ベンチ4件スキップ。GUI本体145件合格・既存3件失敗・7件スキップ。新しいGUI失敗なし。
- 公式Python MCP SDK **1.29.0** からStreamable HTTPで接続し、プロトコル **2025-06-18** を合意。制限付きモデルの85ツールを取得し、箱の作成→一覧の読み取り→Undo→空になったことの確認に成功。
- SDKの確認はアプリの実行依存ではない。任意の再現手順：
  ```text
  python -m pip install -r tests/requirements-chatgpt-sdk.txt
  python tests/chatgpt_sdk_smoke.py build/tests/sbr_chatgpt_transport_tests
  ```
  Windowsでは実行ファイルの引数に `.exe` を付ける。テスト用の独立したメモリ上のモデルを使い、実アプリのローカルパイプや利用者のファイルには接続しない。
- ChatGPTアカウントと公開HTTPS経由の実接続が成功したという結果ではない。この点は上記の検証範囲どおり。
