# 214. 計画概要の、モデルに無い項目を入れる（2026-11-21）

docs/209 の「まだ」の1つめ。計画概要の表（`scheduleTable(document, 10)`）は、敷地・面積などモデルから読める数字しか出せなかった。物件名・主要用途は「未入力」のままだった。

## 入れる項目

確認申請書（建築基準法施行規則 第二号様式）の第二面・第三面から、図面の計画概要に載せることの多い項目を選んだ。**様式の原文とは照らしていない**。申請先の様式と照らして、足りない項目は後から足す。

| キー | 項目 | 入れ方 |
|---|---|---|
| `project_name` | 物件名 | 文字（図面一式の表題欄の「工事名」が空の時は、これを使う） |
| `client` | 建築主 | 文字 |
| `designer` | 設計者 | 文字 |
| `address` | 地名地番 | 文字 |
| `residence` | 住居表示 | 文字 |
| `city_planning` | 都市計画区域等 | 文字 |
| `fire_zone` | 防火地域等 | 防火地域／準防火地域／法 22 条区域／指定なし |
| `main_use` | 主要用途 | 文字 |
| `work_kind` | 工事種別 | 新築／増築／改築／移転／用途変更／大規模の修繕／大規模の模様替 |
| `start_date`・`finish_date` | 工事着手予定・工事完了予定 | 文字 |
| `source` | 確認資料 | 文字 |

どれも1行・100 字まで。人が入れた値をそのまま出す。区域・用途の法の判断や、防火の規定との照合はしていない。

値は文書の設定（`projectOutline`）に入る。ファイルに保存されて、Undo でも戻る。入れるのも1回の Undo。

## 入れ方と出る所

- 画面：「敷地」メニューの「計画概要の項目...」。決まった選択肢の項目はリストから選び、ほかは文字で入れる。OK で、変えた項目だけを1回で入れる。
- 申請図の工程の「1 敷地・配置図」に「計画概要の項目」の行を足した。状態は未入力／入力不足（足りない項目の名前を出す）／入力済み。ボタンで上の画面が開く。docs/212 の人の確認の指紋にも入るので、項目を変えると工程 1 は要再確認になる。
- 計画概要の表：物件名・建築主・設計者・地名地番・住居表示・都市計画区域等・防火地域等・主要用途・工事種別・着手予定・完了予定の行。根拠の欄は「入力した項目。確認資料 …」。
- 図面一式：表題欄の工事名が空なら、物件名が入る。
- AI：`set_project_outline`（`items`：{キー: 文字}、"" で消す）、`project_outline`（読むだけ。ラベル・選択肢つき）。人が言った値だけを入れて、建築主や住所を推測しない（コマンドの説明にも書いた）。
