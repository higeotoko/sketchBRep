# 床束・柱から束石と独立基礎を計画する（2026-11-05）

布基礎と支持先一覧に続き、実在する床束・柱の直下へ、矩形の束石・独立基礎を計画する機能を追加した。
支持先一覧の「未検出の床束に束石を計画」から対象を選択し、寸法入力・プレビュー・適用・作り直しへつなげる。
木造架構の画面にも床束の選択を追加し、未選定の鋼製束の目印と、木製床束の実形状を区別した。

## SumiCADの参照

接続済みSumiCAD 0.7.1（64ツール）へMCPで再接続し、次を読み取った。

- `list_actions {query:"footing",schemas:true}`：15アクション。
- `list_actions {query:"foundation",schemas:true}`：21アクション。
- `guide {topic:"foundation"}`。

`foundation.generate` の参照部材・基礎断面・重複回避、`structure.footingsUnderWalls` の対象の指定、
`structure.belowWall` の下部支持と高基礎の分離、ガイドの「追加された部材の下も再確認する」流れを照合した。
今回はこの流れを、SketchBRepの実床束・柱と既存の支持先一覧へ応用した。
SumiCADの束石専用の内部処理を確認・再現したという意味ではない。ソースコード・法規式・断面の初期値は移植していない。
モデルの編集・自動修正・保存は実行せず、プロジェクト固有の情報や認証値は同梱しない。

## 画面からの流れ

1. 木造架構の作成・作り直しで「1階の床束」を選ぶ。木製床束は実形状、鋼製束・製品未選定は目印。
2. 土台から布基礎を計画し、適用する。
3. 「木造 → 基礎までの支持先」を開く。布基礎に既に載る床束は形状の経路あり、内部の支持先がない床束は未検出になる。
4. 「未検出の床束に束石を計画」を押す。実部材で未検出の床束だけを選択して設定を開く。
5. 幅・奥行・高さを入力し、プレビューで形状とコンクリート量を確認して適用する。
6. 支持先一覧を「モデルから再確認」する。

ボタンは、部分支持・浮き・重複候補・未評価の部材を自動で補修するものではない。
鋼製束の目印や既に支持されている床束を、このボタンで束石の対象にはしない。
直接使う場合は実際の床束・柱を選択して「木造 → 束石・独立基礎計画（床束・柱から）...」。
柱は明示選択のみ。全ての柱や上階の柱へ勝手に独立基礎を付けない。

作り直しは束石の計画グループを選んで同じ画面へ戻る。寸法と参照部材を再表示する。
参照部材を選び直す場合は、先に新しい床束・柱を選択し、既存の計画を選び、対象を「選択した実部材の床束・柱」に切り替える。
架構の作り直し等で部材IDが変わった場合も、この方法で明示的に再指定する。近くの別部材へ自動で参照を付け替えない。

## 形と寸法

初期入力は幅300・奥行300・高さ150mm。形状検討用の仮の値で、必要断面・法定値・仕様の推奨ではない。
平面は世界X/Y方向の矩形。部材下面の実形状の中心へ配置し、天端は各部材の下面へ合わせる。
親グループの配置、柱の回転・断面の寄せ、共有部材も反映する。
幅と奥行は部材下面全体を覆う寸法が必要で、小さすぎる入力は生成前にエラーにする。

天端は世界Zを直接指定することもできる。自動に戻せば各部材の下面へ戻る。
高さが異なる部材には、それぞれの下面に合わせて独立した形状を置く。
これは地形へ追従する段差基礎ではない。地盤からの根入れ・床下地盤・基礎底の位置を決めた形とは扱わない。

各束石は編集可能な矩形＋押出レシピで、「基礎・土台」タグ、`kind:foundation_pad`、材料rc。
計画グループは文書直下に置き、元の床束・柱・架構・レベルを変更しない。
布基礎と同じ基礎伏図プリセットへ描かれる。数量は基礎検査のコンクリート量にまとめ、木材拾い出しには混ぜない。

## 重複・重なり・変更

- 同じ位置・同じ天端の参照部材は一つの束石へまとめ、参照元を全て記録する。
- 同じ入力の再実行は変更なしで返し、形状もUndoも増やさない。
- 束石同士や既存の立体と正の体積で重なる場合は、対象名を示して生成前にエラーにする。面で接するだけなら許容する。
- 判定は外接箱だけでなく実B-repの交差体積を使う。数値誤差との区別は0.001mm³で、構造・施工の許容値ではない。
- 手編集・追加・削除した計画は、明示的な置換を選ぶまで保持する。
- 参照部材の移動・断面変更・削除、基礎の手編集を検知する。計画の基礎種別を置換で変更することはできない。

複数形状を含む場合も、全て生成・測定・重なり確認した後に、一つのUndo操作として確定する。
途中の失敗で一部だけ配置しない。プレビュー却下・設定キャンセルは保存データを変更しない。
作り直しのプレビュー表示が元形状の管理フラグを変えていた既存の問題も、表示用の独立コピーを使って修正した。

## 検査とAPI

既存の `generate_foundation` に `inputs.type:"pads"` を追加した。既定の布基礎は従来どおり。

```json
{"command":"generate_foundation","args":{"inputs":{"type":"pads","sources":["床束ID1","床束ID2"],"width":300,"depth":300,"height":150}}}
{"command":"generate_foundation","args":{"inputs":{"type":"pads","sources":["柱ID"]},"preview":false,"expected_revision":123}}
{"command":"generate_foundation","args":{"replace":"束石計画ID","inputs":{"height":200},"preview":false,"expected_revision":124}}
{"command":"check_foundation","args":{"foundation":"束石計画ID"}}
{"command":"check_foundation_supports","args":{"ids":["床束ID1","床束ID2"]}}
```

APIは初期状態が読み取り専用プレビュー。適用はrevision確認か既存のbatch/proposeを使う。
束石は `sources` で1〜200本の実部材を明示指定する。架構全体の `frame` 指定は受け付けない。
`top_z` 省略は各部材下面、`top_z:null` は既存の手入力を外すmerge-patch。
`on_modified:"replace"` は手編集の明示的置換。部材IDの再指定は `inputs.sources` を上書きする。

`check_foundation` は布基礎と束石の両計画を返す。既存の単一部材の `quantities.*.id` は維持し、
複数束石は `quantities.foundation_pad.ids`、正味体積、連続体数で返す。
削除された生成部材があれば全量はnull、残存部材の既知量は別項目。手で追加した形状は生成部材の量には含めない。
天端が複数の場合、計画全体の `top_z` はnullとし、各参照元に `planned_top_z` を返す。
`packing_gap_mm` と `packing_gap_matches` は既存形式を維持し、束石では部材下面との隙間・0mmとの比較を表す。
参照が変わった・手編集された場合、一致判定は未確認のnullへ戻す。

## 残る範囲

地盤・支持力・沈下・凍結深度・根入れ・必要断面・配筋・アンカー・接合・荷重伝達の照査は含まない。
配筋設計はオーナーの既存方針どおり対象外。接触していても構造の合格にしない。
べた基礎、内部耐力壁の下部軸組、段差基礎・地形・床下地盤、人通口・配管・換気は引き続き別の工程。
鋼製束の実製品・調整高さ・接合は未実装。任意加工・非矩形・傾いた部材は未対応。
重なる束石を連続基礎へ自動でまとめる機能や、既存基礎の自動切欠きは行わない。
