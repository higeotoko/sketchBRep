# 架構チェック：段階3

docs/52 §6・§11の段階3。木造の形と配置の診断で、操作を止めない。
構造の安全・法令への適合・施工可否は判定しない。

## 画面

ツール →「架構チェック」。別のパネルで裏のスレッドが文書のコピーを調べる。
編集直後に古い結果を消し、250 msの入力待ちの後に再計算する。
計算中に再び編集した場合は古い計算を中止し、その結果を表示しない。
Undo/Redo、レベル・通り芯・共有部品・プロジェクトの初期値変更も更新対象。
チェックを開くためにAI接続をONにする必要はない。

- 判定は合格／不適合／未評価／対象外。件数は部材数ではなく結果の行数（梁端は両端それぞれ）。
- 初期表示は不適合・未評価のみ。チェックを外すと全件表示する。
- 行をダブルクリックすると対象を選択し、その部材へ画面を寄せる。
- 理由、測定値、必要な値を表示。詳しい理由コード・出典・検査器の版は行の説明に含める。
- CSVは表示フィルターにかかわらず全件。UTF-8 BOM、引用符処理つき。
  理由コード・値と単位・出典・検査器の版・文書のrevision・但し書きを各行に保存する。

## AI

```json
{"command":"check_frame","args":{"system":"timber","rules":["MOD-01","TMB-01"]}}
```

`frame` で生成済み架構グループを指定できる。支え・衝突相手は指定した架構の外も調べる。
`rules` を省くと全ルール。`LAT-*` などの接頭辞による指定も可能。
読み取り専用で、モデル・履歴・revisionを変えない。返り値は検査したrevisionを含む。
MCPにも同じコマンドを公開する。

各結果は `rule`、`targets`、`status`、`reason_code`、`message`、`measured`、
`required`、`source`、`normative`、`checker_version` を持つ。
`status` は `pass`、`fail`、`not_evaluated`、`not_applicable`。
`frame_settings` には生成入力と割付の方式・ピッチ・端部調整の記録を返す。
`complete` はぶつかり検査を上限・演算失敗なく走査できたかであり、構造上の合格ではない。

## 判定の範囲

ルールの一覧・説明・出典・比較許容差は `assets/construction/timber/checks.json`。
同じ表からヘルプと `get_construction_guide` の説明を作る。
比較許容差1 mmは、この概略診断の仕様値で、施工許容差や法令の値ではない。

| ルール | 今回の判定 |
|---|---|
| COM-01 | 木材の実形状の体積交差。まず外接箱で絞り、OCCTの共通部分の体積が1 mm³を超えるものを報告。候補の絞り込みは形状計算誤差0.0001 mmを使い、支え・通り芯の1 mmとは分ける。外接箱の重なりだけで不適合にはしない |
| COM-02 | 未編集の鉛直柱脚・水平梁端の下側と、木の柱・梁・土台・小屋束の立体との接触。接合耐力は判定しない |
| COM-03 | 現在の世界座標の設計芯長と定尺を比較。架構入力の `stock_length`、なければプロジェクトの定尺初期値を使用。継手の目印だけで合格にはしない |
| MOD-01 | 設計芯の両端と、対応する水平・等倍の通り芯交点の距離。形の中心から柱芯を推測しない。`module_exception` 属性に理由があれば対象外 |
| MOD-02 | 根太・垂木の生成時の平面割付位置と現在の設計芯を比較。移動・削除を検出。高さ変更と架構・通り芯全体の平面移動・回転は区別する |
| TMB-01 | 2FLをまたぐ未編集の一本柱、または2階管柱の柱脚に接する下階柱・受け梁。管柱の階への所属も使う。平屋は対象外 |
| TMB-02 | 水平梁の両端の下側に柱・受け材との接触があるか。接触位置と受け材IDを返す |
| TMB-03 | 未編集の一本の通し柱の設計芯が1FL〜2FLを通るか。切断・ブーリアンなどの編集後の連続性は未評価 |
| TMB-04 | 出典つきの柱間隔の目安の表が未登録なので未評価 |
| LAT-01〜03 | 壁量・四分割法・N値の検査器と根拠表は段階5。未評価 |
| SEC-01 | 断面照査は今回の対象外 |

COM-01は、非平行な部材の端部付近（断面外寸の1.5倍以内）に局所化した重なりを接合候補として
衝突とは区別する。平行な重複材や両方の材の中間で交差する物は、この除外を使わない。
接合候補しかない場合も、仕様が未確認なので全体結果を未評価にする。
これで継手・仕口の仕様が確認されたことにはならない。
標準では体積検査の候補2,000組まで。`pair_budget` で1〜20,000に変更可能。
上限に達した場合、閉じた立体でない場合、演算に失敗した場合は未評価を残し、合格で埋めない。

未評価になる主な情報不足は、対応する通り芯・階の高さ・設計芯・生成時の割付記録。
旧版の架構は割付記録を持たないので、MOD-02を推測で合格にしない。
手で編集した形や斜材の端部の支え、金物の仕様・耐力、基礎との取り合い、持ち出し梁の成立は未評価。
支えの検査は木材の材料・役割属性を使う。未分類の形が接する場合は、役割不足として未評価にする。
表示専用の金物・継手・鋼製束の目印を、構造上の支えとして数えない。

生成は概略の候補なので、生成直後にも定尺超過・受け材未確認・重複などの指摘が残る。
チェックの指摘を消すために、検査器が部材を動かしたり追加したりすることはない。

## 生成データの更新

生成記録の版を3にし、根太・垂木の設計上の平面割付位置と割付条件を保存する。
手編集を保持して再生成した場合も、その物の元の割付記録を保つ。
レベル追従では、平面割付の情報を勝手に書き換えない。

2階管柱の柱脚とその金物の位置を、仕上げFLから床下地厚ぶん下がった受け梁上端へ修正した。
それまでの生成物は勝手に移動しない。新規生成・明示的な再生成で反映する。

## 検証

`FrameChecks.*`：4段階、情報不足、柱移動とUndo、実形状の交差、端部接合候補、平行重複、
外接箱だけの重なり、0.5 mmの食い込み、検査上限、梁端の接触、定尺、通し柱、割付の移動・削除・保存、
読み取り専用、キャンセル、標準10×8、親の平面回転、例外の理由、架構外の支え・衝突、旧版・平屋。

`frameChecksUpdateAndDiscardStaleResults`：本物のメニューと結果パネル、計算中の編集、
古い結果の破棄、MOD-01/TMB-01の変化、選択・画面移動、CSV保存、Undo後の自動更新。

インストーラーのビルド・アップロードは引き続き `if: false`。
`packaging/installer/SketchBRep.iss` は保持する。今回もWindows zipを配布する。
