# ホイールズーム（2026-10-23、2026-10-28更新）

2026-10-28：透視投影で壁の手前に止まり続ける制限を変更しました。現在の使い方と参考資料は [室内へのホイール操作](35_wheel_surface_navigation.md) を参照してください。

依頼書：「SketchBRepのホイールズーム改善依頼書」（比較対象は Windows 版 SketchUp Pro 2026）。
調べた版：3462646。対象は `Viewport::wheelEvent`。

## 1. 原因（修正前）

```cpp
const int delta = event->angleDelta().y() / 4;        // 120 → 30（整数の割り算）
view_->ZoomAtPoint(x, y, x + delta, y + delta);       // OCCT に「斜め 30+30 px のドラッグ」として渡す
```

| 要素 | 修正前の挙動 | 影響 |
|---|---|---|
| 速さ | OCCT の ZoomAtPoint は (dx+dy)/100 + 1 を係数にする。刻み式マウスの 1 ノッチ（120）で ×1.6、5 ノッチで約 ×10.5 | **速すぎると感じた主な原因** |
| 入力の分け方 | 整数割り算のあと、1 イベントごとに係数を掛ける。120×1 回 = 1.600、60×2 回 = 1.690、1×120 回 = 1.000（小さい入力はすべて捨てられる） | 高分解能ホイールやタッチパッドでは、速さが不安定になったり、まったく動かなかったりする |
| 中心 | 画面上の点を中心に、カメラの倍率を変える（カーソル下の形状の奥行きは見ない） | 透視投影では、指した部材が横に滑る |
| 奥行き | 形状との距離を使わない | 近くでは 1 ノッチが大きすぎ、遠くでは小さすぎる |
| 描画 | `redraw()` で 1 フレームにまとめてから描く（もともと遅延なし） | 問題なし |

利用者の exe（Windows 版）は conda-forge の OCCT（7.8 系）をリンクしている。上の係数の計算はその版のソースによる。SketchUp の実際の倍率ではない。

## 2. 新しい挙動（`src/app/WheelZoom.h/.cpp`、`Viewport::zoomWheel`）

- **ノッチ量**：q = angleDelta.y / 120 を小数のまま使う。pixelDelta は、angleDelta が 0 の機器（一部のタッチパッド）でだけ使う（50 px で 1 ノッチ相当）。両方を足すことはしない。中身が 0 のイベント（ScrollBegin / ScrollEnd）では何もしない。
- **倍率**：r = 比率^q（= exp(k·q)）。イベントの分け方が違っても、同じ合計なら同じカメラになる。逆方向に同じだけ回せば元に戻る。
- **アンカー**（寄る先の点）：カーソルの下の点。
  1. 表示されている面（スナップ用のデータを使う。非表示の部材、ガイド、プレビューは対象外。断面で切った面は切り口の外側だけ）
  2. 面がなければ地面（z = 0）。ただし、地平線の近くで遠すぎる場合（通常の奥行きの 3 倍を超える）は使わない
  3. それもなければ、カーソルの視線上の点。奥行きは直前のアンカーの奥行き、なければカメラの注視点の奥行き。**原点やモデル全体の中心へは飛ばない**
- **透視投影**：面の近接域の外では視点をアンカーへ向かう直線上で動かし、距離を 1/r にする。モデル面の近接域は小さい移動で越えられ、通過後も視線方向を保つ。FOV は変えない。通過前のアンカーは視点から見て同じ方向に残るので、**画面上でカーソルの位置から動かない**。距離に比例して動くので、遠くでは大きく、近くでは細かく寄れる。
- **平行投影**：表示の大きさ（scale）を 1/r にする。アンカーの画面位置が変わらないように平行移動する。
- **操作のまとまり**：400 ms 以内の連続入力で、カーソルの移動が 3 px 以内なら、同じアンカーを使い続ける（壁から奥の壁へ途中で飛ばない）。どちらかを超えるか、オービットなどでカメラが変わったら、アンカーを取り直す。ScrollBegin / End だけには頼らない（Windows のマウスは送らないことが多い）。
- **モデル面への近接**：10mm手前で止める制限は廃止。近接域は細かく進んで面を越え、視線は反転しない。室内で加速しすぎない上限も設ける。地面・空白の補助アンカーの従来計算は維持。空白に向かって寄るときは、仮のアンカーを常に 500 mm 先へ押し出すので、止まらずに進み続ける。遠ざかる限界は 100 km。平行投影の scale は 10 mm〜10⁹ mm。
- **作図の継続**：ホイールはツールの状態（線の始点、Push/Pull の面、固定軸、入力中の数値）に触れない。ズームのあとはツールに現在のカーソル位置を渡し直すので、予告線が新しい視点に追従する。
- **慣性・時間ベースの加速なし**：移動量は面との距離に応じて変わるが、時間ベースの慣性や加速、イージングを足すことはしない（OS が送る慣性入力はそのまま反映する）。
- **表示倍率（DPI）**：ノッチ量は angleDelta だけから計算する。表示倍率はカーソル位置の変換（rayAt / project）にしか使わないので、100% / 150% / 200% でも 1 ノッチの倍率は変わらない。
- **向き**：OS の設定（ナチュラルスクロールなど）をそのまま使う。逆にしたいときは、「表示 > ホイールズームの設定」の「ホイールの向きを逆にする」で 1 か所だけ切り替える。

### 既定値は暫定

| 値 | 既定 | 根拠 |
|---|---|---|
| 1 ノッチの比率（距離 ÷） | **1.2** | 修正前（×1.6）より明らかに穏やかにするための**仮の値**。SketchUp の値ではない。下の実機比較で決める |
| pixelDelta 50 px = 1 ノッチ | 50 | 仮の値。タッチパッドの実機で調整する |
| 操作のまとまり | 400 ms / 3 px | 仮の値 |
| モデル面の近接域 / 空白の先行距離と通過後の速度尺度 | 10 mm / 500 mm | アプリ側の調整値。モデル面を通過可能にしつつ、近くでは細かく進める |

「表示 > ホイールズームの設定...」で 1 ノッチの比率（1.05〜2.00）を変えられる。値は保存される。

## 4. 実機比較の手順（SketchUp Pro 2026 と並べて）

1. 条件をそろえる：同じモデル（8000×12000 mm の外形、壁高 3000、窓幅 1200、50 mm 角の部材）、同じ描画領域の大きさ、同じ投影法と FOV（SketchUp 側はカメラ > 視野で確認）、同じ見付け。SketchUp 側の設定は変えない。
2. 記録しておくもの：SketchUp のビルド番号、OS の版、表示倍率、マウスの機種（刻み式か、高速回転モードがあるか）、SketchBRep の exe の SHA（ヘルプ > SketchBRep について）。
3. SketchBRep の診断ログ：環境変数 `SBR_WHEEL_LOG=C:\temp\wheel.tsv` を付けて起動すると、ホイールのイベントごとに 1 行記録される（時刻、機器名、angleDelta、pixelDelta、inverted、phase、カーソル位置、DPR、ノッチ量、投影法、FOV、eye / center / scale、アンカーとその出どころ）。通常は記録しない。
4. 測り方：窓幅 1200 mm の画面上の長さを、0 / 1 / 5 ノッチのあとで録画から測る（静かに 1 ノッチずつ × 3 回、素早く 5 ノッチ × 3 回、それぞれ寄る方向と戻る方向）。アンカーの奥行きにある部材なら、1 ノッチあたりの比率 ≈ (L₅ / L₀)^(1/5)。
5. SketchBRep の「表示 > ホイールズームの設定」の比率をその値にして、もう一度並べる。合った値を教えてもらえれば既定値にする（仮の目標：倍率の差 10% 以内）。
6. 体感で見るところ：狙った窓に自然に寄れるか、近づいたあとに細かく調整できるか、止めた位置で止まるか、手前の壁と奥の壁、面と空白の行き来、選択・線・Push/Pull・Z（ズーム）ツールそれぞれの最中。

SketchUp の公式ヘルプには、「ホイールズームはカーソル位置を中心に、形状との距離に応じて速さが変わる」とある。ただ、ヘルプのページによって説明が違う部分もある。内部の計算方法（レイキャスト、倍率の関数、加速の有無）は公開されていないので、推測で決めつけない。基準は利用者の実機での挙動とする。

## 5. 残っている違いと次の判断

- 1 ノッチの比率は暫定（実機で決める）。
- 透視投影でモデル面を越えるホイール操作は対応済み。重力・衝突判定・床に沿った歩行などは別の操作で、今回は追加しない。
- Z ツール（ドラッグでズーム）は今回の対象外。
- タッチパッドのピンチ（QNativeGestureEvent）は未対応。
