# ヘルプ画面と、落ちたときの記録（2026-11-02 JST）

## ヘルプ画面

「ヘルプ > 操作方法・ヘルプ」（F1）で開く。前の「操作方法」のメッセージは、この画面に置き換えた。

| 項目 | 内容 |
|---|---|
| トピック | はじめに / キーと操作の一覧 / 描く・数値で決める / 形を作る・直す / 建築の機能 / 図面を書き出す / ファイルのやり取り / 困ったとき・不具合の報告 |
| 検索 | 上の欄に打つと、その言葉を含むトピックだけが残り、本文の最初の場所に移る |
| 本文の場所 | `src/app/help/*.md`。プログラムに埋め込む（Qt のリソース）。インターネットは使わない |
| 開いたまま作業 | モーダルではないので、見ながら操作できる |

- 「ヘルプ > キーの一覧」で、キーのトピックを直接開く。
- `docs/` は開発の記録なので、利用者向けの説明は help に別に書いた（短く、操作だけ）。

## 落ちたときの記録

| 項目 | 内容 |
|---|---|
| 記録するもの | 直前の 64 件の操作：使ったツール、編集（Undo の名前と版）、開いた・保存した・取り込んだ・書き出したファイルの名前、図面ダイアログ、Qt の警告 |
| 記録しないもの | モデルの形、ファイルの中身、フォルダの場所 |
| いつ書くか | 落ちたときだけ（Windows の例外、POSIX のシグナル、捕まえられなかった C++ の例外、Qt の致命的エラー）。普段はメモリに持つだけ |
| 書く場所 | アプリのデータフォルダの `logs/crash-<起動時刻>.txt`（Windows は `%LOCALAPPDATA%\SketchBRep\logs`）。新しい 20 個だけ残す |
| 中身 | バージョン、OS、Qt と OCCT の版、失敗の種類（Windows は例外コードと、どのモジュールの何番地か）、直前の操作 |
| 次の起動 | 「前回、SketchBRep が途中で終了しました」と記録の場所を出す。「記録のフォルダを開く」「報告のしかた...」を選べる。一度知らせた記録は、もう知らせない |
| 送信 | しない。送るかどうかは利用者が決める |

- 落ちた瞬間はメモリを確保できないことがあるので、記録は固定の大きさの場所に持ち、書き出しは OS の関数だけで行う。
- 例外で操作が失敗しただけ（落ちない）のときは、今までどおり「内部エラーが起きました」と出し、作業は続けられる。その警告も記録に入る。
- 復旧（docs/12）とは別の仕組み。復旧は作業を戻す、記録は原因を探す。

## 不具合を報告...

「ヘルプ > 不具合を報告...」で開く。送ってほしいもの（手順・報告用の情報・落ちたときの記録・可能なら `.sbr`）の説明と、バージョン・OS・直前の操作を表示する。

- 「報告用の情報をコピー」：表示している内容をクリップボードへ。
- 「記録のフォルダを開く」：エクスプローラーで `logs` を開く。
