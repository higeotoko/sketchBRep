## 1. プロジェクトの要点

**SketchBRep**：建築設計向けの 3D モデラー。
- 操作は SketchUp：面をクリックして押し出す直接操作。
- 中身は Rhino 的：Open CASCADE（OCCT）の B-rep を正規データとして持つ。

**最優先の思想**：直感的に造形できること。人間と AI が同じ 3D 環境を扱えること。
- 精密な B-rep を保つ。
- 線や面を直接編集できること、開いた形状を編集できること、意図した面分割を保つ。
- Undo / Redo を壊さない。
- 処理を軽くするために、編集の意図やデータを失わない。

**技術**
- C++17 / CMake / Open CASCADE 7.6 以上 / Qt 6
- nlohmann-json / GoogleTest

**リポジトリと作業場所**
- リポジトリ：`higeotoko/sketchBRep`
- 作業ブランチ：`claude/sketchbrep-modeler-spec-4wnp0b`
  - 下書き PR #1：<https://github.com/higeotoko/sketchBRep/pull/1>（main にはまだマージしていない）
- 引継時点のコミット：`2dccb9d`（CI は Windows・Linux とも合格）

## 2. ビルドとテスト（Linux / Ubuntu 24.04）

```bash
cmake -S . -B build -G Ninja && cmake --build build -j8
./build/tests/sbr_core_tests                                  # コア：305 件
DISPLAY=:99 QT_QPA_PLATFORM=xcb ./build/tests/sbr_gui_tests   # GUI：131 件（先に Xvfb :99 を起動）
```

- GUI テストには X ディスプレイが要る。`Xvfb :99 &` を先に起動しておく（止まっていたら起動し直す）。
- ベンチマークは普段は飛ばされる。環境変数で動かす。
  - `SBR_BENCH_N=1000`：テスト名 `bench*`、`Bench*`
  - `SBR_BENCH_FILE=xxx.sbr`：保存のピークメモリ
- アプリなしでコマンドを実行するには `./build/tools/cli/sbr_cli script.jsonl` を使う（1 行に 1 コマンドの JSON）。
- `sbr_cli --schema` で、全コマンドの一覧が出る。

**CI（`.github/workflows/ci.yml`）**
- `linux`：ビルドと全テスト
- `windows`：ビルド、コアテスト、ポータブル zip `SketchBRep-windows-x64` の作成
- docs と `*.md` だけの変更では、CI は動かない。

## 4. 守っている決まり

**コード**
- 周りのコードの書き方に合わせる。
  - コメントは英語。「何をするか」より「なぜそうするか」を書く。
  - 名前の付け方、コメントの量も周りと同じにする。
- モデルの変更は必ず `Modeler` から `CommandStack` を通す。直接 Document を変えない。
  - 失敗したときは何も変えない。
  - 1 つの操作は Undo 1 回にする。
- AI 用の特別な裏口は作らない。GUI と AI は同じ `Modeler` を使う。
- 不具合を直すときの手順
  1. 先にテストで再現する。
  2. 修正前のコードでそのテストが落ちることを確かめる。
  3. 直す。
- 推測した懸念を、確定した不具合として扱わない。
- 採用しない近道
  - 正規の形状を表示メッシュに置き換える。
  - 許容誤差を広げて無理に通す。
  - テストを飛ばす・無効にする。
  - 加工の履歴を、黙って捨てる。

**docs**
- 日本語で書く。
- 1 文は短くする。手順や項目は箇条書きにする。

**コミット**
- 英語。1 行目に何が変わったかを書く。本文に原因・対策・数字を書く。

## 7. 直近の作業（新しい順）

**2dccb9d：消しゴムは、当てた区間だけを消す**
- ユーザー報告への対応。面の上で線が交差していると、先に引いた線が消せなかった。
- 原因：消しゴムが、線を引いた手順（SplitOp）を履歴から取り除いていた。後から引いた線が面を見つけられなくなっていた。
- 対策：両側の面を 1 枚にする手順 `MergeAcrossOp` を、履歴の最後に足す（保存形式では `mergeacross`）。
- **Windows実機確認：まだ。**

**b86f955：押し出した立体が、接している・重なっている立体と 1 つに合体する**
- ユーザー報告への対応。欠けを埋めた四角形、箱の脇の三角柱で、消せない線が残っていた。
- 原因：別々のオブジェクトの境目だった。
- 対策：`Modeler::joinTouching` を追加した。面を共有するか体積が重なれば、パラメトリックな和にする。辺や点で触れるだけなら、別のまま。
- **Windows実機確認：まだ。**

**e50b3da〜64d5153：性能・整合性監査への対応**（詳しくは `docs/22`）
- 変更が途中で失敗したら、全部元に戻す。

## 9. はまりどころ

- **壁 ID の変化**：AI の `place_openings` は、開口を開けた壁を新しい ID で返す。同じ壁を続けて操作するときは、直前の結果の ID を使う。
- **batch の参照**：`batch` の中では `"$3.ids.0"` の形で、前のステップの結果を参照できる。ただし batch 全体で Undo 1 回なので、Undo するとまるごと戻る。
- **ピックの扱い**：ピックの前に、表示がまだ取り込んでいない変更を 1 回分だけ取り込む（`takeInChanges`、`freshen`）。ピックの仕組みを変えるときは、`picksNeverUseADisplayBehindTheModel` を必ず通す。
- **Object のキャッシュ**：`Object` には、外接箱・面の素材・隠し辺のキャッシュ（mutable）がある。形状を変えたときは、形状と指定が一致しなければ自動で作り直される。手で消す必要はない。
- **関連テストの期待値**：期待値が古い挙動を前提にしていることがある。テストを変えるときは、変える理由をコミットと docs に書く。

#### 円弧についての追加調査・修正（ユーザー回答後）

- ユーザーは A の円弧ツールを使用。「2 辺の直線 → 間に円弧 → 重なった線を消す → 残りをつなぐ」と補足した。
- この操作順を GUI で再現し、面にならず 4 本の線図が残る失敗を確認した。
- 消した後の直線の端点が、円弧の途中の交点につながる場合を、端点同士だけの探索が見落としていた。
- `Modeler::faceFromCurveJunctions` を追加。端点探索で経路が見つからないときに、曲線の途中の接続点で区間を分けて面を作る。
- 未使用の区間は残す。元のレシピに `CurveIntervalOp` を追加し、履歴を捨てず保存再読込にも対応する。
- 辺の数・端点を検証して、元形状の変更後に違う辺を使わないようにした。
- 許容誤差は拡大していない。画像に見える隙間を勝手に埋める処理ではない。
