# 柱・土台・床束の支持先を基礎まで確認する（2026-11-05）

[布基礎計画](66_foundation_planning.md) に続き、柱脚・土台下・床束下の実形状と、その支持先を一覧にした。
柱→土台→基礎の順に確認でき、行とボタンで元の部材を選択・強調できる。
自動配置や構造の合否を増やす前に、実在する部材と未確認箇所を見えるようにする追加。

## 今回のSumiCAD MCP確認

SumiCAD 0.7.1（64ツール）へ接続して読み取った。最初の接続は切断したが、再接続後に取得できた。

- `list_actions {query:"structure",schemas:true}`：43アクション。
- `guide {topic:"foundation"}`：最下階の耐力壁・土台に合わせて基礎を生成し、追加された部材の下も再確認する流れ。
- `run_action foundation.steps`：現在のモデルは基礎0件・段差0件。
- `run_action structure.runChecks {check:"foundation",limit:50}`：現在のモデルは `Foundation: NONE — 基礎なし`。
- `list_actions {query:"support",schemas:true}` も取得したが、該当はバルコニーの2操作だった。今回の支持判定の根拠には使っていない。

`structure.belowWall` は、下階のない上階壁に下部軸組・高基礎を選び、壁から基礎までの支持のつながりを扱う。
`structure.offGridPosts` は自動配置の柱を理由・位置・IDと一緒に返す。
`structure.runChecks` は段階別の概要と問題の理由を分けて返す。
これらから「対象を実部材へ戻せる」「形状の確認と構造計算を区別する」「不存在と問題0件を区別する」流れを取り込んだ。
今回はソースコード・法規係数・寸法の初期値・自動修正を移植したものではない。
SumiCADのモデルを変更・保存していない。プロジェクト固有の詳細と認証値はリポジトリ・ZIPに同梱しない。

## 画面から使う

建築ツールバー「木造」→「基礎までの支持先（柱・土台・床束）...」。ツールメニューからも開ける。

1. 柱・通し柱・土台・床束が一覧に出る。非表示の構造部材も対象。
2. 直下の支持先、隙間、部材下面の重なり率、基礎までの形状の経路を確認する。
3. 行を選ぶと対象部材を選択・強調。「支持先を見る」で経由する土台と基礎を選択・強調する。
4. 形状・属性・部品定義などモデルが変わったら、古い一覧と強調は無効になる。「モデルから再確認」で更新する。

確認・選択で、モデル・壁量入力・Undoを変更しない。通常の直接編集を制限しない。
基礎自体を作り直す場合は、別の「布基礎計画」を使う。

## 何を測るか

対象の実B-repから水平な下面と支持候補の水平な上面を取り出す。
上面を下面の高さへ投影し、面同士の正確な交差面積と元の上下の差を測る。
外接箱は探索を減らすために使い、支持の成立には使わない。穴がある面は穴を除いて測る。
接触が線・点だけの場合は、載る面積がないので支持先として検出しない。

柱・床束からは土台、または基礎の立上り・底盤・束石を探す。土台からは基礎を探す。
最も高い候補面の高さの近傍だけを残し、近くの立上りが部分支持なのに下の広い底盤で覆い隠す判定を避ける。
初期の比較許容差は1mm、上下の探索深さは1000mm。モデルを確認するための入力で、構造・施工上の許容値ではない。

| 直下の状態 | 意味 |
|---|---|
| detected / 形状対応あり | 一つの候補面が下面全体を覆い、高さも対応する |
| partial / 一部だけ重なる | 一部しか載っていない。複数の部分を足して全面支持にはしない |
| ambiguous / 複数候補 | 全面を覆う候補が複数。重複・継ぎ目等を人が確認する |
| gap / 高さ・隙間を確認 | 全面の重なりはあるが、期待する隙間と高さが違う |
| interference / 食い込みを確認 | 支持面が部材下面より上に入り込んでいる |
| missing / 支持先未検出 | 探索範囲内で、対応する面積を持つ支持先が見つからない |
| not_evaluated / 未評価 | 形状・軸方向が未対応、未選定の目印、上階経路、計算上限等 |

柱・床束の接触の期待値は0mm。土台は基礎計画に保存されたパッキン高さを参照する。
計画に属さない基礎に対しては `packing_mm`（初期20mm）を使う。
隙間がこの値に合っても、パッキンの実物や接合・アンカーが存在するという判定ではない。
全面の数値比較は面積比1−1e-6以上を使う（計算誤差を区別するためで、部分支持の設計許容値ではない）。

## 柱から基礎まで

直下が土台の場合、その土台下面の基礎対応を `via` に添える。
柱が土台に触れていても、土台下に基礎がない・高さ不一致・部分支持なら、基礎までの経路は「要確認」。
参照する基礎計画が土台変更後で再生成待ち、手編集済み、参照不明の場合も「要確認」にする。
接触の測定値と、基礎計画の変更状態は別に返す。

`path_status:geometry_detected` は、候補が一意で、土台を経由する場合はその下まで形状が対応し、
参照する生成基礎計画に変更が検知されていない状態。耐力・荷重伝達・安全の判定ではない。
土台全体の下面を確認するため、柱の直下だけ接していて他の部分が欠けた土台は経路全体を要確認とする。
生成計画を持たない手作成の束石等は形状だけ確認し、変更履歴の照合は行わない。

## 束石・未評価の扱い

`kind:foundation_pad`、`material_class:rc` の実形状は手作成の束石・独立基礎候補として参照できる。
寸法・配置は人が決める。今回、束石を自動生成したり、床束の製品を選定したりはしない。
既存の鋼製束「未選定」の目印は `display_only:true` のため、支持成立の根拠にしない。

矩形の水平土台、鉛直柱・床束の加工前の部材と、それらの共有部品配置を対象にする。
傾斜・任意加工・非矩形の対象部材、水平上下面のない基礎、段差や複数天端の基礎は未評価。
土台天端から探索深さを超えて高い柱脚は、上階・梁上から基礎までの追跡が未対応と明示する。
内部耐力壁の下部軸組・梁経由の荷重経路、壁下の支持、アンカー・仕口・金物、地盤・沈下・耐力は未評価。
配筋設計は既存方針どおり対象外。既存の基礎構造チェックを合格へ変更しない。

## API / MCP

```json
{"command":"check_foundation_supports"}
{"command":"check_foundation_supports","args":{"within":"架構グループID"}}
{"command":"check_foundation_supports","args":{"ids":["柱ID","床束ID"],"tolerance_mm":1,"search_depth_mm":1000}}
```

`within`・`ids` は検査する部材を絞る。支持先は独立グループの基礎も探せるよう文書全体から探す。
`ids:[]` は対象0件。ID不存在・対象外の役割・不明なキー・範囲外の数値はエラー。
`packing_mm` は0〜1000、許容差は0〜10、探索深さは1〜10000mm。
`pair_budget` は形状交差の上限（初期20000、最大100000）。上限時は `incomplete:true` と未評価を返す。
文書内の関連部材は4000件まで。それを超えた場合は対象を分ける必要がある。

戻り値は `version:foundation-supports-1`、検査時sequence/revision、`source_signature`、`rows`、
状態別件数、比較数、未評価の基礎一覧 `unassessed_supports`、`verified:false`。
各行は部材ID・役割・下面高さ・面積、候補ID・隙間・面積比・期待する隙間・基礎計画の状態、経由土台を持つ。
共有定義の変更と親配置も署名に含める。検査の交差演算は非破壊で行う。
