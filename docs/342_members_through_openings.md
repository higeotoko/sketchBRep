# 342. 開口を通る柱・間柱・筋かいの照合

オーナーから例題E について指摘があった。

> 扉に柱とか間柱とか通っちゃってる

例題E の架構は、壁の開口を渡さずに作っていた（generate_frame の `opening_hosts` が空）。架構の作り方には、開口のある壁を `opening_hosts` に入れれば、次のようにする仕組みがある。

- 間柱を開口で切って、まぐさ・窓台を入れる。
- 開口にかかる柱・筋かいは「競合」として警告し、消さずに残す。

渡さなければ何もしないので、戸や窓の中に柱・間柱が立ったままになる。開口を後から動かした時も同じになる。それなのに、これを見つける照合が無かった。

## 作り

申請の段階3（平面）のチェックに「開口を通る柱・間柱・筋かい」の行を足した。

- 柱・通し柱・間柱（kind が column・through_column・stud）：部材の外形の箱で見る。次の3つがそろったら「通っている」とみなす。
  - 壁の開口の幅に、2 mm を超えて重なる。
  - 壁の厚みの中にある。
  - 開口の下端から上端までの高さに、2 mm を超えて重なる。
- 筋かい（brace）：外形の箱は柱間いっぱいに広がるので、箱では見ない。筋かいの下端から上端までの線上の 19 点のどれかが開口の中にあれば「通っている」とみなす。
- 1本でもあれば「要確認」になる。
  - 本数と、どの壁のどの開口かを出す。
  - 部材をチェックの対象（選べる物）にする。
  - 直し方も添える：開口のある壁を opening_hosts に入れて架構を作り直すか、柱の位置を見直す。
- 架構の部材が1本も無いモデルでは、この行は出さない。

## 確認

- `Schedules.MembersThroughOpeningsAreFound`（見本の建物の南の窓）：
  - 部材が無いと行は出ない。
  - 窓の端の 200 mm 外の柱は「入力済み」（通っていない）。
  - 窓の真ん中に立てた柱は「要確認」で、その柱1本が対象になる。消すと「入力済み」に戻る。
  - 窓をまたぐ筋かいは「要確認」。
- コアのテスト 878 本、申請・平面の GUI テストが通る。
