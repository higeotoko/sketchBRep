# 拾い出し・伏図：段階4

docs/52 §8・§11の段階4。木材の役割・断面・長さごとの数量と材積を集計し、
架構・タグで絞った伏図を、部材符号つきでDXF／JWW／PDFに出力する。
モデル・Undo履歴を変更しない。

## 画面から使う

### 拾い出し

ツール →「木材の拾い出し...」。開いた時点のモデルを集計する。
架構・タグ・「表示中の物だけ」で対象を絞り、「CSVに保存...」で全行を出力する。
材料属性 `material_class:timber` が対象。同じ部品の共有定義を数えるのではなく、配置を数える。
単一材を部品化した場合は、内部の役割・材料属性も参照する。

集計は裏のスレッドで行い、条件を変えた古い結果は表示しない。
外部でモデルが変わっても、開いた時点のコピーを使う。最新のモデルで集計するには開き直す。

| 欄 | 意味 |
|---|---|
| 数量 | 1本の部材・1枚の合板・未確認の複合部品などの対象数。単位は行ごとに表示 |
| 材積 | 未編集の部材の断面積×現在の世界座標の設計芯長。mm³を10億で割ってm³にする |
| 実形状体積 | 加工後の閉じた立体ごとの体積の合計。部材どうしの重複を建物全体で引いた値ではない |
| 定尺換算 | 同じ行の総延長÷定尺。小数のまま表示 |
| 切上げ参考本数 | 定尺換算を切り上げた理論下限。切断・木取り・発注計画ではない |

1本の対象に立体が複数あっても数量は1。共有部品が同じ定義を使っていても、配置が10あれば10本。
材料・役割を確認できても、部材の寸法を読み取れない形や編集後の形は、寸法・材積を未評価にする。
複合部品の中の材の内訳は未対応。未評価の「個」の行で残し、材積に勝手に足さない。
複合部品の体積を丸ごと木材として計上することもしない。
単一材以外の内訳を確かめる場合は、別途、部品の内容を確認する。

合計欄は既知の量だけの合計。未評価がある場合は全量ではない。
表示専用の金物・継手候補・鋼製束の目印は除外し、除外数を表示する。
合板は枚数・材積を出すが、板の定尺寸法が未登録なので、棒材の定尺換算は適用しない。
定尺は架構の作成入力 `stock_length`、なければプロジェクトの初期値を使う。

### 伏図

ファイル →「図面を書き出す（平面・断面・立面・伏図）...」を開き、「種類」で以下を選ぶ。

| 種類 | 既定の対象タグ |
|---|---|
| 基礎・土台伏図 | 基礎・土台 |
| 1階床伏図 | 1階床組 |
| 2階床伏図 | 2階床組 |
| 小屋伏図 | 小屋組 |

選択タグの上端から見下ろす図で、架構・タグ・縮尺を変更できる。
床下地や垂木に隠れた材も見分けられるよう、伏図は隠れた線の破線表示を既定でONにする。
「部材符号・断面」で部材の符号と断面を表示し、「非表示の物も含める」でモデルの非表示を含める。
通り芯は、架構に含まれるものや部材が参照するものを描く。モデルのタグ表示は切り替えない。

「この図の拾い出しCSV...」は、図面と同じ架構・タグ・表示条件の表を保存する。
図面の符号はこの表に対応する。別の対象条件で作った表では符号が変わる場合がある。
タグや架構が違う表と混ぜない。

既存の「書き出す」でDXF／JWW／PDF／DWG、「印刷」で用紙へ出力する。
DWGは既存のODA変換経路で、今回新しい変換器は追加していない。
部材符号は紙面寸法で配置し、重なりが避けられない場合は注記を返す。
図面の注記を見て縮尺・タグ・符号の表示を調整する。

基礎・土台伏図は選んだタグの形状だけを描く。基礎コンクリートを追加生成せず、
その有無・寸法を確認したことにもならない。図面には概略検討用・断面／接合未照査の注記を入れる。

## AI・CLI

```json
{"command":"take_off","args":{"system":"timber","within":"架構グループID","tags":["2階床組"],"visible_only":true,"include_csv":true}}
```

読み取り専用。`rows` は役割・断面・長さ・定尺ごとの集計、`parts` は配置ごとの情報、
`totals` は対象数・未評価数・既知の材積と体積、`excluded` は表示専用の除外対象。
断面・長さは0.001 mmに丸めて分類し、体積・総延長は丸める前の値で合計する。
`source`・`normative`・`version`・`scope`・`quantity_notes` を返し、APIは検査時の `revision` も返す。
`stock_length` で、この集計に使う定尺を明示できる（モデルの設定は変更しない）。
CSVはUTF-8 BOMつきで、引用符・改行を含む値も引用する。
符号・役割・断面・長さ・数量・単位・材積・実形状体積・定尺・換算・参考本数・
継手要確認・評価・タグ・対象条件・出典・版・但し書きを保存する。

```json
{"command":"export_drawing","args":{"kind":"framing","preset":"second_floor","within":"架構グループID","path":"floor2.dxf","scale":30}}
```

`preset` は `foundation`／`first_floor`／`second_floor`／`roof`。
`tags` で対象タグを指定できる（空なら伏図の既定タグ）。
`include_hidden`・`member_labels`・`hidden` を指定できる。
通常の平面・断面・立面にも、架構・タグの絞り込みと部材符号を使える。
ファイル出力なので、アプリ内AIでは既存のファイル操作制限に従う。

## データと検証

`assets/construction/timber/outputs.json` に出典・数量の扱い・伏図の種類と既定値を持つ。
人向けヘルプとAI向け手引きも、このデータから生成する。

`Quantities.*`：手計算との本数・材積の一致、共有配置、合板、拡大・鏡像、編集後の未評価、
複数立体を1対象として数えること、定尺換算、対象・タグ・非表示、読み取り専用、保存・再読込、
4種類の伏図、符号と表の対応、DXF／JWWを読み戻せること、手で作った部品の属性・内訳未評価。

`timberQuantitiesAndFramingExport`：実際の拾い出し画面・メニュー、条件変更、CSV保存、
開いた時点のモデルを使うこと、伏図・符号・対応CSV・PDF/DXF/JWWの書き出し。

既存の図面処理も、形状をコピーしてからOCCTへ渡し、共有形状の内部フラグを変えないようにした。
同期更新中にバックグラウンドの完了通知が同じ計算結果を二重に受け取らないよう、通知を一時的に抑止する。

インストーラーのビルド・アップロードは引き続き `if: false`。
`packaging/installer/SketchBRep.iss` は保持する。
