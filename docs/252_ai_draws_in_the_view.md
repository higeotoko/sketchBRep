# 252. AI が 3D の画面で、道具・クリック・ドラッグ・長さの打ち込みをする（2026-11-22）

docs/242 の「まだ」（3D の画面の中のクリック・ドラッグ）。docs/105 の、道具で描く項目（壁ツールで部屋を描く、移動ツールで動かす、屋根ツールで外周を描く…）を台本にするため。

## 足したコマンド（この PC の AI だけ。ChatGPT の接続からは断る）

| コマンド | すること |
|---|---|
| `ui_tool` | 道具を選ぶ（select・line・rectangle・push_pull・move・rotate・offset・measure・circle・paint・eraser・arc・dimension・text・section・polygon・scale・wall・slab・opening・member・room・roof・stair・door_swing・site_north） |
| `ui_view_click` | 3D の画面で、モデルの点（mm）をクリック。今の画面の見え方で画面上の位置に直す。`points` で続けて何点も、`button`（左・右・中）、`modifiers`（ctrl・shift・alt）、`double` |
| `ui_view_drag` | モデルの点から点へ、押したまま動かして離す |
| `ui_view_hover` | マウスを点の上へ（道具の先に見える形、スナップ） |
| `ui_type` | 道具を使っている時に、人が長さや数を打つのと同じに打つ（測定の欄に入る）。最後に Enter（`enter: false` で無し） |

- 点が画面の外の時は断り、「先に set_view（top・fit など）」と返す。
- 人と同じ速さ：マウスを点に動かし、画面が下にある物（スナップ）を出すのを待ってから押す。

## 作りで分かった事（テストで見つけた物）

| 物 | 直したこと |
|---|---|
| クリックを「答えの直後」に送る作りにしていたので、次の命令（マウスを乗せる・打つ）がクリックの途中に割り込んだ | 3D の画面のクリック・ドラッグ・打ち込みは、答える前に終わらせる。窓が開いて答えを待つ操作の時だけ `async: true`（答えの直後） |
| `ui_*` を「モデルを変える命令」の扱いにしていたので、ブリッジがその前後で描きかけの道具を止めて付け直し、クリックで始めた線の始点が消えた | `ui_*` は画面の命令の扱い（ViewWrite）にした（押した結果でモデルが変わる事はある。人の操作と同じ） |
| 何も無い所に描く線は、打ち込んだ後も Esc で終えるまで 1 本として残らない | アプリの作りどおり（テストを人の手順に合わせた） |

## 確認

- `GuiPhase1::aiDrawsInTheView`：真上から、四角形の道具で (0,0)・(600,400) をクリック → 600 × 400 の面。線の道具で (-500,-500) をクリック、(-100,-500) にマウス、「250」Enter、Esc → 長さ 250 の線。画面の外の点は断られ、「set_view」と言う。ChatGPT の道からは断られる。
- `McpServer.AppCommandSpecsAreValidSchemas`：アプリのコマンド 23 個。
- AI・図面・機器まわりの GUI 32 件成功。落ちた 2 件は既知のローカルだけの物（クリップボード、175% の画素）。
