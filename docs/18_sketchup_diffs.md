# SketchUp 操作差分表（2026-10-23）への対応

依頼資料：「SketchBRep × SketchUp：直接操作の差分表と修正依頼」（調査の固定点は 3462646）。
作業を始めた時点の HEAD との差分は、ホイールズーム（f108c12 = T4 / CAM-01、[docs/17_wheel_zoom.md](17_wheel_zoom.md)）だけだった。T4 はそのとき対応済みなので、ここでは作り直していない。

各項目に共通して守っていること：
- OCCT の正規 B-rep と解析的な円弧はそのまま扱う（ポリゴンに置き換えない）
- GUI と AI / MCP は同じ `doc::Modeler` を通る
- 1 操作 = 1 Undo
- 失敗したときは何も変えない

## T1：面だけを削除して輪郭を残す（DEL-01〜03、API-01 の一部）

**原因**：選択した要素（面・辺）はもともと区別されていた。ところが Delete の処理で、単独の面は「ばらの輪郭」として扱われ、`Modeler::remove` に進んでいた。そのため面も線も、オブジェクトごと消えていた。ソリッドの一部の面を消す処理（`removeFaces`）はあったが、消えた面だけが使っていた辺は残らなかった。

**修正**：`Modeler::deleteFaces(id, faces, droppedEdges)` を追加した。GUI の Delete も API の `delete_faces` もここを通る。

| 選択 | 結果 |
|---|---|
| 単独の面を 1 回クリック → Delete | 面が消え、外周と穴が線として残る（円は円のまま） |
| 箱の上面だけ | 上面が消えて開いた形状（Shell）になる。辺は側面も使っているので、線は増えない |
| 箱の上面＋その 4 辺（ダブルクリック） | 辺を消すと、その辺を使う面も成り立たないので、上面と側面 4 枚が消える。底面と縦の 4 辺が残る |
| オブジェクトの全部の面 | オブジェクトは消え、すべての辺（共有辺は 1 回ずつ）が線として残る |
| 面と辺（トリプルクリックで全部） | 何も残らない（これまでどおり） |
| 複数のオブジェクトの面 | 1 回の Undo でまとめて戻る |

- 辺だけを選んだ場合は、これまでどおり。分割線なら面が統合される。ソリッドの一部の辺だけを選んだ場合の拒否も残した。
- 残る線は、直線ならつながった折れ線（Polyline）、円弧なら解析的な円弧（Arc）。円・楕円・スプラインは、元の辺をそのまま保持する（以前は 12 点の折れ線で近似していた。消しゴムで残る線も同じ処理を通るので、こちらも正確になった）。
- 線は元の面と同じタグに入る。
- API の `delete_faces` は単独の面も受け付けるようになった。`edges` も一緒に指定でき、結果として `lines`（残った線）と `id`（オブジェクトが残っていれば）を返す。

**テスト**：
- `DeleteFaces.*`（コア 5 件）：単独の面、面＋辺、円の穴（保存・再読込しても半径 500 の円のまま）、箱の上面だけ／上面＋辺／全部の面、API
- `gui_phase1: deleteLooseFaceKeepsItsOutline`
- `selectFacesEdgesAndWholeObject` は期待値を新しい仕様に合わせて更新した（以前は「面だけは削除できない」ことを期待していた）

**実機で確認していないこと**：SketchUp 2026 で「面＋辺の一部」を選んで Delete したときに、どの面が残るか。上の表は、SketchUp のヘルプにある「辺を消すとその辺に囲まれた面も消える」という説明から組んだもので、実機と並べた比較はしていない。

## T2：200 mm 内側にオフセットしたあと、枠を Push/Pull する（OFF-01〜02、PP-01）

**原因**：単独の面のオフセット（`Modeler::offset`）は、元の面を複製してから `addObject` で追加していた。矩形や円を描いたときに通る `addProfile → punchHole`（外側の面に穴を開ける処理）を通らないので、元の面に内周ができない。結果として、大きな面と小さな面が重なっているだけで、枠になっていなかった。ソリッドの面のオフセットも、面の上に別の面を重ねるだけで、元の面は分かれていなかった。Push/Pull 側が穴を捨てていたわけではない（穴のある面の押出は、以前から正しく動いていた）。

**修正**：
- **単独の面**：オフセットと穴開けを 1 回の Undo にまとめた。
  - 内側：元の面がオフセットの形の穴を持つ「枠」になる
  - 外側：新しい面が元の面の形の穴を持つ「枠」になる
  - 面積の例：4000×3000 を内側に 200 → 枠が 2,640,000 mm²、中央が 3600×2600
- **ソリッドの面（内側）**：新しいレシピの手順 `InsetOp` を追加した。オフセットした輪郭を面に刻む（`geom::imprintOffset`、OCCT の `BRepFeat_SplitShape` を使う）ので、上面が「枠」と「中央」の 2 枚の面になる。どちらも単独で Push/Pull や塗装ができる。ソリッドのままで、体積も変わらない。距離はソリッドのパラメータとして後から変えられ、保存もされる（形式は `"inset"`）。
  - 外側へのオフセットは面からはみ出すので、これまでどおり別の面として作る。
- **数値の打ち直し**：オフセットの直後に数値を打ち直したとき、単独の面ではオフセットを作り直すので、枠の穴も一緒に追従する（Undo は 1 回のまま）。API の `set_parameter` で距離を変えた場合も、穴を開けている側の面が同じ手順の中で追従するようにした。
- **面の識別**：細い枠の面は、内部の点を探す格子の点がすべて穴の中に落ちて、どの面か識別できなかった（「2 枚の面のどちらか分からない」と拒否されていた）。辺の少し内側から内部の点を探す方法を追加した（`FaceRef::interiorPoint`）。

**テスト**：
- `Offset.InwardsTheOriginalBecomesTheFrame`：4000×3000 → 内側 200 → 枠を 1000 押し出す → 体積 2.64×10⁹ mm³、中央の面はそのまま。距離の変更、Undo
- `Offset.FaceOfSolidThenPushInMakesRecess`：箱の上面 → 枠と中央の 2 面、中央を押し込む、距離の変更、枠を引き上げる
- `Offset.OutwardsInwardsAndExtrude`：外側は枠になる、という新しい仕様に合わせて期待値を更新
- `gui_phase1: offsetToolInwards` / `offsetToolOnSolidFace`：GUI で枠の穴が追従すること、ツールで枠だけを押し出すこと

**実機で確認していないこと**：
- SketchUp で外側にオフセットしたときの面の分かれ方（元の面が残るかどうか）は、ヘルプで確定していない。実機で比較する。
- 穴のある面のオフセット、辺の列のオフセット（OFF-03）は対象外（これまでどおり拒否する）。

## T3：先に選んだ複数の辺でフォローミー（FM-01〜02、FM-04 の一部）

**原因**：ツールを起動すると、それまでの選択を読まずに断面をリセットしていた。操作の順番は「断面をクリック → 経路をクリック」しかなく、経路にできるのは 1 つの線オブジェクトか、ソリッドの面の外周だけだった。直線と円弧が見た目はつながっていても、別のオブジェクトなら 1 本の経路にはならない。ユーザーの画像のケースがこれで説明できる可能性は高いが、断面の向きやカーネルの失敗という可能性も残っているので、原因はまだ確定していない（「要再現」のまま）。

**修正**：
- `geom::pathFromEdges(edges, near)` を追加した。ばらばらの辺を端点でつないで、1 本のワイヤにする。
  - 辺を選んだ順番や向きは結果に影響しない
  - 開いた経路は断面に近い端から、閉じた経路は断面に最も近い頂点から始まる
  - 端点の誤差は 1e-4 mm までつなぐ。それより離れた隙間は勝手に埋めない
  - 分岐（その位置の座標を表示）、途切れ（離れている辺の本数を表示）、同じ辺の二重指定は、理由を出して拒否する
  - 円弧は解析的な円のまま経路に入る
- `Modeler::followMe(profile, edges)` を追加した。断面自身の辺が選択に混ざっていても、経路からは除く。GUI も API もここを通る。
- **GUI**：ツールを起動した時点で選ばれている辺（なければ、選ばれている線オブジェクトの全部の辺）を経路にする。そのあと断面を 1 回クリックすれば実行する（SketchUp と同じ順番）。失敗しても断面と経路はそのまま残り、別の面をクリックし直せる。辺を選んでいないときは、これまでの「断面 → 経路」の順番も使える。
- **API**：`follow_me` に `path_edges` を追加した。`{"id": ...}` でそのオブジェクトの全部の辺、`{"id": ..., "edge": ...}` で 1 本の辺を指定する。
- **FM-04**：
  - 当初：角のある経路で使う予備のスイープ（`mitredSweep`）は外周しか使わなかった。穴のある断面を通すと穴が埋まった形になるので、成功扱いにせず拒否していた。
  - 2026-10-23（W5）から：外周と各内周を、それぞれ同じ留め継ぎでスイープし、内周の分を Boolean でくり抜く。中空の断面は中空のまま角を回る（`Flows.SC13_*`）。

**テスト**：
- `FollowMeEdges.*`（5 件）
  - 順不同・逆向きでもつながる（始点は断面側、円弧は円のまま）
  - 分岐・隙間・二重指定は拒否し、モデルも Undo も変わらない
  - 直線＋直線＋円弧（3 つのオブジェクト）で、順番を変えても同じ体積
  - 面の外周で閉じた経路
  - API の `path_edges`
- `gui_phase1: followMeAlongSelectedEdges`

**実機で確認していないこと**：
- ユーザーの画像のケース（保存したモデルがまだないので再現していない）
- SketchUp で断面が経路から離れているときの扱い（ここでは断面の位置をそのまま使う）
- 手で経路をなぞる操作（FM-03）は対象外

## T5：棟の線を上げる屋根づくり（DRAW-02、MOV-02、MOV-01 の一部）

**確認したこと**：ソリッドの場合（箱の上面を線で中央で分けて、棟を上げる）は、これまでの `moveVertices` で正しく切妻になることを、受入課題（6000×4000×3000、棟を +1500）で確かめた。屋根の 2 面と両端の妻壁が追従し、7 面のソリッドで、体積は 7.2×10¹⁰ + 1.8×10¹⁰ mm³。差分表の「要再現」は、ソリッドの場合は問題なしと分かった。残っていたのは次の 2 つ。

**段階 1：共有境界の追従（DRAW-02）**
- **原因**：単独の面を線で分けると、2 つの別のオブジェクト（FacePart）になる。`moveVertices` は 1 つのオブジェクトにしか効かないので、分割線を上げても片側だけが動いて、もう片側は置き去りになっていた。
- **修正**：動かすオブジェクトと**辺を共有している**、同じグループ内の面・Shell・ソリッドは、その位置の角を一緒に動かす。1 回の Undo にまとめ、追従する側が動けなければ全体を断る。グループの外のものや、ロック・非表示のものは対象外。座標が同じでも辺を共有していないもの（角が触れているだけのもの）は動かさない。

**段階 2：Autofold（MOV-02）**
- 平らなままでいられない面だけを、平らな断片に分ける（`geom::moveVertices(..., autofold)`）。
  - 動かない角が 3 つ以上あれば、その部分はもとの平面に 1 枚の面として残る
  - 動いた角の側は、できるだけ少ない枚数の平面に分ける（必要なところだけ三角形）
  - 平らなままの面は分けない
  - 穴のある面・凹んだ面を折る必要があるときは、理由を出して断る
  - 裏返り、つぶれ、自己交差、体積のないソリッドは、これまでどおり断る
- レシピの手順（`MoveVerticesOp.autofold`）として保存されるので、移動量は後からも変えられる。
- 塗った面の素材は、分けた断片の両方に引き継ぐ。
- **既定**：GUI・API ともにオン（API では `autofold: false` で以前の動作にできる）。移動ツールの予告には「平らに保つため面を N 枚に分けます」と出る。
- 以前の方針（「面が増える」ことを理由に断る）は [15_reshape.md](15_reshape.md) と [16_review_2026-10-23.md](16_review_2026-10-23.md) で更新した。期待値が変わる古いテスト（角を 1 つ上げると断る、など）は `autofold=false` を付けて「断る」ことを確かめる形にし、オンの場合の期待値を別に足した。

**テスト**：
- `Roof.RidgeOfASplitTopMakesAGable`（受入課題）
- `Roof.SharedEdgeOfSplitFacesFollows`：単独の矩形を分けて中央の線を上げると、両方が上がる。角が触れているだけの面は動かない。Undo
- `Roof.AutofoldOneCornerUp`：上面だけが 2 枚になる、素材が両方に残る、保存・再読込、Undo
- `Roof.AutofoldOnlyWhereNeeded`：斜めに動かすと、側面も折れる
- `Roof.AutofoldRefusesHolesAndConcaveFaces`
- `Reshape.*`：`autofold=false` で以前の拒否を確認
- `gui_phase1: moveToolLiftsRidgeIntoGable`（GUI で棟を Alt でつかんで青軸ロックで 1500）、`moveToolReshapesCornersAndEdges`（角 1 つで Autofold）

**実機で確認していないこと・残り**：
- SketchUp の Autofold が対角線をどう選ぶか（ここでは、動かない角の側を残す分け方にした）。どういう条件で自動的に折れて、どういうときに Alt が必要か。どちらも実機で比べる。
- 移動ツールの予告に出るのは本体だけで、追従する隣の面はまだ予告に出ない。
- 面を 1 枚だけ選んで移動したときに Push/Pull になる動作（MOV-01）は変えていない。任意の方向に面を動かすのは、これまでどおり Alt でつかむ経路になる。
- 穴のある面・凹んだ面の Autofold は次の段階。

## 追加：ボリュームに線を引いて閉じたところを面にする（2026-10-23 の要望）

**要望**：グループ化されていないボリュームに線を引いて、その辺と一緒に領域が閉じたら、そこに面を作りたい。例：L 字の側面に、背の高い部分の上端から段の角まで線を引くと、切り欠きのところに三角形の面ができる。

**修正**：交差する線から面を作る既存の処理（`facesFromCrossings` / `closesByCrossing`）を広げた。
- 同じグループの中にある、表示中のソリッドと Shell を対象にする（グループやコンポーネントの中身は対象外）。
- 線を含む平面にあるソリッドの直線の辺も、交差の計算に入れる。
- そのうちすでにソリッドの面になっている領域は、面を作り直さない。新しく閉じた領域だけを面にする。
- 処理を軽くするために、次のものは最初に除外する：
  - 線の範囲と外接箱が重ならないソリッド
  - 線を含まない面の平面
- ソリッドの辺は面の境界として使うだけで、変更しない。
- 新しい面の縁になった線の部分は、その面の辺になる（線としては残らない）。

**テスト**：
- `LinesOnSolids.*`（3 件）
  - 切り欠きを閉じる線 → 三角形の面が 1 枚できる。線は残らない、体積は変わらない、Undo は 1 回
  - 写真の線（既存の面を横切る）→ 新しく閉じた部分だけが面になる
  - グループの中のボリュームには作用しない
- `gui_phase1: lineAgainstVolumeMakesFace`

**残り**：既存の面を横切る部分の線は、まだ面を分割しない（線として残る）。面の辺から辺まで引いた線で面を分ける処理は、これまでどおり。

## 追加：選択削除の不具合 2 件（2026-10-23）

**原因（コードで確認したこと）**：`MainWindow::deleteSelection` は、選択の中身によって次の 3 つの経路に分かれていて、規則がそろっていなかった。
- 辺だけを選んでいて、所有オブジェクトが 1 つのソリッドか面のとき → `eraseEdge`
- 面を含むとき → `deleteFaces`
- それ以外 → オブジェクトごと `remove`

この分かれ方で、次の問題が起きていた。
- `eraseEdge` は「面を分けている線」を消すための処理なので、面の外周の辺やソリッドの角の辺は「角なので消せません」と断っていた（不具合 2 の原因の 1 つ）。
- 線オブジェクトは、辺を 1 本だけ選んでいてもオブジェクト全体を消していた（ポリラインの一部を選んでも、全体が消える）。
- 不具合 1（立方体全体が消える）は、コアの `deleteFaces` だけを動かしても再現しなかった。選択内容が経路ごとに違う扱いを受けていたことが原因として考えられるが、どの経路で起きたかは**ユーザーの選択操作を再現しきれていない**。経路そのものを 1 つにまとめた。

**修正**：`Modeler::deleteSelection(targets)` に一本化した。GUI の Delete と API の `delete`（`ids` と `elements`）は、どちらもここを通る。
1. 最初に、すべての対象を所有オブジェクトごとに整理する：「オブジェクト全体」「選んだ面」「選んだ辺」。面は内部の点と法線、辺は両端と中点、という形の情報として記録する。
2. 処理するときは、対象を毎回この形の情報から探し直す。そのため、途中の変更で ID や番号が変わっても取り違えない。
3. 規則：
   - オブジェクト全体 → 削除
   - 線の辺 → その辺だけを消す（残りは線のまま）
   - 同じ平面の面を分ける線 → 消して面をつなげる。つなげられない場合は、両側の面を消してしまわないように、理由を出して断る
   - それ以外の辺 → その辺を使っている面を消す（使われなくなった辺は線として残る）
   - 面 → 消す（辺は線として残る）
4. 全体で Undo は 1 回。どこかで失敗したら全部元に戻し、理由を表示する（「削除できませんでした: …」）。

**上面が消える 2 つの場合の区別**：
- 下の 5 面と、関係のない線を選んだ場合 → 上面は残る
- 上面の辺も選んでいた場合 → その辺がないと上面が成り立たないので、上面も消える

**テスト**：
- `DeleteSelection.*`（5 件）
  - 5 面＋関係のない線 2 本：上面と選ばなかった線は残る。立方体の残りの 8 辺は線として残る
  - 上面の辺も選んだ場合
  - 線の各ケース：単独の線、ポリラインの 1 辺、面の外周の辺、面を分けている線
  - 全部成功するか、何も変えないか（ロック中のものが含まれる場合）
  - API
- `gui_phase1: deleteMixedSelection`（ウィンドウ上の選択、Delete、単独の線をクリックして削除）

**確認していないこと**：テスト環境では、ビューポートをクリックしてフォーカスを移すまで Delete キーが届かないことがあった（ウィンドウが前面に出ていない、というテスト環境の事情と見ている）。実機でパネルなどにフォーカスがある状態で Delete が効かない場合は、別に調べる。

## 追加：開いた形状の面を Push/Pull して体積を作る（PP-04、2026-10-23）

> 2026-10-24 変更：この動きは Ctrl（開始面を残す）を押したときだけになった。既定の動きは「辺の共有（第 1 段）と SketchUp 式の Push/Pull」の節を参照。

**以前**：`Modeler::pushPull` は Shell（面を消して開いた形状）を一律に断っていて、「穴をふさいでソリッドに戻してください」と求めていた。

**修正**：開いた形状を「造形の途中」として扱い、操作が幾何的に成り立つかどうかで判断するようにした。既存ソリッドへの足し引き（Boolean・押出の編集）とは別の処理（`Modeler::volumeFromOpenFace`）にした。

## 追加：同じ位置に重なる線・面を二重にしない（OV-01、2026-10-23）

**以前**：同じ場所に同じ四角を 2 回描くと、面が二重に重なっていた。線を既存の線の上に描いた場合も同じ。重複を抑える処理は、`copyEdges` の「完全に一致する直線は作らない」だけだった。

**修正**：共通の処理 `Modeler::settleOverlaps(ids)` を 1 つ作り、次の操作から同じように呼ぶ。
- 作図：矩形・円・多角形・面（`addProfile`）、線・円弧（線ツールと API `create_line`）
- 移動・回転（`transform`）
- コピー・配列（`copy`、`copyEdges`）
- 貼り付け（`paste`）
- オフセット（`offset`）

整理は呼び出した操作の Undo の 1 段の中で行う。GUI も API も同じ関数を通る。

**対象**：今回作った・動かしたオブジェクトと、その近く（バウンディングボックスが重なるもの）だけ。比べるのは**同じ編集コンテキスト**（同じ親）の中で、3D 形状と幾何許容差（`kMinDimension` = 0.001 mm）で判断する。画面上の重なりでは判断しない。

**線**：
- 既存の辺（線、面の辺、ソリッドの辺）の上に乗る区間は作らない。完全に重なれば、線そのものを作らない。
- 一部だけ重なる場合は、新しい区間だけを残す。接続点はそのまま残る。
- 新しい線が既存の単独の線の途中で終わる場合は、その線をそこで分ける（接続点を作る）。
- 円弧などの曲線は、完全に一致する場合だけ重複とみなす。

**面**（同じ平面上の、平らな単独の面どうし。表裏が逆でも対象）：
- 重なる部分は 1 枚だけにする。規則は**既存側を優先**：重なった部分は既存の面が持ち、その材質・タグ・属性・表裏を引き継ぐ。
- 既存の面は新しい面の輪郭で分割する。新しい面は既存と重ならない部分だけが残る。分かれた領域は、それぞれ別の面になるので、選択・材質変更・Push/Pull が個別にできる。
- 外周だけでなく内周（穴）も含めて比べる。穴のある面の穴は失われず、新しい面が穴の上に来れば、その円の部分が新しい面になる。
- まったく同じ面を描いた場合は、何も増えない。戻り値は既存の面の ID になる（API も同じ）。

**しないこと**：
- 別のグループ、別のコンポーネント、ソリッド部材とは統合しない。ソリッドの面の上に面を描いても、ソリッドはそのまま。
- 接しているだけの 2 つのソリッドは結合しない（部材の Boolean 結合は別の操作）。
- 高さが少し違う面を同じ平面に寄せることはしない。
- 表示位置をずらしてちらつきを隠すことはしない。
- 既存モデル全体の自動清掃はしない（別の機能として扱う）。

**あわせて直した不具合**：
- **再入力で一つ前の操作が取り消されていた**（「/3」で箱が面に戻る、選択が効かなくなる）。
  - 原因：線を既存の辺の上にコピーすると、何も作られないので Undo の段も増えない。それでも続けて打った「/3」の再入力が Undo を 1 回実行し、一つ前の操作（箱のプッシュ/プル）を取り消していた。
  - 修正：`RecentEdit` が「この編集は段を作らなかった」ことを覚え、その場合は Undo せずにやり直すようにした（`begin` / `mark`）。
- **閉じた外周をコピーしたときに面ができなかった**。面の外周の辺をコピーして閉じた平らな輪になったときは、描いたときと同じように面にする。
- **往復した線から面積ゼロの面ができていた**。同じ線を逆向きに描き直すと、往復を「閉じた輪」とみなして、つぶれた面ができていた。面積のない輪は輪とみなさない。

**テストの変更**（新しい規則に合わせて）：
- `Modeler.ObjectIdsAreUniqueAndNamesIncrement`：2 つ目の四角を別の位置に描くようにした。
- `Freeform.LoftIsParametricAndSaved`：上の断面を、土台の外に描いてから移動するようにした。
- `Gate3.F05`：角が重なる四角は、床を分割することを確かめるようにした。

**新しいテスト**：
- `Overlaps.*`（8 件）：確認例 1〜6、線の各ケース、コピーと移動、外周のコピー
- `gui_phase1: copyOntoEdgeThenDivideKeepsSolid`：報告された操作の再現

**まだのこと・制約**：
- **共有境界の扱い**：隣接する別々の面オブジェクトは、それぞれ自分の辺を持つ（位相としての共有はしない）。
- **分割後の面**：分割された面は、決まった形の領域（`ImportedShape`）になるので、矩形の幅のような元のパラメータは編集できなくなる。
- **完全に内側の面は従来どおり**：既存の面の完全に内側に描いた面は、今までどおり「既存側に穴を開け、新しい面は自分の材質のまま」になる（`punchHole`）。この場合は既存優先の規則の例外。
- **計算量**：たくさんの面を一度に動かすと、近くの面との比較が増える。大きなモデルでの速度はまだ測っていない。

## 追加：面を横断する線は、はみ出していても、何枚またいでも面を分割する（SP-01、2026-10-23）

**報告**：グループの中で、縦に 3 つに分かれた壁の面に横線を描いたりコピーしたりしても、面が分割されなかった。縦長の面全体が選ばれてしまっていた。

**再現と原因**（`SplitAcross.*`、`lineAcrossStripsInAGroupDividesEach`）：
- 線は面の上にあった（同じ平面・同じグループ。ロックや非表示もなし）。面の B-rep そのものが分割されていなかった（選択表示の問題ではない）。
- `Modeler::splitWithLine` は「線のすべての点が 1 枚の面の上にあり、両端がその面の境界にある」場合だけ分割する。そのため、次の 2 つはどの面の候補にもならず、ただの線として置かれていた：
  - **A**：面より長い線（両端が面の外）
  - **C**：縦に分かれた複数の面を 1 本でまたぐ線
- 報告の場面は C に当たる。線ツールでも、コピー配列でも同じ。

**修正**（`Modeler::splitAcross`）：
- **区間の求め方**：線を直線の区間ごとに、同じグループ内の平らな面と照らし合わせる。対象は、面の平面上にあるもの（距離 0.001 mm 以内）。面の中に入る区間は、`BRepAlgoAPI_Common` で求める。
- **分割に使う区間**：面の端から端まで横断する区間だけ（両端が境界上にあり、中点が境界上にないもの）。その区間で面を分割する。
  - 1 本の線で、横に並んだ複数の面をそれぞれ分割する。
  - 既存の縦の分割線との交点は、実際の頂点になる（ソリッドとして正しいことも確認）。
- **使わなかった部分**：面の外にはみ出した部分などは、線として残る。
- **分割しないもの**：
  - 面の途中で止まる区間（延長しない）
  - 平面から少し浮いた線
  - 面を斜めに貫くだけの線
  - 別のグループの面
- **穴のある面**：穴の両側の区間は、1 本ずつでは面を分けられない。同じ面に属するときだけ、まとめて 1 本として分割する。穴は埋めない。
- **使われる場面**：重なりの整理（`settleOverlaps`）から呼ぶので、次のどれでも同じように分割される。
  - 作図（線ツール、API `create_line`）
  - コピー・配列
  - 移動
  - 貼り付け
  - 線を先に描いて、後から面を描いた場合（面の側から線を探す）
- **API**：`split_face` も同じ処理を使う。戻り値は、分割した面の数。
- **Undo**：1 操作で 1 回。保存・再読込でも分割したままになる。

**あわせて直した不具合**：
- 入れ子の Undo グループの内側で `abortGroup` を呼ぶと、外側の操作まで巻き戻していた。何もしなかったときは、巻き戻さずにグループを閉じるようにした。
- ばらの面を線で分割するときにも、穴をまたぐ線に対応する予備の分割（`splitPlanarFaceExtended`）を使うようにした。再生成するときと同じ処理。

**テストの変更**：`Gate1.AC09` は、外側に置いた線の上に矩形を描いていた。新しい規則では、その矩形はその線で分割される。このテストで確かめたいのは「グループ内の線は外の面を分割しない」ことなので、矩形を線から離れた位置に描くようにした。

**まだのこと**：
- ソリッドの穴あき面を、穴の両側でまたぐ分割は確かめていない（ばらの面では確認済み）。
- 曲線（円弧など）による横断の分割は、これまでどおり 1 枚の面の中で閉じる場合だけ。

## 追加：矩形を縦の面にも描く（RECT-UP、2026-10-23）

**変えたこと**（`RectangleTool`）：
- **点に向かって立てる**：最初の角から見て上下にずれたモデルの点（端点、中点、エッジ上、原点、交点、追跡した点からの軸線）にカーソルを合わせると、角とその点を通る縦の軸平面（赤 X か緑 Y に直交）に矩形を立てる。

**テスト**：`GuiPhase1::rectangleStandsUpLikeSketchUp`。地面から箱の上の角へ向かうと立つこと、モデルの点がなければ地面のままなこと、→ で X 向きの壁になり寸法入力が効くこと、↑ → ↓ のあとは地面に戻ることを確かめる。

## 追加：範囲選択で面・辺を 1 つずつ選ぶ（UX-04 実機報告、2026-10-24）

**問題**：
- 面 1 枚とその 4 辺を範囲で囲んでも、その要素だけを選べなかった。
- 線だけを囲んでも、線だけを選べなかった。

**原因**：範囲選択（`SelectTool::boxSelect`）は、オブジェクトの外接直方体を画面に投影して判定していた。そのため、形状の面・辺を 1 つずつ判定する処理がなかった。

**変えたこと**：
- **生の形状（線・面・開いた形状・ソリッド）**は、面と辺を 1 つずつ判定する。判定には、辺に沿って取った点の画面上の位置を使う。
  - 左→右（ウィンドウ）：辺上の点がすべて枠の中にある要素を選ぶ。
  - 右→左（クロス）：枠の中にある要素、または枠と交差する要素を選ぶ。
  - 枠が面の内側だけにある場合（辺に触れない場合）：
    - 通常表示では、枠の中心で手前に見えている面だけを選ぶ。
    - X 線表示では、その位置に重なる面をすべて選ぶ。
  - 輪郭が枠に入る要素・触れる要素は、手前の面に隠れていても選ぶ（通常表示・X 線とも）。
  - 非表示にした辺（スムーズ・非表示）は選ばない。
- **グループ・コンポーネント・ロック中のオブジェクト**は、今の編集階層で 1 単位として扱う（従来どおり外接直方体で判定）。
- **選択集合**：面だけ、辺だけ、面と辺の混在、グループとの混在を、そのまま保持する（`setMixedSelection`）。
  - 一部の面・辺だけを選んだときは、その要素だけが対象になる（`selectionTargets` が whole にならない）。
  - すべての面と辺を選んだときだけ、オブジェクト全体とみなす（従来どおり）。
  - Shift を押しながら範囲選択すると、今の選択に加える。
- **面や辺の上からドラッグを始めた場合**も範囲選択になる。動かさずに離せば、従来どおりクリックで選ぶ。

**テスト**：`GuiPhase1::boxSelectionTakesFacesAndEdges`
- 正面の面と 4 辺をウィンドウで囲む。
- 線だけを囲む。
- 上面の内側でクロス選択する（通常表示 → 上面だけ、X 線 → 奥の面も）。
- 箱全体を囲む → 面 6・辺 12 で全体扱い。
- グループを 1 単位として選ぶ。
- Shift で、グループと面・辺を混在させる。

既存の `boxSelectionWindowAndCrossing` は期待値を変えた。箱の半分を囲むウィンドウは、従来は「何も選ばない」だった。新しい規則では「枠に完全に入る面・辺だけを選ぶ」になる。

**SketchUp の実機で未確認**：
- 隠れた要素（手前の面の奥）を範囲選択で選ぶかどうか。
- 面の上からのドラッグが範囲選択になるか。

## 追加：別々に描いた面が囲む立体を、閉じたソリッドにする（2026-10-24）

**切り分け**：6 枚の矩形を辺・頂点を合わせて描くと、文書上は 6 つの独立した `Face` オブジェクトになっていた。
- 面と面の辺・頂点は共有されていなかった。形状がつながっていなかった。
- 分類（種類の表示）だけが古いのではなかった。そもそも面どうしをつなぐ処理がなかった。

**変えたこと**：
- 面を作るたびに、重なりの整理（`settleOverlaps`）の最後に `closeIntoSolid` を呼ぶ。
- **対象**：同じ編集階層にある面と開いた形状（Shell）だけ。辺を共有するもの（端点と中点が 0.0001 mm 以内）をたどって集める。
  - 別のグループ・コンポーネントの面は対象外。
  - 既存のソリッドとは自動で結合しない。
- **ソリッドにする条件**（`geom::sewIntoSolid`）。どれか 1 つでも満たさなければ、面は面のまま残す。
  - すべての辺の両側に面がある（隙間がない）。
  - 3 枚以上の面が同じ辺を共有していない。
  - 全体が 1 つにつながっている。
  - 面どうしが交差していない。
  - 体積がある。
  - 形状チェックを通る。
  - 枚数だけでは判定しない。
  - 許容誤差は 0.0001 mm。意図した隙間（0.5 mm など）は閉じない。
- **結果**：新しいソリッド 1 つ（`SewnFeature`）になる。
  - 各面の元のレシピを保持するので、保存・再読込しても再生成できる。
  - 面の材質は、ソリッドの対応する面に引き継ぐ（面の表裏は問わない）。
  - 押し出しで作った箱と同じように、面・辺を 1 つずつ選べて、Push/Pull もできる。
- **面を削除したとき**：従来どおり開いた形状（Shell）に戻り、残りの面・辺は保たれる。開いた穴をまた面で塞げば、同じ処理でソリッドに戻る。
- **Undo**：最後の面を描く操作と結合は、まとめて 1 回で戻る。
- **速さ**：辺を中点の格子で探す。共有相手のない辺が 1 本でもあれば、縫い合わせ（sewing）は試さない。床タイルのように面が多く並んでいても重くならないように。

**テスト**（`ClosingFaces.*`）：
- 1000 mm 角の 6 面が体積 1,000,000,000 mm³ の妥当なソリッドになる。描く順序を 3 通り変えて確かめる。
- Undo/Redo、保存・再読込、上面だけの Push/Pull。
- ソリッドにならない場合：5 面、0.5 mm の隙間、1 辺に 3 枚目の面（ひれ）、最後の 1 面を別グループに描いた場合。
- 面を 1 枚削除すると Shell に戻り、描き直すと再びソリッドになる。
- 塗った面の材質が引き継がれる。

既存の GUI テスト `cutCopyAndMoveCopyTakeOnlyPickedElements` は期待値を変えた。上面を切り取って同じ位置に貼り付けると、従来は「ばらの面 1 枚」だった。今は「箱がまた閉じてソリッドになる」。

**制限**：
- 辺でつながった面の集まりの中に、閉じた部分と余分な面（ひれ以外の、外へ伸びる床面など）が混ざっていると、全体として閉じていないためソリッドにしない。閉じた部分だけを取り出す処理はまだない。
- 開いている途中で、面どうしの辺を共有させて 1 つの開いた形状にまとめる処理はしていない。各面は閉じるまで独立した面のまま。

**SketchUp の実機で未確認**：
- SketchUp では途中でも辺が共有されている（エンティティの構造が違う）。ここでは閉じたときにまとめる。

## 追加：辺の共有（第 1 段）と、開いた形状の SketchUp 式 Push/Pull（2026-10-24）

**以前**：別々に描いた面は、閉じるまでそれぞれ独立した面のままで、辺を共有していなかった。SketchUp では、閉じる前から辺を共有する。

**第 1 段で変えたこと**：
- **角度をもって接する面は、描いた時点で辺を共有する**。同じ編集階層にある面・開いた形状のうち、辺（端点と中点が 0.0001 mm 以内）を共有し、平面が違うもの（壁と床、箱の側面どうし）は、1 つの開いた形状（Shell、`SewnFeature`）に縫い合わせる。
  - 共有された頂点・辺を移動ツールで動かすと、両側の面がついてくる。
  - 最後の面で閉じれば、これまでどおりソリッドになる。
  - 既に縫い合わせた面にさらに面が加わるときは、入れ子にせず、元の面のレシピを並べ直す。再生成は 1 回の縫い合わせで済む。
  - 面の材質は、全部の面が同じときだけオブジェクト全体の材質にする。違うときは面ごとに保つ。
- **同じ平面で隣り合う面（床のタイルなど）は、まだつながない**（第 2 段）。地面の矩形を Push/Pull して箱にする今の使い方は変わらない。
- **開いた形状の Push/Pull を SketchUp の面と同じ動きにした**（既定）。
  - 押した面が法線方向に動き、各辺に元の位置へ戻る側面ができる。
  - 側面が、その辺の向こうの面と同じ平面に来るときは、側面を重ねない。代わりに次のようにする。
    - 向こうの面から離れる方へ引いたとき → その面を伸ばす（床が広がる）。
    - 向こうの面に沿って押し込んだとき → その面を新しい辺の位置で分ける（床を押し上げると、壁が床の高さで分かれる）。
  - 結果は同じオブジェクトのまま。閉じればソリッドになる。距離は後から打ち直せる（`PushPullOp`）。
  - 曲面は理由を出して断る。
- **Ctrl で開始面を残す**（SketchUp の「新しい開始面を作成」）。
  - 開いた形状では、従来の PP-04 と同じく、その面から別の体積（ソリッド）を作る。壁に厚みを付ける操作がこれ。
  - Push/Pull ツールで Ctrl を押すと切り替わる。状態はステータスに出る。
  - API では `push_pull` に `keep_start_face` を付ける。
- **仕様との関係**：108 項目の PULL-05 と SC07 にある「開いた形状から体積を作る」は、Ctrl ありの操作として確かめ直した（`Flows.SC07_*` は `keepStartFace` で厚み 200 を付ける）。

**処理の重さ**：
- 描くたびに同じ階層の面を全部読むのではない。たどり着いた面と、外接箱が接する面の辺だけを読む。
- 閉じているかの確認は、相手のない辺が見つかった時点でやめる。
- `ClosingFaces.Bench`（`SBR_BENCH_N=20`）で測った結果（手元）：

| 場合 | 共有処理なし | 共有処理あり |
|---|---|---|
| 床のタイル 400 枚（同じ平面、つながない） | 1 枚 3.83 ms | 1 枚 4.19 ms |
| 箱 20 個を 1 面ずつ（角度でつながる） | 1 面 2.50 ms | 1 面 6.32 ms |

**テスト**：
- `ClosingFaces.AngledFacesShareTheirEdgeWhileOpen`：2 面で辺が 7 本になる。共有した角を動かすと 2 面がついてくる。Undo は 1 面ずつ戻る。同じ平面の隣どうしは別の面のまま。
- `ClosingFaces.OpenBoxPulledThenClosed`：上面のない箱の側面を引き出すと、形状が広がる。最後に上面を描くと、体積 1.5×10⁹ mm³ のソリッドになる。
- `OpenPushPull.*`：
  - 側面を引く：床と隣の面が伸び、上に細長い面ができる。Undo・打ち直し・保存も確かめる。
  - 床を押し上げる：4 つの壁が床の高さで分かれる。
  - 穴あき面を引く。
  - 曲面は断る。
  - Ctrl で厚み（体積）を作る。
  - API（`keep_start_face` も）。
- `GuiPhase1::pushPullOnOpenShape`：既定の動きと、Ctrl の両方を確かめる。

**制限**：
- 大きな開いた形状（数百面）に面を足すと、そのたびに形状全体を縫い直す。時間は面の数に比例して増える。
- Push/Pull で側面が向こうの面に沿うときの「伸ばす」「分ける」の処理は、平らな面で、分ける場合は直線の辺だけ。それ以外は側面をそのまま追加する。
- ソリッドの面での Ctrl（開始面を残す）は、まだない。

**SketchUp の実機で未確認**：
- 側面が隣の面と同じ平面に来るときに、面が伸びるか・分かれるかの細かい規則。
- 開いた形状で Push/Pull をしたときの、面の表裏の扱い。

| 1. 経路の辺選択が所有オブジェクト全体になっていないか | 問題なし。3 本とも辺のまま選ばれる |
| 2. ツール切替で事前選択が失われないか | 問題なし。「選んだ 3 本の辺に沿わせます」と出る |
| 3. 断面クリックが面として認識されるか | 問題なし |
| 4. 別々に描いた辺を一続きの経路に組み立てられるか | 問題なし（`pathFromEdges`。選んだ順に依存しない） |
| 5. 経路の始端・向きと断面の位置関係 | 始端は断面に近い方の端。断面は動かさない |
| 6. GUI から形状計算へ意図した断面・経路が渡っているか | **ここが原因 1** |
| 7. 計算後の登録・描画 | 原因 1 を直した後は問題なし。ただし形が間違っていた（**原因 2**） |

**原因 1（GUI → 計算）**：
- ツールは、断面の ID を、文書内のオブジェクトへの参照（`o->id`）のまま `Modeler::followMe` に渡していた。
- スイープの途中で結果のオブジェクトが文書に加わると、文書の格納領域が移動し、この参照は解放済みのメモリを指す。
- そのあと断面を消すときに壊れた ID を読み、`std::bad_alloc` で失敗していた。画面には「形の計算でエラーが起きた」と出て、何もできなかった。
- 計算だけの自動テストは、ID のコピーを渡していたので通っていた。
- 直し方：ツール側でも `followMeAlong` 側でも、ID をコピーしてから使う。ほかのツールにも同じ書き方がないか確認した（なかった）。

**原因 2（計算）**：
- 曲がり角のある折れ線では `BRepOffsetAPI_MakePipe` がエラーを出さずに成功する。ところが断面を回転させずに平行移動するだけなので、角ではせん断された形になり、体積も違っていた。
  - 例：2 区間の経路で、正しくは 1.906 × 10¹⁰ mm³ のところが 1.35 × 10¹⁰ mm³ になっていた。
- 角の処理（`mitredSweep`）は「パイプが失敗したとき」の予備でしかなかったので、使われていなかった。
- 直し方：経路に角（接線が折れる点）があれば、最初から角を突き合わせるスイープにする。断面は角ごとに向きを変え、前後の形をつなぐので、内部に面は残らない。

**失敗時の表示**（いずれもモデルは変えず、Undo 履歴にも残らない）：
- 分岐：場所を示す（既存）。
- 途切れ：経路が切れている場所を示すようにした。
- 自己交差（断面の大きさより狭い範囲で折り返す経路など）：交差の判定を加え、いちばん鋭い角の位置を示す。

**確認の区分**：
- **計算テスト済み**（`FollowMe.*`）：
  - 直線 1 本、曲がり角 1 か所、曲がり角 2 か所（報告の 3 区間）。それぞれ 1 本の折れ線と、区間ごとに別の線の両方。選ぶ順は逆順にした。
  - 体積が「断面積 × 経路長」と一致する。
  - 面の数が「区間数 × 4 + 2」で、内部に面が残らない。
  - 断面の位置が始端の面として残る（断面を動かしていない）。
  - Undo 1 回で元に戻る。Redo、保存・再読込でも形が保たれる。
  - API（`follow_me` の `path_edges`）の結果と一致する。
  - 円弧を含む経路、中空断面（200 の枠）。
  - 分岐・途切れ・自己交差は、理由と場所を示し、何も変えない。
- **GUI 自動確認済み**（`GuiPhase1::followMeReportedSetup`）：
  - 実際のクリックで経路 3 本を Shift で選び、ツール切替、Esc で何も変わらないこと、断面のクリック、を順にたどる。
  - 体積、API との一致、Undo/Redo、保存・再読込を確かめる。
  - 途切れた経路では、場所つきのエラーを表示し、何も変えない。
- **Windows 実機確認済み**：まだ。

**操作 B（面から経路をなぞる）について**（2026-10-24 追記：実装した。下の「操作 B」の節を参照）：この時点では、計算機能はあるが、手動で経路をなぞる操作は未実装だった。
- 今できること：断面をクリックしたあと、線オブジェクト 1 つ（その線の辺すべて）か、ソリッドの面（その輪郭を一周）をクリックすると、それに沿わせる。
- まだできないこと：
  - カーソルでつながった辺をたどって、採用中の経路を強調する。
  - 途中までの形をプレビューする。
  - 終点で確定する。
- 区間ごとに別々に描いた線を使うときは、今は操作 A（辺を先に選ぶ）を使う。

## 追加：Follow Me の操作 B（面から経路をなぞる、2026-10-24）

**操作**：
1. 経路を選ばずに Follow Me を起動し、断面の面をクリックする。
2. 断面につながる辺の上をカーソルでなぞる。
   - 断面にいちばん近い点から、カーソルの下の辺の先の端まで、つながった辺の最短の道を経路にする。
   - 経路の辺は強調表示し、できる形をプレビューする。カーソルを手前の辺に戻すと、経路も短くなる。
3. 終点でクリックすると確定する。Esc で中止する（何も変わらない）。
- 経路の候補は、今の編集階層にある線・面・開いた形状・ソリッドの辺。断面自身の辺は入れない。
- 線は区間ごとに別々に描いたものでもよい（端点が 0.0001 mm 以内でつながっていれば一続き）。
- プレビューと確定は、操作 A と同じ計算（`geom::pathFromEdges` と `geom::sweep`）を使う。作れない経路はプレビューの代わりに理由を表示し、クリックしても確定しない。
- なぞらずにソリッドの面をクリックすると、従来どおりその輪郭を一周する。断面とつながらない線をクリックすると、その線全体に沿わせる。

**テスト**：`GuiPhase1::followMeTracedFromTheProfile`
- 区間ごとの 3 本の線をなぞると、1 → 2 → 3 本と伸び、毎回プレビューが出る。戻ると短くなる。
- Esc で中止すると、文書と Undo 件数が変わらない。
- もう一度なぞってクリックすると、体積が「断面積 × 経路長」と一致し、プレビューの体積とも一致する。Undo 1 回で元に戻る。

**SketchUp の実機で未確認**：
- 経路の選び方。SketchUp は面の辺に沿った自動追従もするが、ここでは「断面から最短のつながり」とした。
- 断面と離れた経路の扱い。

## 追加：選んだ面を横へも動かす（MOVE-05 / LIM-01、2026-10-24）

**以前**：面を 1 枚だけ選んで移動すると、法線方向にしか動かなかった（Push/Pull と同じ伸縮）。横へずらして斜めの形にすることはできなかった。

**変えたこと**：
- 既定は今までどおり。法線方向に固定され、ソリッドを伸縮する。
- ↓ で固定を外すか、→ ← ↑ で別の軸に固定すると、横へも動かせる。
  - 動かす向きが法線と平行でなければ、その面の角をまとめて動かす（`moveVertices`、角・辺の移動と同じ処理）。
  - まわりの面はついてくる。平らを保てない面は折って分ける（Autofold）。
  - プレビューは確定と同じ計算を使う。動かせない位置では理由を表示する。
- 数値入力：横へ動かすときは、カーソルが示す向きに入力した距離だけ動かす。法線方向のときは従来どおり。
- Ctrl でのコピーは従来どおり（面のコピー）。

**テスト**：`GuiPhase1::move05FaceMovesSideways`
- 上面を ↓ で横へずらす：体積は 1 × 10⁹ mm³ のまま、妥当なソリッド。
- 正面を → で X 方向へずらす。
- 既定（法線方向）は伸縮のまま。
- それぞれ Undo 1 回で戻る。

**SketchUp の実機で未確認**：
- SketchUp は面の移動を最初から自由な方向で行う。ここでは誤操作を避けるため、既定を法線方向の固定にした。

## 追加：伸縮した部品配置を、固有化・編集・分解できるようにする（LIM-02、2026-10-24）

**以前**：配置だけを伸縮すると、その配置からの編集・分解は断っていた。固有化しても伸縮は配置に残るので、やはり編集できなかった。

**変えたこと**：
- **固有化（右クリック >「この配置だけ独立」）**：その配置の伸縮を、新しい専用の定義へ焼き込む。
  - 定義の各部材のレシピの最後に、伸縮（`StretchOp`、部材自身の座標に変換したもの）を足す。パラメトリックなまま。
  - 配置は伸縮なしに戻り、見た目は同じ。共有の定義と、ほかの配置は変わらない。
  - そのあとは普通の配置と同じく、ダブルクリックで編集でき（反映はこの配置だけ）、分解もできる。
  - その部品の配置が 1 つだけで伸縮しているときは、その定義そのものに焼き込む（伸縮していなければ従来どおり「固有化の必要なし」）。
- **分解**：伸縮した配置を分解すると、伸縮した部材が出てくる（同じく焼き込み）。
- **編集**：伸縮した配置をダブルクリックしたときは、従来どおり断る。メッセージで、ほかの配置から共有の定義を編集するか、固有化してから編集するかを案内する。
- **まだ断るもの**（理由を表示）：
  - 鏡像で、しかも伸縮した配置。
  - 中にコンポーネントを含む定義の伸縮配置。
- 共有の定義全体の寸法は、この操作では変えない。

**テスト**：`Stretch.StretchedPlacementMadeUniqueEditedAndExploded`
- 2 つある配置の片方を伸縮して固有化する：見た目が同じ、伸縮なしの配置、別の定義になる。
- 固有化したあと編集できる。高さを変えても、もう一方の配置は変わらない。
- 保存・再読込しても保たれる。Undo で共有の定義と伸縮に戻る。
- 伸縮したまま分解すると、同じ範囲に伸縮したソリッドが出る。
- 配置が 1 つだけのときは、その定義に焼き込んで編集できる。

## 追加：回転矩形ツール（W8、2026-10-24）

**操作**（Shift+R、ツールバー「回転矩形」）：
1. 最初の角をクリックする。
2. 1 辺目の終わりをクリックする（向きは自由。数値を入力すると、その長さで確定）。
3. もう一方の辺の向きをクリックする（数値を入力すると、その長さで確定）。
- 3 つめの点は、モデルの点（端点・中点・辺上・交点など）に吸着すると、その点を通る傾いた面になる。そうでなければ開始面（地面か、最初にクリックした面）の上になる。1 辺目が開始面から出ていれば、それを通る縦の面になる。
- 結果は矩形ツールと同じ矩形プロファイル（幅・高さはあとから変えられる）。向きだけが自由。
- Esc で 1 クリックずつ戻る。

**テスト**：`GuiPhase1::rotatedRectangleTool`
- 地面で 45° 回した 2000 × 500 を数値で作る。
- 箱の角 3 点に吸着して、45° 傾いた 1000 × 1414 を作る。
- Esc で 1 段戻る。

**SketchUp の実機で未確認**：SketchUp は 3 点目を分度器のように回して角度を指定できる（角度の数値入力も）。ここでは点への吸着と長さの入力だけ。

## 追加：線や円弧の端から、なめらかにつながる円弧（接線、W8、2026-10-24）

- 円弧ツールの始点が、線や円弧 1 本の端点に吸着したとき、その線が来た向きを覚える。
- 膨らみを決める段階で、その向きになめらかにつながる膨らみ（接線になる膨らみ）の近く（弦の半分の 5% 以内）に来ると、そこに吸着して「接線」と表示する。
  - 膨らみ = 弦の半分 × tan(θ/2)。θ は、来た向きと弦のなす角。
- 端点に辺が 2 本以上集まっているときは、どの向きか決められないので吸着しない。

**あわせて直した不具合**：円弧の終点を決めるとき、地面上の始点から上方向（青軸）の推論に吸着すると、終点が作図面から外れていた。そのまま膨らみの段階へ進むと、計算エラーになっていた（`gp_Vec::Normalized() - vector has zero norm`）。終点は作図面上のカーソル位置にするようにした（膨らみの段階と同じ扱い）。

**テスト**：`GuiPhase1::arcCarriesOnTangent`
- 線の端から円弧を描き、接線の近くで「接線」と表示されることを確かめる。
- できた円弧の始点での向きが、線の向きと一致することを確かめる。

**SketchUp の実機で未確認**：吸着する範囲（ここでは弦の半分の 5%）。SketchUp は接線の円弧を水色で示す。

## 追加：インチ・フィートの入力（W8、2026-10-24）

- 長さの入力欄で、mm・cm・m に加えて、インチ（`12"`・`12in`）とフィート（`3'`・`3ft`）、フィートとインチの組み合わせ（`3'6"`・`3' 6"`・`3'6`）を読めるようにした。マイナスも使える（`-3'6"` は全体がマイナス）。

- 拡大縮小ツールでは、`'` や `"` が付いた値を「倍率」ではなく「寸法」として扱う。
- 表示は今までどおり mm。
- テスト：`Units.InchesAndFeet`。
