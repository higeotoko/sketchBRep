# 測量図（DXF）から敷地・地形の B-rep を作る：実験記録と取り扱いの指針（2026-11-06）

オーナーの測量図 DXF 1 枚から、AI が図面を読み取って SketchBRep に敷地・道路・地形の 3D モデルを作る実験をした。
SketchBRep 本体は変えず、既存の MCP だけで作った。ここでは次の 3 つを残す。

- やったことと結果（§1〜3）
- **今後、測量データを扱うときの指針**（§4）
- 足りない機能の候補（§5）

測量図そのもの、座標、標高の表、モデル、画面写真はオーナーの非公開データなので Git に入れない（CLAUDE.md）。
この文書には件数・誤差・考え方だけを書く。

## 1. 入力の性質（よくある測量図の形）

| 項目 | 今回の図面 |
|---|---|
| 形式 | AutoCAD 2013 DXF（AC1027）。文字コードは UTF-8（2007 以降の DXF は UTF-8。`$DWGCODEPAGE` が ANSI_932 でも本文は UTF-8） |
| 図面の単位 | mm。座標は原点から 100 m 前後離れた値（公共座標系の可能性が高い）。全要素が Z=0 |
| 標高 | **文字（TEXT）だけ**。`dd.dd` 形式の m 単位（51〜57 m 台）で、図形の Z には入っていない |
| 画層 | 2 つだけ（「一般」と文字用）。**画層では用途がわからない** |
| 記号 | 境界標＝半径 150 の円と塗りつぶし（HATCH）、標高点＝半径約 76 の小円、マンホール＝円の中に文字「M」、側溝＝「U=240」の注記と約 120 mm 間隔の二重線 |
| 要素数 | LINE 28 / LWPOLYLINE 17 / POLYLINE 17 / CIRCLE 75 / TEXT 67 / HATCH 17 / INSERT 2 |

既存の `import_dxf`（docs/24）は線図だけを取り込み、**文字を取り込まない**。そのため標高はこの経路では失われる。
今回は DXF を自前のスクリプトで読んだ。

## 2. やったこと

### 2.1 解析（スクリプト）

1. **敷地境界**：LINE の端点をつないだグラフから、面積が最大の閉じたループを探す。その全頂点に境界標の円があることを確認した（西区画：12 頂点で閉じている）。東区画は、両端が西区画の頂点に一致し、頂点の大半に境界標がある開いたポリラインと、共有辺とで閉じた。
2. **分類**：全 223 要素を、閉じているか・幅・面積・直交性・敷地の内か外か・平行な二重線の間隔・注記までの距離から分類した。すべてに信頼度（高・中・低）と根拠を付けた。セットバック線か分筆線か、水路か暗渠か、のように決められないものは「候補」のまま残した。
3. **標高の紐付け**：文字の最近傍点をそのまま採用しない。
   - 文字の回転を考えた外接矩形と、記号の中心との距離を測る。
   - 標高点・マンホール・境界標を候補にして、**ハンガリアン法で全体として最適な 1 対 1 の割り当て**を求める。
   - 1.2 m 以内に記号がない文字は「対応なし」とする。
   - 信頼度は、距離と「次に近い候補との距離の比」で決める。
   - 結果：53 文字のうち、標高点 42 と マンホール 9 に対応した（high 37 / medium 14）。**2 文字は対応なし**で、地形には使っていない。
4. **単位**：Z(mm) = 標高文字(m) × 1000。XY は DXF の元座標（mm）をそのまま使い、ローカル原点は作っていない。

### 2.2 地形ソリッドの作り方（既存の MCP だけで、1 つの閉じた B-rep にする）

51 点の Delaunay TIN（三角形網）を作り、凸包の外周にできる細長い三角形 7 個を除いた（裏付けになるデータがないため）。そのあと次の順で作る。

1. TIN の外周を `create_polygon` で底の高さ（TP+50.0 m）に作り、`extrude` で 1,000 mm 押し出す。
2. 上面を `split_face` で 83 回分けて、TIN の三角形 84 枚にする。
   - `split_face` は「面を端から端まで横切る線」でしか分けられない。
   - そこで内部の点は「既にある頂点 → 新しい点 → 既にある頂点」の折れ線で入れる。
   - その順番はスクリプトで決める（両端が既にある辺を先に、次に既にある隣の点を 2 つ以上持つ点、の繰り返し）。
3. 51 個の頂点を `move_vertices` で各標高まで上げる。
   - 三角形は動かしても平らなまま。外周の側面も鉛直の四角形のまま平らなので、自動の折り（autofold）は要らない。

結果は Solid 1 個（上面 84・側面 16・底面 1 の計 101 面、体積 3,329.7 ㎥、履歴 156 手順、すべてパラメトリック）。

ほかに次を作った。

| 作ったもの | 内容 |
|---|---|
| 2D 原図 | 線・円・文字・ブロックを元座標・Z=0 のまま再現（289 個）。比較用 |
| 標高点 | 各点に 800 mm の縦線とラベル |
| 投影した線 | 敷地境界・建物輪郭・塀・側溝などを地形に投影した 3D 線。TIN の辺との交点で区切り、TIN の外は描かない |
| 敷地の面 | Z=0 の敷地の面（面積の確認用） |

### 2.3 自動の検証

| 項目 | 結果 |
|---|---|
| 地形の位相 | 面の数が TIN と完全に一致（上面 84 ＝三角形数、側面 16 ＝外周の辺の数） |
| 地形の形 | 上面 84 面の重心と、TIN の三角形の重心の差：最大 0.004 mm |
| 標高点 | 位置・高さとも DXF との差は最大 0.005 mm |
| 2D 原図 | 137 要素の外接矩形の差は最大 0.005 mm。漏れ 0、文字 67/67 |
| 敷地 | 2 区画とも閉じている。面積は DXF からの計算値と一致 |
| 図面自体の矛盾 | 境界線の端点と境界標の中心が 30.2 mm ずれている頂点が 2 つ。境界標の無い頂点が 1 つ（最も近い境界標まで 730 mm） |
| 地形の異常 | 30° を超える三角形が 25 枚（最大 85°）。南側で 約 1.8 m の間に 約 2.2 m の高低差（擁壁と思われる）。周りの点からの推定と 1.5 m 以上ずれる点が 5 つ |
| データの範囲 | 西区画の西側は標高点が無く、敷地境界の 34% が TIN の外だった |

確認の段階：**計算テスト済み**（上の自動検証）、**GUI 自動確認済み**（MCP 経由で実アプリのモデルを作成し、画面を取り込んで目で確認）。
保存した .sbr を開き直す確認は、まだしていない。

## 3. 途中でわかったこと（MCP と Modeler の挙動）

| 起きたこと | 原因 | 対処 |
|---|---|---|
| 3D の三角形を `create_line` で閉じても面にならない | `faceFromLoop` は「開いた線」を探す。1 本の閉じた折れ線では面にならず、既に面になっている辺には次の三角形がつながらない | 地形は押し出し → `split_face` → `move_vertices` で作った |
| `create_polygon` の三角形を並べてもばらばらの面になる | 面どうしを縫い合わせる手段が MCP に無い | 同上 |
| `move_vertices` が「A face would fold over」で止まる | 隣の頂点が先に上がって急になった三角形で、低い頂点を一度に大きく上げたとき | `autofold:false` にし、失敗した頂点だけ 6 回に分けて上げた |
| 近い円を `create_circle` で描くと ID が消える | 円は面（プロファイル）なので、120 mm しか離れていない円どうしが重なってまとまる | 2D 原図の円は `create_arc` の半円 2 本で描いた |
| 投影線が「coincident consecutive points」で止まる | 交点と頂点が重なって同じ点が続いた | 0.5 mm 未満の点を除いた |
| MCP から保存できない | AI の経路は `allowFileCommands=false`（`src/app/AiBridge.cpp`）。`save` / `open` / `import_dxf` などはツールの一覧に出ない | アプリ画面で Ctrl+S |
| 大量の作成 | 1 回の `batch` で 50 個ずつ。作成時間はほぼ 0 秒。`split_face` は 30 個で 3〜24 秒、`move_vertices` は 1 回 1〜5 秒（履歴が長いほど遅い） | 少数で試してから本番を流した |

## 4. 測量データを扱うときの指針

今後、測量図から敷地・地形を作る機能やワークフローは、次に従う。

### 4.1 データの原則

1. **元の座標を変えない。** XY は図面の座標（mm）のまま。表示の精度などでローカル原点が必要になったら、平行移動量を属性に残し、元に戻せるようにする。
2. **Z の単位をはっきりさせる。** 標高の文字は m、図面は mm が普通。変換式（Z(mm)=標高(m)×1000）と基準（TP など、図面に書かれている場合）を、地形の属性 `coord` / `source` に書く。図面の Z が 0 以外なら、どちらを採ったかも書く。
3. **捏造しない。** 標高点の無い範囲へ外挿しない。高さ・深さの無い建物・塀・側溝は押し出さない。決めきれない対応は「対応なし」として地形に使わない。足りない情報は「未評価」「判断不能」として残し、合格や確定として扱わない（CLAUDE.md の「未評価」と同じ考え方）。
4. **元の 2D を残す。** 原図は Z=0・元座標の別タグに残し、生成物といつでも重ねて比べられるようにする。

### 4.2 解析の原則

5. **画層に頼らない。** 測量図の画層はたいてい少なく、用途を表していない。閉じているか・幅・平行線の間隔・記号の半径・注記までの距離など、図形そのものから判断する。
6. **標高の紐付けは、全体で 1 対 1。** 文字ごとに最近傍を取ると、同じ記号を 2 つの文字が取り合う。外接矩形からの距離をもとに、全体で最適な割り当てを求める。さらに「次に近い候補との差」で信頼度を付ける。
7. **すべての判定に信頼度と根拠を付ける。** 分類表と標高の対応表は、要素番号・距離・次に近い候補との距離・信頼度を持つ表として出す。人が後から確かめ、直せるようにする。
8. **図面の矛盾も結果として出す。** 境界の端点と境界標のずれ、境界標の無い頂点、急な段差、周りから浮いた点を一覧にする。勝手に直さない。

### 4.3 モデルの原則

9. **地形は正規の B-rep で作る。** 表示用のメッシュで代用しない。平面の三角形を共有辺でつないだ閉じたソリッド（底は基準高さ）を基本にする。こうすると体積（切土・盛土の比較）、`boolean`（建物との取り合い）、断面（`set_section`）に使える。
10. **滑らかな NURBS 曲面は使わない。** `loft` / `patch` の曲面は測点を正確には通らず、段差のところで面が行き過ぎる。使うなら、表示用か、測点で誤差を確かめたうえで使う。
11. **段差はブレークライン（地形の折れ線）として扱うのが正しい。** 擁壁・側溝・道路端の線に沿って三角形の辺を合わせる（拘束付き TIN）。天端と下端の標高の組が図面に無い場合は、急な斜面の近似にとどめ、そのことを結果に書く。
12. **作ったら自動で確かめる。** 面の数（TIN の三角形数・外周の辺数）、面の重心、標高点の位置と高さ、2D 原図との座標差、敷地の閉合と面積、投影線のカバー率を、`get_object` / `query_objects` で毎回確認する。

### 4.4 Git に入れないもの

13. オーナーや施主の測量図、そこから出した座標・標高の表、モデル、画面写真は Git に入れない。docs には件数・誤差・手法だけを書く。

## 5. 足りない機能の候補（未着手）

優先度はオーナーが決める。今回は既存の機能だけで作れることを確かめた。

| 候補 | 何が良くなるか |
|---|---|
| `create_terrain`（点群と外周、任意でブレークライン → 地形ソリッド） | 今は `split_face` 83 回と `move_vertices` 51 回で約 2 分かかり、履歴も 156 手順になる。1 コマンドなら 1 手順で、点を直せば作り直せる |
| `import_dxf` で TEXT / MTEXT を注記として取り込む（位置・回転・高さ付き） | 標高・注記が失われない。AI が図面の文字を読める |
| 面の縫い合わせ（平面の面を共有辺でつないで 1 つの殻にする） | TIN を別の作り方で作ったときにも、1 つの B-rep にまとめられる |
| AI の経路での保存（保存先の確認付き） | 今は画面操作が要る。オーナーの許可を前提に、確認の画面を出して保存できるようにする |
| 標高点の文字と記号の対応づけ（§4.2 の方法）を Modeler の解析として実装 | 図面ごとのスクリプトが要らなくなり、結果の表を GUI で確かめて直せる |
| 地形から敷地の切土・盛土の量（`take_off` との連携） | 計画の地盤面との比較ができる |
