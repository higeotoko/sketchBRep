# 336. 建具表に防火設備の列

docs/335 で、開口に防火設備の仕様と認定番号を持たせた。平面図の「防」は出るけど、建具表には出ていなかった。建具表は符号ごとの一覧なので、図の「防」とどの製品のことかが、表で引けるようにする。

## 作り

- 符号の付け方：
  - 防火設備を入れた開口は別の製品なので、自動の符号では別の行（別の符号）にした。種類・幅・高さ・建具が同じでも分ける。
  - 防火設備を入れていない開口の符号は、今までと変わらない。分けるキーに仕様を足すのは、仕様が入っているときだけだから。
  - 手で決めた符号は1行のまま。防火設備の違う開口が混ざると「混ざっています」の注が出る（大きさや品番が違うときと同じ）。
- 建具表（図面一式の表、export_schedule の openings、CSV）：
  - 「品番」の後に「防火設備」の列を足した。中身は「仕様（認定番号）」。
  - 注の文も「大きさ・建具・品番・防火設備の違う開口が混ざっています」にした。
- 表の注（符号の付け方）を「種類・建具・幅・高さ・防火設備が同じ開口に同じもの」に直した。CSV も同じ。
- 図面一式のゴールデン（docs/249）を更新した。差分は建具表だけ。
  - 列が1つ増えた（見出し「防火設備」と縦線1本）。
  - 注の文が上のとおり変わった。

## 例題で見たこと

例題E の東西の窓（AW3、4 か所のうち 2 か所）を防火設備にして描かせた。保存はしていない。建具表で、防火設備の 2 か所が AW4 の行に分かれた。防火設備の列には「アルミサッシ＋複層ガラス A12（網入厚6.8含）（EB-0000（架空））」が出た。ほかの 2 か所は AW3 のまま残った。

## ついでに直したこと

検証の道具 `sbr.py` が、GUI テストの失敗の中身を表示する途中で落ちていた。テストの出力の文字が、コンソールのコードページ（cp932）に無かったため。それで結果の行が出ず、通ったように見えかけた。標準出力と標準エラーを、表示できない文字は置き換えるようにした。

## 確認

- `Schedules.FireEquipmentOpeningsAreMarkedOnThePlan` に足したこと：
  - 建具表の9列目が「防火設備」。
  - 南の窓2つが「アルミサッシ＋網入りガラス（EB-9999）」の1行（数 2）になる。
  - その符号が、北の同じ大きさの窓と別になる。
  - CSV にも出る。
- 既存の CSV の期待値（列が1つ増えた分）を直した。直したテスト：
  - `Schedules.OpeningsOfOneKindSizeAndFittingShareAMark`
  - `Schedules.AMarkGivenByHandStaysAndWorkedOutNumbersSkipIt`
  - GUI の `schedulesAreReadFromTheModelAndTheirMarksShowOnThePlan`
- コアのテスト 868 本、表・開口・図面の GUI テストが通る。
