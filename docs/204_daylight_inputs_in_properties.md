## 2. GUI テストが、開いているアプリに届いていた（`ff546dd`・`72374a5`）

AI 連携の通り道（ローカルソケット）の名前は、Windows のユーザーごとに1つだった。Windows では同じ名前のパイプを2つ目のアプリも開けて、つなぐ側はどちらにつながるか分からない。

そのため、オーナーが確認用のアプリを AI 連携オンで開いている時に GUI テスト `aiRequestsTakeTurnsWithTheWindow` を回すと、テストが送った「箱を作る」20回がオーナーのアプリに届いて、テストは失敗していた（2026-11-20 に4回）。オーナーに確かめてもらい、モデルは大丈夫だった。

- `bridgeServerName()` は、環境変数 `SBR_AI_BRIDGE_NAME` があればその名前を使う。
- GUI テストは、始まる前（`QTEST_MAIN` の前の初期化）に、実行ごとの名前 `sketchbrep-ai-test-<時刻>` を入れる。テストのウィンドウもテストのソケットも同じ名前を使うので、人が開いているアプリには届かない。
- 普通の使い方（アプリと `sbr_mcp`）では、この環境変数は無いので今まで通り。
- ZIP の検証（`verify_portable_*.py`）は `sbr_mcp --headless`（自分だけのモデル）なので、もともと関係ない。
