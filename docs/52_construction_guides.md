# 構造種別の手引き（木造・鉄骨造・RC造）の設計（2026-11-04 JST）

位置づけ：設計書。段階1は実装済み（[docs/54](54_construction_guides_stage1.md)）。段階2以降は未実装。木造ルール v0.2 / v0.4（`timber_rules_recipe_v0.4.json` の 42 項目）の思想を引き継ぎ、重さの配分を変えた。

## 1. 決めたこと（2026-11-04）

| 項目 | 決定 |
|---|---|
| 標準寸法 | 事務所の標準はない。**市場で流通している寸法**を初期値にする。利用者が上書きでき、上書きは保存・共有できる |
| 階数 | **2 階建てを最初から**入れる（平屋は 2 階建ての特別な場合として扱う） |
| 壁量計算 | **入れられる枠組みまで**作る。係数の表は出典と版つきで後から登録する。登録されていない間は「未評価」と出す |
| 最終形 | 木造・鉄骨造・RC 造を、**同じ仕組みの「手引き」**として持つ。人にもAIにも、同じデータから作った説明を渡す |
| 壁量の係数表（2026-11-04 追加） | **同梱する**。どの時点の基準かを、結果を出すたびに但し書きで出す（§7.3） |
| 金物（2026-11-04 追加） | **形として置く**。数が多くても軽いよう、同じ金物は共有の部品にする（§5.1） |
| RC の配筋（2026-11-04 追加） | **やらない**（最初の範囲外）。RC は部材の形・寸法・拾い出しまで |

v0.2 / v0.4 から引き継ぐこと：

- 判定は 4 つに分ける：合格（pass）・不適合（fail）・未評価（not_evaluated：情報・根拠・検査が足りない）・対象外（not_applicable：理由つき）。分からないことを合格にも不良にもしない。
- ルールは**人の操作を止めない**。自動生成の候補選びと、頼まれた時の診断にだけ使う（v0.4 の gate_policy）。
- モジュールへの割付と、構造上の成立は別に判定する。
- 表示の簡略さと、本当の仕様（継手名・寸法）は別に持つ。
- 生成は反復する。変えた所に関係する判定は、古い合格を残さず、作り直す。

変えること：

- 先に厚くするのは**標準寸法・生成・形のチェック・拾い出し・伏図**。構造の照査（断面の照査・水平力・基礎）は、出典と範囲を示せる時だけにする。
- レシピの初期値は 1 件の実案件ではなく、入力（間口・奥行・階数・屋根）から決める。

## 2. 全体の形

構造種別ごとに 1 つの「手引き」を持つ。中身は同じ型のデータで、コードは共通にする。

| 部品 | 内容 | 木造 | 鉄骨造 | RC 造 |
|---|---|---|---|---|
| 断面カタログ | 選べる断面と、その出典 | 製材の流通寸法（新規） | JIS 形鋼 1204 種（既存 `steel_sections.json`） | 柱・梁・壁・スラブの寸法の候補（新規） |
| 部材の役割 | 用途の言葉の一覧と、既定の断面 | 土台・柱・梁… | 柱・大梁・小梁・ブレース… | 柱・大梁・小梁・耐震壁・スラブ… |
| プリセット | モジュール・基準高さ・既定値 | 910 / 1000 | スパン自由（通り芯） | スパン自由（通り芯） |
| レシピ | 入力から部材を組む手順 | 2 階建て軸組＋和小屋 | ラーメン・ブレース架構 | ラーメン架構 |
| チェック | 4 段階の判定を返す述語 | 共通＋木造 | 共通＋鉄骨 | 共通＋RC |
| 計算の枠 | 表を登録して使う計算 | 壁量・四分割法・N 値 | （後で） | （後で） |
| 出力 | 拾い出し・伏図・手引きの文章 | 共通 | 共通 | 共通 |

置き場所：`assets/construction/<種別>/` に JSON で置く（カタログ・役割・プリセット・レシピの設定・計算表）。アプリに埋め込み、利用者の上書きは別ファイル（プロジェクトか、PC の設定）に保存する。元の表は書き換えない。

すべての表に `source`（出典名・版・日付・URL）と `normative`（法令・告示か、仕様書か、市場の慣行か）を持たせる。市場の慣行は「目安」として表示する。

## 3. 今のアプリとのつながり

新しい別のモデルや別の Undo は作らない（v0.4 §2 と同じ）。

| 必要なもの | 今あるもの | 足すもの |
|---|---|---|
| 部材の芯（設計芯） | 2 点で引く部材のレシピが軸を持っている（docs/40） | なし。MOD-01（柱芯が通り芯に乗るか）は形の中心から推測せずに判定できる |
| 用途・材料 | 属性 `kind`・`material_class`（steel / timber / rc） | 役割の言葉（下の §4）を `kind` の値として足す。新しい項目は作らない |
| 通り芯・レベル | 通り芯（docs/43）、GL・FL（docs/45）、レベルに付いていく柱・梁 | 基準高さのプリセット（基礎天端・土台天端・軒高など）をレベルとして作る |
| 壁・スラブ・開口 | あり（docs/26） | 耐力壁の仕様（§7） |
| 同じ物の共有 | コンポーネント | 同じ断面・長さの材をコンポーネントにして、1,000 本を超えても軽くする |
| 生成の確定 | batch（Undo 1 回）、AI の preview | 生成をプレビュー → 確定（Undo 1 回） |
| 図面 | 平面・断面・立面、DXF・JWW・PDF（docs/50） | タグで絞った伏図、部材の符号 |
| 検索・集計 | query_objects・aggregate | 役割ごとの拾い出し |

## 4. 木造：標準寸法（市場の流通寸法。目安）

### 4.1 断面（mm）

| 役割 | 既定 | 選べる候補 |
|---|---|---|
| 土台 | 120×120 | 105×105、120×120 |
| 大引 | 90×90 | 90×90、105×105 |
| 床束 | 鋼製束 | 90×90（木）、鋼製束（製品は未選定として持つ） |
| 根太（根太床） | 45×60 | 45×45、45×60 |
| 床下地合板（根太レス） | 厚 28 | 厚 24、28 |
| 通し柱 | 120×120 | 120×120、105×105 |
| 管柱 | 105×105 | 105×105、120×120 |
| 間柱 | 30×105 | 27×105、30×105、30×120 |
| 胴差・床梁・桁・小屋梁 | 幅は柱と同じ × せい 240 | 幅 105 / 120 × せい 105〜390（30 刻み） |
| 火打梁 | 90×90 | 90×90、鋼製火打（製品は未選定） |
| 筋かい | 45×90 | 30×90、45×90、90×90 |
| 小屋束 | 90×90 | 90×90、105×105 |
| 母屋・棟木 | 105×105 | 90×90、105×105、120×120 |
| 垂木 | 45×60 | 45×45、45×60、45×90、45×105 |
| 定尺（材の長さ） | 4,000 | 3,000、4,000、6,000（梁は 5,000 以上も） |

- 梁せいの既定値は、**形を作るための仮の値**。スパンから自動で決めない（v0.2 §3.2）。スパン表は、出典と版を登録した時だけ「目安」として出す。
- 樹種・等級は属性として持つだけ（スギ・ヒノキ・ベイマツ、E 値・無等級など）。判定には使わない（使う計算の表が登録されるまで）。

### 4.2 プリセット

| 項目 | 既定 | 選べるもの |
|---|---|---|
| モジュール | 910 | 910、1,000、自由入力 |
| 根太・垂木の割付 | 等分（910/2、910/3） | 等分、固定ピッチ（303、455 など。端の調整を記録） |
| 基礎天端 | GL+400 | 数値 |
| 土台天端 | 基礎天端＋パッキン 20＋土台 | 計算で出す |
| 1FL | 土台天端＋根太（または合板）＋仕上げ | 仕上げ厚が未決でも、計画 FL を先に決められる（v0.2 §1.7） |
| 階高（1FL→2FL） | 2,900 | 数値 |
| 軒高（2FL→桁天端） | 2,700 | 数値 |
| 屋根勾配 | 4 寸 | 寸勾配か角度 |
| 軒の出・けらばの出 | 柱芯から 600 / 450 | 数値。どこから測るか（柱芯か外壁面か）を持つ |

すべてレベル（docs/45）として作るので、あとで高さを変えると、付いている部材が一緒に動く。

### 4.3 床の方式

床の区域ごとに選ぶ（v0.2 §1.2）。既定は 1 階が根太床、2 階が根太レス（厚 28 の合板を床梁 910 ピッチに直張り）。混ぜてもよい。区域の境目の受け材と段差を記録する。

## 5. 木造：生成（最初のレシピ）

**2 階建て・矩形・在来軸組・切妻（または片流れ）・和小屋**。平屋は「2 階なし」として同じレシピで作る。

| 入力 | 例 |
|---|---|
| 通り芯（既存の通り芯から、または間口・奥行とモジュール） | X 10 マス × Y 8 マス（910） |
| 階数 | 1 / 2 |
| 2 階の範囲 | 全体 / 通り芯で指定（下屋のある形） |
| 屋根 | 切妻 / 片流れ、勾配、棟の向き、軒・けらばの出 |
| 床の方式 | 区域ごと |
| 柱の位置 | 外周の交点＋指定した交点（全交点には立てない） |
| 開口 | 既存の開口から、まぐさ・窓台を入れる |

手順（反復できる）：

1. 基準高さをレベルとして作る（§4.2）。
2. 柱を置く：外周の隅と、2 階の外周が乗る所は通し柱。それ以外は管柱。柱の間隔の目安を超える所は、チェックで知らせる（勝手に足さない）。
3. 横架材：土台 → 胴差・2 階床梁 → 桁・小屋梁。梁は柱から柱へ。柱のない所は受け梁の候補を出す。
4. 床組：区域ごとの方式で、大引・床束・根太、または合板。
5. 小屋組：小屋梁 → 小屋束（910 ピッチ）→ 母屋・棟木 → 垂木。
6. 火打・筋かい（筋かいは §7 の耐力壁の指定から）。
7. 材の長さが定尺を超える所に継手の候補を置く（仕様名だけ。形は簡略）。
8. 層ごとにグループとタグを分ける：基礎・土台／1 階床組／1 階軸組／2 階床組／2 階軸組／小屋組。

- 確定の前にプレビューを出す。確定は Undo 1 回。
- 作り直し：最初の版では、**手を加えていない生成物だけ**を置き換える。手を加えた物があれば、どうするかを聞く（v0.4 の差分マージは後の段階）。
- 生成のあとは自由に編集できる。チェックは操作を止めない。

### 5.1 金物（形として置く）

数の見積もり（延床 30 坪前後の 2 階建て、目安）：

| 金物 | 数 |
|---|---|
| アンカーボルト | 30〜50 |
| ホールダウン | 10〜20 |
| 羽子板ボルト | 50〜100 |
| かど金物・山形プレート | 100〜200 |
| 筋かいプレート | 40〜80 |
| 短冊金物・火打金物ほか | 50〜100 |
| 合計 | **300〜600 個** |

部材（1,000 本前後）と合わせても、次のようにすれば軽さを保てるので、形として置く。

- 同じ種類の金物は**共有の部品（コンポーネント）**にする。形は 1 つだけ持ち、置いた場所の数だけ配置を持つ。
- 形は**簡略形**（板・ボルトを直方体と円柱で。数十面まで）。メーカーの製品名・型番は属性で持ち、詳しい形は持たない（v0.2 §1.3 の「表示は簡略、仕様は本物」）。
- タグ「金物」で、まとめて表示・非表示にできる。図面と拾い出しにも使う。
- 置き方：
  - 生成：レシピが、決まった場所に置く（土台のアンカーボルト、梁端の羽子板ボルト、筋かいの端の筋かいプレート）。柱頭・柱脚の金物は、N 値計算（§7）の結果から選ぶ。表が無い・計算していない柱には「未選定」の目印を置く。
  - 手で置く：金物ツールで、部材の端や交点に吸着させて置く。置く先の部材を必須にしない（v0.4 `host_selection_required_for_hardware: false`）。
- 部材を動かした時に金物が付いてくるのは、明示的に「追従」を ON にした物だけ（docs/42 と同じ）。
- 段階 2（レシピ）の受け入れで、金物を含めて生成・移動・表示の速さを測る。遅ければ、生成時は目印だけにして、形は必要な時に作る方式へ切り替える。

## 6. チェック（診断。操作は止めない）

結果は 1 件ずつ：ルール ID、対象、判定（4 段階）、理由コード、測った値と単位、必要な値と出典（あれば）、検査器の版。一覧のパネルから、対象の部材へ飛べる。

| ID | 内容 | 必要な情報 | 初期の実装 |
|---|---|---|---|
| COM-01 | 部材どうしのぶつかり（継手・仕口の重なりは除く） | 形・役割 | 実装 |
| COM-02 | 支えがない（下に何も無い柱・梁の端） | 形・役割・接合 | 実装 |
| COM-03 | 材の長さが定尺を超える（継手が要る） | 長さ・定尺 | 実装 |
| MOD-01 | 柱芯が通り芯（モジュール）に乗っている | 部材の芯・通り芯・例外 | 実装 |
| MOD-02 | 根太・垂木の割付（等分か固定ピッチか） | 割付の方式 | 実装 |
| TMB-01 | 2 階の柱の下に、1 階の柱か受け梁がある | 部材の芯・役割 | 実装 |
| TMB-02 | 梁の端に柱か受け材がある | 部材の芯・役割 | 実装 |
| TMB-03 | 通し柱が 1 階から 2 階まで続いている | 役割・高さ | 実装 |
| TMB-04 | 柱の間隔が目安を超える | 目安の値と出典 | 目安の表が無ければ未評価 |
| LAT-* | 壁量・四分割法・N 値 | §7 | 枠だけ。表が無ければ未評価 |
| SEC-* | 断面の照査 | 荷重・樹種・計算方法 | 対象外（今回はやらない） |

## 7. 壁量計算の枠組み

2025 年 4 月の改正（壁量の基準の見直し）に合わせられるよう、**計算の形だけ**を作り、係数は表として後から入れる。

### 7.1 データ

| データ | 中身 |
|---|---|
| 耐力壁 | 通り芯上の区間（始点・終点）、階、方向（X / Y）、仕様 ID。壁・筋かい・面材の部材から作るか、手で指定する |
| 壁の仕様の表 | 仕様 ID → 壁倍率（筋かい 45×90 片掛け、構造用合板 9mm など）、準耐力壁の扱い、出典・版 |
| 必要壁量の表 | 階・屋根や外壁の重さ・太陽光などの条件 → 床面積あたりの係数（または計算式の係数）、出典・版 |
| 地震・風の条件 | 地域係数、見付面積の扱い（風）、出典・版 |
| 床面積 | 階ごと。スラブや外周から計算するか、手で入れる（どちらで決めたかを持つ） |

### 7.2 計算

- 存在壁量 ＝ Σ（壁の長さ × 壁倍率）を、階・方向ごとに。
- 必要壁量 ＝ 床面積 × 係数（地震）、見付面積 × 係数（風）。大きい方。
- 判定：存在 ≥ 必要。
- 四分割法（バランス）と N 値（柱頭・柱脚の金物）は、同じ枠に別の計算として入れる。

### 7.3 同梱する表と、いつ時点の基準かの但し書き

- 壁倍率・必要壁量の係数・地域係数・N 値の表は**同梱する**。
- 表ごとに持つ情報：
  - `basis`：根拠の法令・告示・技術資料の名前と番号、版（例：令和〇年国土交通省告示第〇号、〇〇早見表 第〇版）。
  - `effective_from`：その基準が施行された日。
  - `checked_on`：SketchBRep の開発側で、改正が無いことを確かめた日。
  - `errata`：反映した正誤表（v0.2 §7）。
- 計算結果には**いつも但し書きを出す**（画面・診断の一覧・CSV・図面の注記・AI への返り値の全部）。例：
  > 壁量は「〇〇（令和〇年〇月〇日施行）」による。2026 年 11 月 4 日時点で改正の無いことを確認した表を使用。最新の基準を確認してください。
- `checked_on` から 1 年を過ぎた表で計算した時は、但し書きを強めて「表の確認から 1 年以上たっています」と出す。計算は止めない。
- 改正があった時は、新しい表を別の版として足す。古い表は消さず、プロジェクトがどの版で計算したかを保存する（古いプロジェクトを開いても結果が黙って変わらない）。版を切り替えると、関係する結果を作り直す（v0.2 OPS-03）。
- 表の数値は、実装の時に原典（告示・公的な資料）で 1 つずつ確かめてから入れる。確かめられない値は入れず、その項目は未評価にする。

### 7.4 表が無い・足りない時

- 必要な表が登録されていない、または適用条件が合わない時は**未評価**。理由に「どの表が足りないか」を出す。0 として計算しない。
- 表を登録しても、結果は「登録した表と入力による計算」として出す。建物全体の安全や、確認申請に通ることは言わない（v0.2 §5.4）。
- 同梱の表に加えて、利用者が自分で表を登録することもできる（その場合も、§7.3 と同じ項目を必須にする）。

## 9. 手引き（人と AI に渡す説明）

- 手引きは、§2 のデータ（カタログ・役割・プリセット・レシピの設定・ルールの一覧と出典）から**自動で作る**。手で書いた別の文章を持たないので、データとずれない。
- 渡し方は 3 つ：
  - ヘルプ画面のトピック（docs/51 の仕組み）。
  - AI 用：MCP のリソースと、`get_construction_guide {system: timber | steel | rc}` コマンド。
  - 文書として書き出す（Markdown / PDF）。
- AI が使うコマンド：`list_sections {system, role}`、`generate_frame {system, recipe, inputs, preview}`、`check_frame {system, rules}`、`take_off`。寸法は AI の一般知識ではなく、カタログから選ばせる。
- AI 接続時の説明（今は操作の約束ごとだけ）に、「構造種別の手引きを先に読む」と足す。

## 10. 鉄骨造・RC 造への広げ方

同じ型のデータを足すだけで動くようにする。

| | 鉄骨造 | RC 造 |
|---|---|---|
| 断面 | 既存の JIS カタログ（H 形鋼・角形鋼管・溝形鋼・山形鋼など） | 柱 500〜900 角、大梁 幅 300〜600 × せい 600〜1,000、小梁、壁厚 150〜250、スラブ厚 150〜200 などの候補（目安） |
| 役割 | 柱・大梁・小梁・間柱・ブレース・母屋・胴縁・ベースプレート | 柱・大梁・小梁・基礎梁・耐震壁・非耐震壁・スラブ・基礎 |
| レシピ | 通り芯＋階 → 柱・大梁・小梁（ラーメン）、ブレースの位置 | 通り芯＋階 → 柱・大梁・小梁・スラブ・壁 |
| チェック | 共通（ぶつかり・支え）、梁の端の接合の種類が決まっているか | 共通、壁・梁の取り合い、スラブの支え |
| 計算の枠 | （後で：表の登録で） | （後で：表の登録で） |
| 出力 | 拾い出し（重量 kg） | 拾い出し（コンクリート m³、型枠 m²） |
| 範囲外 | 継手・仕口の詳しい形（ボルト本数などは属性で） | **配筋**（鉄筋の本数・径・かぶり）。将来入れる時も、まず属性として持ち、形は作らない案 |

鉄骨の部材ツールとカタログはもうあるので、手引きの形に合わせるのは小さい。

## 11. 段階と受け入れの目安

| 段階 | 内容 | 受け入れの目安 |
|---|---|---|
| 1 | 共通の枠（データの型・出典・上書き保存）、木造の断面カタログ・役割・プリセット、AI と ヘルプへの手引き | AI が `list_sections` で木の断面を選んで柱を引ける。手引きがデータから作られ、上書きが反映される |
| 2 | 木造レシピ（2 階建て・切妻 / 片流れ・和小屋）、プレビュー → 確定 | 10×8 マスの 2 階建てが 1 回で生成され、Undo 1 回で消える。レベルの高さを変えると付いてくる |
| 3 | チェック（§6 の「実装」の行）と結果パネル | 柱を 1 本動かすと MOD-01 と TMB-01 が変わる。操作は止まらない |
| 4 | 拾い出しと伏図 | 本数・材積が手計算と合う。伏図が DXF / JWW に出る |
| 5 | 壁量（耐力壁の指定・同梱の表・計算・但し書き・未評価の理由） | 同梱の表で計算が手計算と合い、但し書きにいつ時点の基準かが出る。表を外すと「未評価：必要壁量の表が無い」 |
| 6 | 鉄骨造・RC 造の手引き | 同じコマンドで `system: steel / rc` が動く |

## 12. 責任の範囲（画面・ヘルプ・利用規約で同じ書き方にする）

- SketchBRep の手引き・生成・チェックは、**意匠・概略の検討用**。構造の安全、法令への適合、施工できることを判定・保証しない。
- 標準寸法は市場の流通寸法の目安で、法令の値ではない。
- 計算（壁量など）は、利用者が登録した表と入力による計算で、その範囲だけの結果。

## 13. まだ決めていないこと

- 継手・仕口の仕様の一覧（名前と、簡略形状の作り方）。
- 金物の種類の一覧（最初に入れる種類と、簡略形の寸法）。
- 寄棟・入母屋・下屋の多い形の順番。
