# 確かめ：全部入りの小さな家（2026-11-15）

オーナーの「精度は大丈夫？破綻してない？」（2026-11-15）を受けて、新しい機能を止めて確かめに回った。作業は Opus 5.5。
**AI が配った ZIP のアプリ（sbr_cli）で確かめた物で、人の操作による確認（docs/105）の代わりではない。**

## やったこと

配った ZIP（`d12df04`、続けて `13dfde1`）の `sbr_cli` で、2026-11-14〜15 に入れた物を全部使った家を 1 回のバッチ（取り消し 1 回分）で作り、表・図面・IFC を書き出し、保存して開き直した。

## 見つけた事

| 事 | 中身 | どうするか |
|---|---|---|
| 間仕切りが当たる所に扉があけられる | 北の壁の真ん中（間仕切りが T 字で当たる所）に扉をあけても、何も言わない。間仕切りの端が扉の穴の中に来る。室は壁の線で見るので、面積は変わらない | **`ebde5fe` で直した**：開口ツール・等間隔の配置で、ほかの壁の端が開口の所に当たると、ステータスバーに壁の名前を出す（あけるのは止めない）。AI の `place_openings` は `walls_meeting_openings` を返す。壁の面に当たる端も、壁の線（芯）まで描いた端も見る。計算テスト `Schedules.AnOpeningWhereAnotherWallEndsIsSaid`（間仕切りが当たる所 → 言う、当たらない所 → 言わない） |
| **大きいモデルで室の表が重い** | 部屋 400・開口 840（壁 42 本の格子）で測ったら、室の表 673 ms・面積の表 674 ms・建具表 111 ms。部屋ごとに、その階の「壁で囲まれた所」を全部計算し直していた（部屋の数の 2 乗で増える）。平面モードでは編集のたびに走るので、1 回ごとに 0.7 秒止まる。部屋 400 を作るのにも 145 秒 | **`7d7a3dc` で直した**：同じ高さの部屋は、壁で囲まれた所を 1 回だけ計算する。建具の名前の一覧も 1 回だけ読む。同じモデルで、室の表 9 ms・面積の表 5 ms・建具表 77 ms、部屋 400 を作るのに 7 秒。結果（面積の合計 5299.8 ㎡）は直す前と同じ |
| 階段の手すりが屋根から出る | 確かめの家は平屋の屋根の下に 2 階の床と階段を入れたので、上の階の手すり（床から 850）が屋根を突き抜けた | 家の作り方の誤り（うちの確かめ方の問題）。アプリの不具合ではない |

## 大きいモデルでのほかの操作（`7d7a3dc` の ZIP で測った）

部屋 400・開口 840（壁 42 本の格子）：

| 操作 | 時間 |
|---|---|
| 壁を動かす（つながりも付いてくる） | 数 ms |
| 室をもう 1 つ置く | 5 ms |
| 平面図（A1、1:200）を書き出す | 3.6 秒 |
| IFC を書き出す | 0.7 秒 |

書き出しは編集のたびに走る物ではないので、この大きさでは困らないと見ている。もっと大きい物（集合住宅など）は測っていない。

## 確かめていないこと

- 画面（マウス・プロパティ・表の窓）の操作。人の操作（docs/105）とは別。
- オーナーの実物の検討モデル。
- IFC をほかのソフトで開くこと。
