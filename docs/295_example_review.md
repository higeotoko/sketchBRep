# 295. 横浜市の例題で出力一式を照合した

docs/285「ここから先」の 4。架空の木造2階建て新築戸建て（横浜市、敷地225 ㎡、第一種低層住居専用地域・第1種高度地区・準防火地域、9100×7280）を、AIからの操作（MCP）だけで組み立てた。図面一式・照合結果をAIが描かせて見比べ、見つかった点を直した。

例題は配布フォルダの `outputs/example-yokohama-2026-11-26/` にある（`例題E_横浜の木造2階建て.sbr` と、窓の位置と真北を直した `…_修正後.sbr`）。修正前の図面一式は `before/`、修正後は `after-679e51f/` に PNG と PDF がある。

## 例題の中身

- 木造架構（`generate_frame`、10×8間、2階、切妻）、外壁（窯業系サイディング通気）・間仕切り、5室（LDK・和室・洗面浴室・主寝室・子供室）と仕上げ・天井高・居室区分、開口部9か所、屋根。
- 敷地・道路（南6 m）・用途地域と高度地区・接地外周と測点（基準点のZつき）・付近見取図の位置・真北。
- 計画概要（建築主・設計者・工事種別・主要用途・防火地域など）、設備、使用構造材料、内装材の区分。

## 見つけたことと直したこと

| # | 見つけたこと | 対応 |
|---|---|---|
| 1 | 補助のレベル（GL・基礎天端・土台天端・桁天端）も階になり、平面図が6枚、延べ面積が265 ㎡（正しくは132.5 ㎡）。手数料の区分もずれた | 「〜FL」の名前のレベルがある時は、それだけを階にする（`levelIsStorey`）。延べ面積132.50 ㎡、手数料43,000円の区分になった |
| 2 | 真北をAIから入れる命令がない | `set_site_north`（角度か2点、資料、確認日は省略で当日） |
| 3 | 木造架構が作るレベル名が「木造架構 1 1FL」で、様式の階名やGLの判定に合わない | 頭の名前つきでも GL・1FL として読む（`isGroundLevelName`、様式の階名） |
| 4 | 断面図の「切る位置」に伏図まで並び、図面名が用紙からはみ出した | 図面一式の伏図を1:50の独立した図にし、断面の切断記号の対象から外した |
| 5 | 断面図・立面図・軸組図で、近い高さのレベル名（GL・基礎天端・土台天端・1FL）が重なった | 重なるレベル名を左へ順にずらし、レベル線をそこまで延ばす |
| 6 | 意匠の平面図に、木造架構の床組（根太・大引）が部屋の中に描かれて読みにくい | 図面一式の平面図では、基礎・土台、床組、小屋組のタグを描かない（`ViewSpec::excludeTags`）。柱は残す |
| 7 | 1階南の窓の1つが間仕切り壁にかかった | 例題の作り方の誤り。アプリが警告した。窓を移した |

図面の読みにくさの点検（`check_drawing_set`）の指摘は 103 件から 83 件に減った。残りの多くは「910」の寸法の字に通り芯・レベル線がかかるもの。

## 残り（直していない）

- 2階床伏図・小屋伏図は1:50でも部材符号が混み合う（符号の配置の工夫が要る）。
- 配置図の道路が線で描かれず、注記だけ。図面名が「配置図（検討用）」のまま（提出用の名前にするかは判断が要る）。
- 寸法の字に線がかかる、室名と面積の字に壁の線がかかる。
- `check_drawing_set` は地図を取りに行かないので、付近見取図に「地図は…」の注記が出て、重なりとして数える（実際の図面一式では地図が入る）。
- 受付チェックシートで「図面一式にない」まま：構造詳細図、基礎・地盤説明書、施工方法等計画書、構造計算書（壁量計算の入力が例題にない）、省エネの図書（例題に断熱の入力がない）。
- 2階の平面図に、下の階の間仕切りの線が細く見える。
- 確認申請書のWord様式は、この例題ではまだ出していない（画面からの操作。docs/294で別に確認済み）。
