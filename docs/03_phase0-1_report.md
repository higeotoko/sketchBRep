## 実装内容

### Phase 0 — 技術成立性
1. CMake による C++17 プロジェクト（コア / アプリ / ツール / テスト）
2. OCCT 7.6 の導入（`find_package(OpenCASCADE)`）
3. 矩形プロファイル生成（`geom::makeRectangleFace`、任意平面・負寸法対応、面法線を平面法線に統一）
4. ソリッド押出（`geom::extrudeFace`）
5. B-rep 妥当性確認（`geom::validateShape`: BRepCheck + 閉シェル + 正の体積 + 単一ソリッド）
6. STEP 書出・再読込（AP214 / mm）
7. 幾何精度の検証（体積相対誤差 1e-12、STEP 往復で寸法 1e-6 mm）

### Phase 1 — 操作可能な 3D モデラー
1. Qt 6 メインウィンドウ（上: メニュー、左: ツール、中央: ビュー、右: オブジェクト/属性、下: ガイド + 数値入力）
2. OCCT 3D ビューポート（グラデーション背景、軸、トライヘドロン、黒エッジのシェーディング、AA）
3. カメラ: ホイールズーム（カーソル位置基準）、ホイールドラッグのターンテーブル・オービット（Z 上向き維持）、Shift+ホイールドラッグのパン、ダブルクリックフォーカス（ON/OFF 設定可）、標準 6 方向 + アイソメ、透視⇔平行
4. オブジェクト選択（クリック / Shift 追加・解除 / パネルと双方向同期）
5. 線ツール（連続線、始点で閉じると面、Esc/ダブルクリックで終了）・矩形ツール（地面または面上）
6. 面の生成（閉じた線 → 平面性・自己交差チェック付きで面化、不可なら線として保持）
7. Push/Pull（プロファイル押出 / 押出上面は距離パラメータを直接編集 / 他の平面フェースは Boolean で移動・伸縮、プレビュー表示、ジオメトリ点で高さ推論）
8. 数値入力（mm / cm / m、`幅,奥行`、作図直後の再入力で直前の操作を再編集）
9. Undo / Redo（コマンド名付きメニュー）
10. ネイティブ保存・再読込（カメラ含む、原子的保存）、STEP インポート/エクスポート
- 推論・スナップ: 原点・端点・中点・エッジ上・面上・作業平面、X/Y/Z 軸推論（軸色の破線表示）、Shift で推論方向ロック、→←↑ で軸ロック
- 右パネル: 名前、ID、レシピ、体積・B-rep 有効性、パラメータ（幅・奥行・押出距離・各 Push/Pull 距離）の数値編集、表示/非表示
- 表示品質（粗い/標準/精細）: 表示コピーのみ再テッセレーション

## 動作確認方法

### 自動
```bash
cmake -S . -B build && cmake --build build
xvfb-run -a ctest --test-dir build --output-on-failure      # Windows では ctest -C Release
```

### 手動（Phase 1 シナリオ）
1. `SketchBRep` を起動（起動時は矩形ツール）
2. 原点（黄色マーカー「原点」）をクリック → 斜め方向にマウスを動かし `4000,6000` + Enter
3. `P` → 矩形をクリック → 上方向へマウスを動かし `3000` + Enter（続けて `3500` + Enter で高さを打ち直せる）
4. 側面をクリック → 外へ動かし `1000` + Enter（ソリッドの平面フェース移動）
5. `Ctrl+S` で保存 → `Ctrl+N` → `Ctrl+O` で開き直す
6. 右パネルで「押出距離」を 4500 に変更 → 高さが再計算され、側面の Push/Pull も追従する
7. `Ctrl+Z` / `Ctrl+Y` で各段階に戻れる。表示 → 表示品質を「粗い」にしても体積表示は不変
8. ファイル → STEP エクスポート → 他の CAD（Rhino 等）で寸法を確認

## 既知の制限

- **プラットフォーム検証**: 開発・CI は Linux（Ubuntu 24.04 / OCCT 7.6.3 / Qt 6.4）。（2026-10-20 追記）その後 Windows CI（MSVC + conda-forge OCCT/Qt）でビルドと全コアテストが合格し、Windows 11 実機で起動・Push/Pull・オフセットの動作を確認済み。
- **Push/Pull**: 平面フェースのみ。押し抜き（ソリッドが分割/消滅する操作）は拒否。別オブジェクト同士は結合しない（面上に描いた矩形を押し出すと別ソリッドになる）。
- **線ツール**: 既存の面を分割しない（SketchUp の「線で面を分割」は未対応）。開いた線はオブジェクトとして保持するのみ。
- **TNP**: `FaceRef` は幾何マッチのみ。参照平面自体が移動する上流編集では解決できず、編集を拒否する。
- **推論**: 平行・垂直推論、「点から」推論、エッジ方向への推論は未実装。スナップ候補は全探索（大規模モデルでは空間インデックスが必要）。
- **カメラ**: オービット中心はビュー中心（カーソル位置ピボットは未対応）。二点透視は未対応。
- **Move/Rotate/Offset/Group/Component/レイヤ UI**: Phase 2 範囲のため未実装（`transform` とレイヤ属性はデータモデル・保存形式に用意済み）。
- **Undo 履歴**はファイルに保存しない（パラメトリックレシピは保存される）。
- STEP はオブジェクト名・色を保持しない（XCAF 未使用）。
- UI 文言は日本語固定（`tr()` 済みなので翻訳ファイル追加で多言語化可能）。

## 次フェーズ（Phase 2）で解決すべき課題

1. **Windows ネイティブビルドの CI 化**（vcpkg キャッシュ付き GitHub Actions `windows-latest`）とインストーラ（windeployqt + OCCT DLL + LGPL 文書）
2. **Move / Rotate / Copy**（`Object::transform` を使った非破壊配置、数値入力・軸拘束・複数コピー）
3. **Offset**（平面閉輪郭、`BRepOffsetAPI_MakeOffset`）
4. **Boolean**（オブジェクト間の和・差・積、結果のレシピ表現）
5. **Group / Component**（定義共有 + インスタンス変換、ネストした ID 体系）
6. **TNP の強化**: 生成履歴ベースの意味的命名（押出の上面/底面/側面 i）と幾何シグネチャのハイブリッド
7. **推論の強化**: 平行/垂直、点からの軸推論、スナップ候補の BVH 化、推論ツールチップ
8. **SketchUp 互換挙動**: 線による面分割、面上に描いた形状の押出時の自動結合（オプション）
9. **STEP 連携の安定化**: XCAF による名前・色・階層の保持、単位の自動判別
10. **AI/スクリプト API の試作**: `doc::Modeler` を JSON-RPC で公開（GUI と同一コマンド基盤）
