# 土台から布基礎を計画する（2026-11-05）

追記：[束石・独立基礎計画](68_foundation_pads.md) を追加した。下記の未対応範囲・配布記録は、この布基礎実装時点の記録。

従来の木造レシピは基礎天端のレベルと土台を持つだけで、基礎コンクリートを生成していなかった。
今回、実在する土台を参照して立上り・底盤のB-repを作り、プレビュー、再生成、変更検知、正味体積の確認を追加した。
構造計算・配筋設計は含まない。ユーザーの直接編集と同じModeler・Undoを使う。

## SumiCADから確認したこと

接続済みのSumiCAD 0.7.1へMCPで読み取りを行った（64ツール）。
`list_actions {query:"foundation",schemas:true}` の21アクション、`guide` の基礎段階、
`project_info` を取得した。原文・プロジェクト情報・認証値はリポジトリとZIPに同梱しない。

| 確認したAPI・ガイドの設計 | SketchBRepでの取り込み |
|---|---|
| foundation.generate：最下階の耐力壁と基礎断面を参照し、既存基礎を重複生成しない | 実在する土台を参照。同じ対象への重複生成を止め、同一条件なら変更なしで返す |
| 基礎生成後、追加された耐力壁や土台の下も再確認する流れ | 土台と生成結果を記録し、変更後は再生成・確認を促す |
| 基礎断面をまとめて管理し、foundation.checkで別に確認 | 立上り・底盤・パッキン・天端を一画面で設定し、状態・隙間・体積を読み取り検査 |
| foundation.followTerrain / foundation.steps | 段差・傾斜を黙って平らにせず、今回は未対応として生成前に止める |
| fdpassの配置・検査、床下地盤・掘削・換気等 | 別途必要な項目として残す。今回の計画を基礎設計全体の完了に見せない |

これは公開MCPのスキーマとガイドから学んだ操作・データの流れで、内部実装や計算結果の再現ではない。
SumiCADの生成・自動修正・保存は実行していない。断面一覧とfoundation.check等の追加取得は通信切断により完了しておらず、
それらの実行結果・法規照査・数値の正しさを確認したという記録ではない。
SketchBRepでは耐力壁の自動認定を行わないため、壁を耐力壁に変更して基礎を置く処理は取り込まず、実土台を入口にした。

## 画面から使う

1. 木造架構を作るか、矩形断面の水平な木造土台を選ぶ。
2. 建築ツールバーの「木造」→「布基礎計画（土台から作成・作り直し）...」を開く。「ツール」からも使える。
3. 架構グループ全体か、選択した土台を対象にする。非表示の土台もグループ指定には含む。
4. 立上り幅・高さ、底盤幅・厚さ、パッキン高さを指定する。単位はmm。
5. 基礎天端は初期状態で「土台下面−パッキン」。チェックを外すと世界Zで直接指定できる。
6. プレビューで形状・コンクリート量を見て「適用」。却下はモデルを変えない。適用はUndo一回で戻せる。
7. 作り直すときは既存の基礎計画を選ぶ。設定・元の対象を再表示する。「検査・数量を更新」で現在の形状を読み直す。

基礎は文書直下の独立グループに置く。土台や架構・基準レベルを動かしたり書き換えたりしない。
立上り・底盤は「基礎・土台」タグ、材料属性はrc。通常の移動・面編集等も使える。
手編集した基礎は自動で消さず、明示的な「手編集した基礎も置換する」とプレビューを経て作り直す。
設定画面を開いた後・プレビュー後にモデルが変わった場合、古い内容で上書きしない。

## 形状・数量

初期値は立上り幅150・高さ600、底盤幅450・厚さ150、パッキン20mm。
形を作るための仮の入力で、必要断面・標準仕様・法定値として採用したものではない。
土台の実際の矩形断面芯を平面経路とし、各端は幅の半分だけ延長して直角の端部を作る。
各層の経路を正確なソリッドの和演算で結合し、角・T字・重複の二重計上を除く。
立上りと底盤は上下で接する二つのパラメトリック形状。体積は実B-repからm³へ換算する。
離れた経路は複数の連続体として残り、検査画面にその数も表示する。

3m×2mの外周は、初期断面で立上り0.900m³、底盤0.675m³、合計1.575m³。
中央に3mのT字接続経路を追加すると合計2.003625m³。同じ経路を逆向きに重ねても増えない。
これらは形状・体積の検算用の例で、構造仕様の推奨ではない。
既存の木材拾い出しへコンクリートを木材として混ぜず、`check_foundation` の数量で確認する。

## 変更を検知する

元の土台ID、世界座標、下面高さ、部材の状態と、生成した基礎の構成・状態を保存する。
共有部材、部材の上寄せ、親グループの移動・水平回転も反映する。保存再読込後も比較できる。

| 状態 | 意味 |
|---|---|
| current | 元土台・生成形状に記録後の変更なし。構造の合格ではない |
| needs_regeneration | 土台の移動・断面・構成等が変わった。基礎は自動移動せず、作り直す |
| modified | 基礎・親配置・構成が手編集された。明示的な置換が必要 |
| source_missing_or_unsupported | 元土台がない、加工・段差等で参照できない |

土台の下面と記録した基礎天端の隙間も返す。変更なしの計画では設定パッキンとの差を確認できる（モデル上の比較許容差1mm）。
土台・基礎が変わった場合、この一致判定は未確認のnullに戻す。
生成部材が削除された場合、全量を0や残った量で埋めずnullにし、残存部材の既知量を別に返す。
手編集した追加部材は生成部材の数量には含まない。基礎の全容を拾った総数量ではない。

## API / MCP

```json
{"command":"generate_foundation","args":{"inputs":{"frame":"架構グループID"}}}
{"command":"generate_foundation","args":{"inputs":{"sources":["土台ID1","土台ID2"]}}}
{"command":"generate_foundation","args":{"inputs":{"frame":"架構グループID"},"preview":false,"expected_revision":123}}
{"command":"generate_foundation","args":{"replace":"基礎計画ID","inputs":{"stem_width":180},"preview":false,"expected_revision":124}}
{"command":"check_foundation","args":{"foundation":"基礎計画ID"}}
```

生成はAPIでは初期状態が読み取り専用プレビュー。適用には現在のrevision、または既存のbatch / proposeの経路が必要。
Modelerの操作そのものは一つの変更として確定する。`check_foundation` は読み取り専用。
`inputs` は `frame` と `sources` のどちらか一つ。置換時は保存済み入力へmerge-patchするため、対象方式を変更する場合は元のキーをnullで外す。
`top_z:null` も手入力の天端を外して自動計算に戻す。`on_modified:"replace"` は手編集の明示的置換。
`check_foundation` の対象を省略すると全計画。`version:"foundation-plan-1"`、`verified:false`、未照査項目、
状態、理由、参照元、隙間、生成部材別の正確な体積・連続体数、検査時revisionを返す。

## 今回の範囲と次に必要なこと

対象は指定した土台の下だけ。木造レシピの土台は外周主体なので、内部の耐力壁下が全部できたとは扱わない。
床束下の束石・独立基礎、土台のない耐力壁下、べた基礎、地中梁、段差・斜面・地盤面・掘削・防湿、
人通口・配管・換気、アンカーと接合、地盤・支持力・沈下、荷重伝達、断面の構造照査は未実装・未評価。
配筋設計はオーナーの既存方針に従い実装しない。既存の基礎容量チェックも未評価のまま維持する。
任意B-repに加工した土台、傾いた断面・経路、上下の異なる土台は、誤った連続基礎にまとめず生成前にエラーとする。
これで通常の直接モデリングを制限することはない。

次は内部耐力壁・柱・床束から基礎までの対応を一覧にして、支持先の不足を人が確認できるようにする。
構造の自動合否や基礎の勝手な補完にはせず、既存の柱・土台・基礎の実形状を参照する。
